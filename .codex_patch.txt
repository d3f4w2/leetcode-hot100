+# 240. 搜索二维矩阵 II
+
+## 所属专题
+
+- 矩阵
+
+## 题目描述
+
+给你一个 `m x n` 的矩阵 `matrix` 和一个目标值 `target`。
+
+该矩阵具有下面两个性质：
+
+- 每一行从左到右升序排列
+- 每一列从上到下升序排列
+
+请你编写一个**高效算法**，
+判断 `target` 是否出现在这个矩阵中。
+
+如果存在，返回 `True`；
+否则返回 `False`。
+
+## 示例
+
+### 示例 1
+
+```text
+输入：matrix = [[1,4,7,11],[2,5,8,12],[3,6,9,16],[10,13,14,17]], target = 5
+输出：true
+```
+
+### 示例 2
+
+```text
+输入：matrix = [[1,4,7,11],[2,5,8,12],[3,6,9,16],[10,13,14,17]], target = 15
+输出：false
+```
+
+## 题意理解
+
+这道题不是普通的“在二维数组里查一个数”。
+
+它给了我们两个很关键的有序性质：
+
+- 行有序
+- 列有序
+
+但要注意，
+它**不是**整个矩阵按从左到右、从上到下完全整体有序。
+
+比如：
+
+```text
+1   4   7  11
+2   5   8  12
+3   6   9  16
+10 13  14 17
+```
+
+虽然每行有序、每列也有序，
+但你不能把它直接“拉平”后做一次普通二分。
+
+所以这题的关键不是暴力遍历，
+也不是把每一行都单独二分，
+而是要利用“行列同时有序”的特点，
+在比较一次之后就排除掉一整行或一整列。
+
+## 为什么从右上角开始最好想
+
+最经典的做法是从**右上角**开始搜索。
+
+设当前位置是 `matrix[i][j]`。
+
+右上角这个位置很特殊：
+
+- 它左边的数都比它小
+- 它下边的数都比它大
+
+这样一来，比较当前值和 `target` 之后，
+我们就能立刻决定下一步怎么走。
+
+### 情况 1：当前值等于 `target`
+
+那就直接返回 `True`。
+
+### 情况 2：当前值大于 `target`
+
+因为当前列从上到下递增，
+所以这一列当前元素下面的值只会更大。
+
+既然当前值都已经大于 `target` 了，
+那么当前列不可能再有 `target`。
+
+所以可以直接：
+
+- `j -= 1`
+
+也就是向左移动，排除当前列。
+
+### 情况 3：当前值小于 `target`
+
+因为当前行从左到右递增，
+所以当前元素左边的值只会更小。
+
+既然当前值都已经小于 `target` 了，
+那么当前行不可能再有 `target`。
+
+所以可以直接：
+
+- `i += 1`
+
+也就是向下移动，排除当前行。
+
+## 为什么左上角不方便
+
+如果你从左上角开始，
+当前值比 `target` 小时，
+你会面临两个方向都“可能有答案”：
+
+- 右边更大，可能有
+- 下边也更大，也可能有
+
+这时你就无法只靠一次比较排除掉一大片区域。
+
+而右上角不同，
+它天然让“向左变小、向下变大”这两个方向分工非常明确，
+所以能做到每一步都缩小搜索范围。
+
+## 用示例手推一遍
+
+以：
+
+```text
+matrix = [[1,4,7,11],[2,5,8,12],[3,6,9,16],[10,13,14,17]]
+target = 5
+```
+
+为例。
+
+从右上角开始：
+
+```text
+当前位置 = 11
+```
+
+因为：
+
+```text
+11 > 5
+```
+
+所以排除这一列，向左走：
+
+```text
+当前位置 = 7
+```
+
+仍然有：
+
+```text
+7 > 5
+```
+
+继续向左：
+
+```text
+当前位置 = 4
+```
+
+现在：
+
+```text
+4 < 5
+```
+
+说明这一行不可能有 `5`，
+向下走：
+
+```text
+当前位置 = 5
+```
+
+此时刚好等于目标值，
+返回 `True`。
+
+整个过程路径就是：
+
+```text
+11 -> 7 -> 4 -> 5
+```
+
+## 整个搜索过程维护的是什么范围
+
+我们可以把还可能包含答案的区域理解为一个子矩阵。
+
+初始时：
+
+- 行范围是 `0 ~ m - 1`
+- 列范围是 `0 ~ n - 1`
+
+每次比较之后：
+
+- 如果当前值太大，就删掉一整列
+- 如果当前值太小，就删掉一整行
+
+所以搜索区域会不断缩小。
+
+并且每一步都会至少去掉一行或一列，
+因此最多只会走：
+
+- `m` 次向下
+- `n` 次向左
+
+合起来就是 `O(m + n)`。
+
+## 算法步骤
+
+1. 如果矩阵为空，直接返回 `False`
+2. 令 `i = 0`，`j = n - 1`，从右上角开始
+3. 当 `i < m` 且 `j >= 0` 时循环
+4. 如果 `matrix[i][j] == target`，返回 `True`
+5. 如果 `matrix[i][j] > target`，说明当前列可以排除，执行 `j -= 1`
+6. 如果 `matrix[i][j] < target`，说明当前行可以排除，执行 `i += 1`
+7. 如果走出边界还没找到，返回 `False`
+
+## Python 参考实现
+
+```python
+from typing import List
+
+
+class Solution:
+    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
+        if not matrix or not matrix[0]:
+            return False
+
+        m, n = len(matrix), len(matrix[0])
+        i, j = 0, n - 1
+
+        while i < m and j >= 0:
+            if matrix[i][j] == target:
+                return True
+            if matrix[i][j] > target:
+                j -= 1
+            else:
+                i += 1
+
+        return False
+```
+
+## 为什么这样写是对的
+
+关键在于：
+
+- 右上角左边都更小
+- 右上角下边都更大
+
+因此在任意一步，设当前值为 `x = matrix[i][j]`。
+
+### 如果 `x > target`
+
+由于当前列从上到下递增，
+所以当前列中从第 `i` 行往下的元素都满足：
+
+```text
+>= x > target
+```
+
+也就是说，
+当前列在剩余搜索区域内不可能有答案，
+可以安全删掉。
+
+### 如果 `x < target`
+
+由于当前行从左到右递增，
+所以当前行中从第 `0` 列到第 `j` 列的元素都满足：
+
+```text
+<= x < target
+```
+
+也就是说，
+当前行在剩余搜索区域内不可能有答案，
+可以安全删掉。
+
+所以每一步排除都是正确的，
+并且不会漏掉真正的答案。
+
+如果目标值存在，
+它一定会留在不断缩小的搜索区域里，
+最终被访问到；
+
+如果搜索区域被删空了还没找到，
+那就说明目标值确实不存在。
+
+## 复杂度分析
+
+### 时间复杂度
+
+`O(m + n)`
+
+因为每一步不是向左走一列，
+就是向下走一行。
+
+列最多减少 `n` 次，
+行最多增加 `m` 次，
+所以总步数不超过 `m + n`。
+
+### 空间复杂度
+
+`O(1)`
+
+只使用了几个变量记录当前位置，
+没有使用额外数据结构。
+
+## 常见错误
+
+### 1. 只判断 `if not matrix`
+
+如果写成：
+
+```python
+if not matrix:
+    return False
+```
+
+那么当输入是：
+
+```python
+[[]]
+```
+
+时，访问 `matrix[0]` 会出错。
+
+所以更稳妥的写法是：
+
+```python
+if not matrix or not matrix[0]:
+    return False
+```
+
+### 2. 方向写反
+
+从右上角开始时：
+
+- 当前值太大，要向左
+- 当前值太小，要向下
+
+很多人会把这两个方向写反，
+一旦写反就会漏解。
+
+### 3. 想当然地把矩阵拉平成一维再二分
+
+这题和“搜索二维矩阵”那道题不一样。
+
+这里并没有保证：
+
+- 下一行的第一个数一定大于上一行的最后一个数
+
+所以不能直接把整个矩阵当成一个整体有序数组。
+
+### 4. 每一行都做一次二分
+
+这种做法时间复杂度是：
+
+`O(m log n)`
+
+虽然有时也能过，
+但不是这题更优雅、更高效的解法。
+
+这题更值得掌握的是：
+
+- 利用单调性一次排除一整行或一整列
+
+## 一句话总结
+
+这道题的关键就是：
+
+**从右上角开始比较，当前值大了就向左，当前值小了就向下，每一步都排除一整行或一整列，因此时间复杂度可以做到 `O(m + n)`。**
