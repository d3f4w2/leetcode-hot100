# 108. 将有序数组转换为二叉搜索树

## 所属专题

- 二叉树

## 题目描述

给你一个整数数组 `nums`，其中元素已经按升序排列，
请你将其转换为一棵高度平衡二叉搜索树。

这里的两个关键词是：

- 二叉搜索树
- 高度平衡

二叉搜索树要求：

- 左子树所有节点值都小于根节点
- 右子树所有节点值都大于根节点

高度平衡要求：

- 每个节点的左右子树高度差不超过 `1`

## 示例

### 示例 1

```text
输入：nums = [-10,-3,0,5,9]
输出：[0,-3,9,-10,null,5]
```

下面这种结果也算正确：

```text
[0,-10,5,null,-3,null,9]
```

因为这道题只要求：

- 是一棵合法的高度平衡二叉搜索树

并不要求唯一结构。

## 题意理解

这道题不是随便把数组里的数放进树里就行，
而是要同时满足两个条件：

- 这棵树必须是二叉搜索树
- 这棵树还必须尽量平衡

数组已经是升序的，
这其实给了我们非常重要的信息：

- 中间位置左边的数都更小
- 中间位置右边的数都更大

所以如果我们把中间元素选为根节点，
那么：

- 左边那一段天然适合做左子树
- 右边那一段天然适合做右子树

同时因为是从中间劈开，
左右两部分的长度尽量接近，
这样树就比较平衡。

所以这题最核心的想法就是：

**每次都选中间元素作为根节点。**

## 为什么中间元素最合适

假设数组是：

```text
[-10, -3, 0, 5, 9]
```

如果选中间的 `0` 当根节点：

- 左边是 `[-10, -3]`
- 右边是 `[5, 9]`

这时：

- 左边都小于 `0`
- 右边都大于 `0`

满足二叉搜索树的要求。

而且左右两边元素个数都是 `2`，
很接近，
有利于构造平衡树。

如果你选最左边或最右边的元素做根，
就会让树严重偏斜，
不容易保持平衡。

## 为什么适合用递归

当我们选定中间元素作为根节点后，
问题就自然分成了两个更小的同类问题：

- 用左半部分数组构建左子树
- 用右半部分数组构建右子树

而“把一个有序数组转换成平衡二叉搜索树”这件事，
在左右两部分上仍然是同一个问题。

这正是递归最典型的结构：

- 大问题拆成两个更小的同类问题

所以这题非常适合递归。

## 递归定义

我们定义一个函数：

```text
build(left, right)
```

表示：

- 用 `nums[left...right]` 这一段有序数组
- 构建出一棵高度平衡二叉搜索树
- 并返回它的根节点

那么整道题最终要求的就是：

```text
build(0, len(nums) - 1)
```

## 递归终止条件

如果某一段区间没有元素了，也就是：

```text
left > right
```

说明这里不能再构造节点，
应该返回：

```text
None
```

这就是空子树。

## 递归过程

对于当前区间 `nums[left...right]`：

### 第 1 步：找到中间位置

```python
mid = (left + right) // 2
```

### 第 2 步：用中间元素创建根节点

```python
root = TreeNode(nums[mid])
```

### 第 3 步：递归构建左子树

左半部分区间是：

```text
left 到 mid - 1
```

所以：

```python
root.left = build(left, mid - 1)
```

### 第 4 步：递归构建右子树

右半部分区间是：

```text
mid + 1 到 right
```

所以：

```python
root.right = build(mid + 1, right)
```

### 第 5 步：返回当前根节点

```python
return root
```

## 为什么这样一定满足二叉搜索树

因为原数组本来就是升序排列。

当我们取 `nums[mid]` 作为根节点时：

- `mid` 左边所有元素都小于 `nums[mid]`
- `mid` 右边所有元素都大于 `nums[mid]`

所以：

- 左半部分递归构成左子树
- 右半部分递归构成右子树

天然就满足二叉搜索树的大小关系。

## 为什么这样能保持平衡

因为每次都从中间切分：

- 左右子数组长度尽量接近

这样递归生成的左右子树高度也会尽量接近。

所以整棵树会保持高度平衡。

注意：

- 当区间长度是偶数时，中间位置可能有两个候选
- 取左中点或右中点都可以

只要始终保持“从中间切分”，
构造出来的树都是合法答案。

## 用示例手推一遍

以：

```text
nums = [-10, -3, 0, 5, 9]
```

为例。

### 第 1 步：处理整个区间 `[0, 4]`

中点：

```text
mid = 2
```

所以根节点是：

```text
0
```

此时分成两部分：

- 左边：`[-10, -3]`
- 右边：`[5, 9]`

### 第 2 步：构建左子树 `[0, 1]`

中点：

```text
mid = 0
```

所以左子树根节点是：

```text
-10
```

它的右边还有一个 `-3`，
所以 `-3` 会成为 `-10` 的右孩子。

### 第 3 步：构建右子树 `[3, 4]`

中点：

```text
mid = 3
```

所以右子树根节点是：

```text
5
```

它的右边还有一个 `9`，
所以 `9` 会成为 `5` 的右孩子。

### 最终构造出的树可以是

```text
        0
      /   \
   -10     5
      \     \
      -3     9
```

这是一棵合法的二叉搜索树，
并且是平衡的，
所以答案正确。

## 算法步骤

1. 定义递归函数 `build(left, right)`
2. 如果 `left > right`，返回 `None`
3. 取中间位置 `mid`
4. 创建根节点 `TreeNode(nums[mid])`
5. 递归构建左子树 `build(left, mid - 1)`
6. 递归构建右子树 `build(mid + 1, right)`
7. 返回当前根节点
8. 主函数返回 `build(0, len(nums) - 1)`

## Python 参考实现

```python
def sortedArrayToBST(nums):
    def build(left, right):
        if left > right:
            return None

        mid = (left + right) // 2
        root = TreeNode(nums[mid])
        root.left = build(left, mid - 1)
        root.right = build(mid + 1, right)
        return root

    return build(0, len(nums) - 1)
```

## 为什么代码里不用切片

有些人会写成：

```python
left_part = nums[:mid]
right_part = nums[mid+1:]
```

这样写虽然也能做，
但每次递归都会新建子数组，
额外开销更大。

这里用的是：

- `left`
- `right`

两个下标来表示当前处理区间，
这样不会重复拷贝数组，
效率更高。

## 复杂度分析

### 时间复杂度

`O(n)`

因为：

- 每个数组元素都会恰好被选作一次树节点
- 每个节点只创建一次

所以总时间复杂度是 `O(n)`。

### 空间复杂度

`O(log n)`

因为：

- 递归每次都把区间大致平分
- 递归栈深度约为树的高度

而这棵树是平衡的，
所以高度约为 `log n`。

## 常见错误

### 1. 不选中间元素做根节点

如果总是选最左边或最右边，
虽然也可能满足二叉搜索树，
但很容易退化成链表，
不满足高度平衡。

### 2. 递归区间写错

左子树应该是：

```python
build(left, mid - 1)
```

右子树应该是：

```python
build(mid + 1, right)
```

不要把 `mid` 本身重复放进子问题，
否则会死循环。

### 3. 终止条件写成 `left >= right`

如果写成：

```python
if left >= right:
    return None
```

那当区间只剩一个元素时，
这个元素就构不成节点了，
会漏掉叶子节点。

正确写法是：

```python
if left > right:
    return None
```

### 4. 误以为答案唯一

这题允许多种合法结果。

只要：

- 是二叉搜索树
- 同时又高度平衡

即使结构和示例输出不完全一样，
也可能是正确答案。

## 一句话总结

这道题的关键就是：

**每次选择有序数组的中间元素作为根节点，再递归构造左右两半，这样既满足二叉搜索树性质，又能保证树尽量平衡。**
