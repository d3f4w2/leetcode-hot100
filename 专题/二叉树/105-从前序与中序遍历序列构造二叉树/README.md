# 105. 从前序与中序遍历序列构造二叉树

## 所属专题

- 二叉树

## 题目描述

给定两个整数数组 `preorder` 和 `inorder`，
其中：

- `preorder` 是同一棵二叉树的前序遍历结果
- `inorder` 是同一棵二叉树的中序遍历结果

请你构造这棵二叉树，并返回其根节点。

## 示例

### 示例 1

```text
输入：preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]
输出：[3,9,20,null,null,15,7]
```

对应的二叉树为：

```text
    3
   / \
  9  20
    /  \
   15   7
```

## 题意理解

这道题不是让我们“遍历”二叉树，
而是反过来：

- 已知遍历结果
- 倒推出原来的树长什么样

要做对这题，关键是抓住两种遍历各自提供的信息。

### 前序遍历告诉我们什么

前序遍历顺序是：

```text
根 -> 左 -> 右
```

所以：

- `preorder` 的第一个元素，一定是当前子树的根节点

### 中序遍历告诉我们什么

中序遍历顺序是：

```text
左 -> 根 -> 右
```

所以当我们知道根节点是谁之后，
就可以在 `inorder` 中找到它的位置。

这个位置会把中序数组分成两部分：

- 左边是左子树
- 右边是右子树

这就是整道题的核心。

## 最核心的思路

每次递归做三件事：

1. 从前序遍历中取当前根节点
2. 在中序遍历中找到这个根节点的位置
3. 根据这个位置递归构造左子树和右子树

也就是说：

- 前序负责告诉你“根是谁”
- 中序负责告诉你“左右子树边界在哪”

## 为什么适合用递归

当我们找到当前根节点后，
原问题会自然拆成两个更小的同类问题：

- 用一段前序 + 一段中序构造左子树
- 用另一段前序 + 另一段中序构造右子树

而“根据前序和中序构造二叉树”本身又是同一个问题，
所以这题非常适合递归。

## 递归定义

代码里常见的写法是定义：

```text
build(left, right)
```

它表示：

- 当前要构造的子树
- 在 `inorder` 中对应区间是 `[left, right]`

同时我们再用一个全局或闭包变量 `pre_idx`：

- 表示当前应该从 `preorder` 中取哪个元素作为根节点

这样就能一边递归，
一边顺着前序遍历往后取根。

## 为什么 `preorder[pre_idx]` 一定是当前子树的根

因为前序遍历本来就是：

```text
根 -> 左 -> 右
```

当我们递归进入某棵子树时，
前序遍历里当前轮到的第一个节点，
一定就是这棵子树的根。

所以代码里：

```python
root_val = preorder[pre_idx]
pre_idx += 1
```

就是在“消费”当前子树的根节点。

## 为什么要在中序遍历里找根节点位置

因为中序遍历是：

```text
左 -> 根 -> 右
```

假设根节点值是 `root_val`，
那么在 `inorder` 中找到它的位置 `root_index` 后：

- `root_index` 左边这段一定属于左子树
- `root_index` 右边这段一定属于右子树

所以递归边界就自然出来了。

## 为什么要用哈希表

如果每次都在线性扫描 `inorder` 里找根节点位置，
每次查找都要 `O(n)`，整体会变慢。

所以先预处理一个哈希表：

```python
inorder_map = {val: idx for idx, val in enumerate(inorder)}
```

这样：

- 查找某个值在中序遍历中的位置
- 就能在 `O(1)` 时间完成

这也是为什么总时间复杂度可以做到 `O(n)`。

## 递归终止条件

如果当前中序区间无效，也就是：

```text
left > right
```

说明这棵子树没有节点，
应该返回：

```text
None
```

这就表示空子树。

## 递归过程

对于当前区间 `[left, right]`：

### 第 1 步：从前序遍历中取根节点

```python
root_val = preorder[pre_idx]
```

### 第 2 步：创建根节点

```python
root = TreeNode(root_val)
```

### 第 3 步：让 `pre_idx` 后移

```python
pre_idx += 1
```

因为当前根节点已经用掉了。

### 第 4 步：找到根节点在中序遍历中的位置

```python
root_index = inorder_map[root_val]
```

### 第 5 步：递归构造左子树

左子树在中序中的范围是：

```text
left 到 root_index - 1
```

所以：

```python
root.left = build(left, root_index - 1)
```

### 第 6 步：递归构造右子树

右子树在中序中的范围是：

```text
root_index + 1 到 right
```

所以：

```python
root.right = build(root_index + 1, right)
```

### 第 7 步：返回当前根节点

```python
return root
```

## 为什么要先构造左子树，再构造右子树

这是因为前序遍历顺序是：

```text
根 -> 左 -> 右
```

当前拿到根节点之后，
接下来在 `preorder` 中马上出现的，
就是左子树的节点。

所以必须先递归构造左子树，
这样 `pre_idx` 的推进顺序才和前序遍历完全一致。

如果你先构造右子树，
就会把前序里的顺序用乱。

## 用示例手推一遍

以：

```text
preorder = [3,9,20,15,7]
inorder = [9,3,15,20,7]
```

为例。

### 第 1 步：构造整棵树

前序第一个元素是：

```text
3
```

所以根节点是 `3`。

在中序遍历里找到 `3`：

```text
[9, 3, 15, 20, 7]
    ^
```

于是：

- 左边 `[9]` 是左子树
- 右边 `[15,20,7]` 是右子树

### 第 2 步：构造左子树

现在 `pre_idx` 指向下一个元素：

```text
9
```

所以左子树根节点是 `9`。

在中序里，`9` 左右都没有更多元素，
所以它是一个叶子节点。

### 第 3 步：构造右子树

接下来前序里的下一个元素是：

```text
20
```

所以右子树根节点是 `20`。

在中序里找到 `20`：

```text
[15, 20, 7]
     ^
```

于是：

- 左边 `[15]` 是左子树
- 右边 `[7]` 是右子树

### 第 4 步：继续递归

接下来：

- `15` 构成 `20` 的左孩子
- `7` 构成 `20` 的右孩子

最终构造出的树就是：

```text
    3
   / \
  9  20
    /  \
   15   7
```

## 算法步骤

1. 先用哈希表记录每个值在 `inorder` 中的位置
2. 定义指针 `pre_idx`，初始为 `0`
3. 定义递归函数 `build(left, right)`
4. 如果 `left > right`，返回 `None`
5. 取 `preorder[pre_idx]` 作为当前根节点
6. 在哈希表中找到它在 `inorder` 中的位置
7. 递归构造左子树
8. 递归构造右子树
9. 返回根节点

## Python 参考实现

```python
def buildTree(preorder, inorder):
    if not preorder or not inorder:
        return None

    inorder_map = {val: idx for idx, val in enumerate(inorder)}
    pre_idx = 0

    def build(left, right):
        nonlocal pre_idx
        if left > right:
            return None

        root_val = preorder[pre_idx]
        root = TreeNode(root_val)
        pre_idx += 1

        root_index = inorder_map[root_val]
        root.left = build(left, root_index - 1)
        root.right = build(root_index + 1, right)

        return root

    return build(0, len(inorder) - 1)
```

## 为什么时间复杂度是 `O(n)`

因为：

- 每个节点只会被创建一次
- 每个节点只会在递归中处理一次
- 通过哈希表可以 `O(1)` 找到中序位置

所以整体时间复杂度是：

```text
O(n)
```

## 空间复杂度为什么是 `O(n)`

空间主要来自两部分：

- 哈希表 `inorder_map`
- 递归调用栈

哈希表需要存 `n` 个节点的位置，
所以是 `O(n)`。

递归栈在最坏情况下也可能达到 `O(n)`。

因此总体空间复杂度记为：

```text
O(n)
```

## 常见错误

### 1. 没有理解“前序定根，中序分左右”

这题最核心的就是：

- 前序的第一个元素是根
- 中序中根的左边是左子树，右边是右子树

如果这两个点没抓住，
代码就很容易写乱。

### 2. 先构造右子树，再构造左子树

因为前序顺序是：

```text
根 -> 左 -> 右
```

所以一定要先构造左子树。

### 3. 递归边界写错

空子树判断应该是：

```python
if left > right:
    return None
```

不要写成别的条件，
否则会漏节点或者死递归。

### 4. 每次都在线性查找中序位置

如果你每次都用：

```python
inorder.index(root_val)
```

虽然逻辑上可能对，
但性能会退化，
很难保持 `O(n)`。

### 5. 忘记 `nonlocal pre_idx`

如果你在内部递归函数里更新 `pre_idx`，
就需要：

```python
nonlocal pre_idx
```

否则 Python 会把它当成局部变量。

## 一句话总结

这道题的关键就是：

**用前序遍历确定当前根节点，用中序遍历切分出左右子树，再递归构造整棵树。**
