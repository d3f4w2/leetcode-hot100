# 098. 验证二叉搜索树

## 所属专题

- 二叉树

## 题目描述

给你一个二叉树的根节点 `root`，判断其是否是一个有效的二叉搜索树。

有效二叉搜索树定义如下：

- 节点的左子树只包含 **小于** 当前节点的数
- 节点的右子树只包含 **大于** 当前节点的数
- 所有左子树和右子树自身也必须都是二叉搜索树

也就是说，这道题要判断的不只是“像不像二叉搜索树”，而是：

- 整棵树的每一个节点，都必须满足二叉搜索树的严格大小关系

## 示例

### 示例 1

```text
输入：root = [2,1,3]
输出：true
```

### 示例 2

```text
输入：root = [5,1,4,null,null,3,6]
输出：false
解释：
根节点是 5。
虽然 4 在 5 的右子树里，但 4 < 5，
这违反了二叉搜索树“右子树所有节点都必须大于根节点”的规则。
```

## 题意理解

这道题最容易被误解的地方在于：

- 不是只检查“当前节点和左右孩子”的大小关系

而是要检查：

- 当前节点的整棵左子树，所有值都要小于它
- 当前节点的整棵右子树，所有值都要大于它

比如下面这棵树：

```text
    5
   / \
  1   4
     / \
    3   6
```

很多人第一眼会觉得它“差不多是 BST”，
因为：

- `1 < 5`
- `4 < 6`
- `3 < 4`

看起来局部都没问题。

但它其实不是有效二叉搜索树。

原因是：

- `4` 在 `5` 的右子树里
- 右子树里的所有节点都必须大于 `5`
- 可是 `4 < 5`

所以这道题的关键不是“局部比较”，
而是：

- 你要确保整棵树满足全局有序规则

## 最直接的想法：只比较当前节点和左右孩子

最容易想到的做法是：

- 如果左孩子存在，就检查 `left.val < root.val`
- 如果右孩子存在，就检查 `right.val > root.val`
- 然后递归检查左右子树

这个想法看起来很合理，
但其实是不够的。

因为它只能保证：

- 当前节点和它的直接孩子关系正确

却不能保证：

- 更深层的孙子节点、曾孙节点也满足和祖先节点的关系

还是拿这个例子：

```text
    5
   / \
  1   4
     / \
    3   6
```

如果你只看局部：

- `1 < 5`，没问题
- `4 > 5`，这里已经失败了

而有些更隐蔽的例子里，
甚至“当前节点和左右孩子”都看起来没问题，
但仍然会违反更高层祖先节点规定的取值范围。

所以我们需要一种能检查“整棵树是否全局有序”的方法。

## 优化思路：中序遍历判断是否严格递增

这是这道题最经典的做法之一。

### 为什么会想到中序遍历

二叉搜索树有一个非常重要的性质：

- **如果一棵树是有效 BST，那么它的中序遍历结果一定是严格递增的**

为什么？

因为中序遍历的顺序是：

```text
左子树 -> 当前节点 -> 右子树
```

而 BST 又保证：

- 左子树所有值都比当前节点小
- 右子树所有值都比当前节点大

所以按中序遍历拿到的序列，
一定会从小到大排列。

例如这棵 BST：

```text
    2
   / \
  1   3
```

它的中序遍历结果就是：

```text
[1, 2, 3]
```

这是严格递增的。

### 反过来怎么用

既然有效 BST 的中序遍历结果一定严格递增，
那我们就可以：

1. 按中序遍历整棵树
2. 记录上一个访问到的节点值 `prev`
3. 每访问一个新节点，就检查：
   - 当前值是否 **大于** `prev`
4. 如果出现：
   - 当前值小于等于 `prev`
   那就说明不是有效 BST

这里一定要注意是：

- **严格大于**

不能写成“大于等于”，
因为 BST 要求左边必须小于、右边必须大于。

## 用示例手推一遍

以示例 1 为例：

```text
root = [2,1,3]
```

树结构是：

```text
   2
  / \
 1   3
```

对它做中序遍历：

### 第 1 步：先到最左边

先访问左子树节点 `1`。

此时：

- `prev = None`
- 当前节点值是 `1`

因为还没有前一个值，
所以直接记录：

- `prev = 1`

### 第 2 步：回到根节点 2

当前节点值是 `2`。

比较：

- `2 > 1`

成立，说明顺序正确。

更新：

- `prev = 2`

### 第 3 步：访问右子树节点 3

当前节点值是 `3`。

比较：

- `3 > 2`

成立，继续更新：

- `prev = 3`

遍历结束后，整个过程中都保持严格递增，
所以这棵树是有效 BST。

## 再看一个错误例子

```text
root = [5,1,4,null,null,3,6]
```

树结构是：

```text
    5
   / \
  1   4
     / \
    3   6
```

它的中序遍历顺序是：

```text
[1, 5, 3, 4, 6]
```

你会发现这里出现了：

- `3 < 5`

也就是说，序列不再严格递增。

所以它不是有效 BST。

## 为什么这样写

### 1. 这题考的是“全局约束”，不是“局部比较”

BST 的定义不是只要求父子关系正确，
而是要求每个节点都落在正确的范围里。

所以只比较：

- `node.left.val < node.val`
- `node.right.val > node.val`

并不够。

### 2. 中序遍历天然能把 BST 变成升序序列

这是 BST 最重要的性质之一。

所以这题用中序遍历并不是技巧，
而是在利用 BST 本身的结构特点。

### 3. 为什么只需要记录前一个值

有些人会先把完整的中序遍历数组存下来，
再检查它是否递增。

当然也可以这样做，
但没有必要。

因为我们在遍历过程中，
只需要关心：

- 当前值是否大于前一个值

所以用一个变量 `prev` 就够了。

这样更省空间，也更直接。

### 4. 为什么是 `<=` 就判错

因为题目要求非常严格：

- 左子树节点值必须小于当前节点
- 右子树节点值必须大于当前节点

所以如果中序遍历过程中出现：

```text
当前值 <= 前一个值
```

那就说明：

- 要么顺序下降了
- 要么出现了重复值

这两种情况都不符合有效 BST 的定义。

## 算法步骤

1. 定义变量 `prev`，初始为 `None`
2. 定义中序遍历函数 `inorder(node)`
3. 如果当前节点为空，返回 `True`
4. 先递归检查左子树
5. 如果左子树已经不是 BST，直接返回 `False`
6. 检查当前节点值是否大于 `prev`
7. 如果当前值小于等于 `prev`，返回 `False`
8. 更新 `prev = node.val`
9. 递归检查右子树
10. 整个遍历过程中只要有一步失败，就返回 `False`
11. 全部通过后返回 `True`

## 复杂度分析

### 时间复杂度

`O(n)`

其中：

- `n` 是二叉树的节点数

原因是：

- 每个节点都会被访问一次

### 空间复杂度

`O(h)`

其中：

- `h` 是二叉树的高度

原因是：

- 递归调用栈的深度取决于树高

如果树退化成链表，
最坏情况下空间复杂度是：

```text
O(n)
```

## Python 参考实现（详细注释）

```python
from typing import Optional


class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        # prev 用来记录中序遍历过程中“上一个访问到的节点值”。
        prev = None

        def inorder(node: Optional[TreeNode]) -> bool:
            nonlocal prev

            # 空节点本身不影响 BST 合法性，直接返回 True。
            if not node:
                return True

            # 先递归检查左子树。
            # 如果左子树已经不合法，就没必要继续往下看了。
            if not inorder(node.left):
                return False

            # 中序遍历访问到当前节点时，
            # 它的值必须严格大于前一个访问到的值。
            if prev is not None and node.val <= prev:
                return False

            # 更新 prev，供后续节点比较使用。
            prev = node.val

            # 最后递归检查右子树。
            return inorder(node.right)

        return inorder(root)
```

## 这段代码最值得记住的地方

最核心的主线只有三步：

```python
if not inorder(node.left):
    return False

if prev is not None and node.val <= prev:
    return False
prev = node.val

return inorder(node.right)
```

本质上就是：

- 中序遍历整棵树
- 检查访问序列是否严格递增

只要你牢牢记住：

- **BST 的中序遍历结果一定严格递增**

这道题就很容易写出来。

## 常见错误

### 1. 只比较当前节点和左右孩子

这是最常见的错误。

BST 要求的是：

- 整个左子树都小于当前节点
- 整个右子树都大于当前节点

不是只比较直接孩子。

### 2. 把判断条件写成 `<` 而不是 `<=`

错误写法例如：

```python
if prev is not None and node.val < prev:
```

这样会漏掉“重复值”的非法情况。

正确应该是：

```python
if prev is not None and node.val <= prev:
```

### 3. 忘记把 `prev` 声明成 `nonlocal`

因为 `prev` 在内部递归函数里会被更新，
所以要写：

```python
nonlocal prev
```

否则作用域会出问题。

### 4. 先更新 `prev`，再做比较

顺序不能反。

必须先比较：

- 当前值和旧的 `prev`

确认没问题之后，
再更新：

- `prev = node.val`

## 适合你自己再写一遍的版本

```python
from typing import Optional


class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        prev = None

        def inorder(node: Optional[TreeNode]) -> bool:
            nonlocal prev
            if not node:
                return True
            if not inorder(node.left):
                return False
            if prev is not None and node.val <= prev:
                return False
            prev = node.val
            return inorder(node.right)

        return inorder(root)
```

## 一句话总结

这道题的关键不是“每个节点和孩子比大小”，而是：

**利用二叉搜索树中序遍历结果严格递增这一性质，边遍历边检查当前值是否始终大于前一个值。**
