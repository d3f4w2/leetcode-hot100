# 739. 每日温度

## 所属专题

- 栈

## 题目描述

给定一个整数数组 `temperatures`，表示每天的温度，返回一个数组 `answer`，
其中 `answer[i]` 表示对于第 `i` 天，下一个更高温度出现在几天后。

如果在这之后都不会出现更高温度，则 `answer[i] = 0`。

## 示例

### 示例 1

```text
输入：temperatures = [73,74,75,71,69,72,76,73]
输出：[1,1,4,2,1,1,0,0]
```

### 示例 2

```text
输入：temperatures = [30,40,50,60]
输出：[1,1,1,0]
```

### 示例 3

```text
输入：temperatures = [30,60,90]
输出：[1,1,0]
```

## 题意理解

这道题对每一天都要回答一个问题：

- 右边第一个比今天温度更高的日子在哪里
- 这个日子距离今天有几天

注意有两个关键点：

- 要找的是“后面第一个更高温度”
- 返回的是“相隔几天”，不是那个更高温度本身

例如：

```text
temperatures = [73,74,75,71,69,72,76,73]
```

对于下标 `2`，温度是 `75`。
它后面第一个更高温度是下标 `6` 的 `76`，
所以答案是：

```text
6 - 2 = 4
```

而对于下标 `6`，后面没有更高温度，
所以答案就是 `0`。

## 最直接的想法：每个位置都向右找

最容易想到的做法是：

1. 遍历每一天
2. 从当前位置继续往右找
3. 找到第一个更高温度就记录距离
4. 如果扫到结尾还没找到，就记 `0`

这个思路是对的，但效率不高。

因为对于每个位置，最坏情况下都要把右边再扫一遍，
时间复杂度会达到：

`O(n^2)`

例如数组单调递减时：

```text
[80,79,78,77,76]
```

几乎每个位置都要一直找到末尾，
所以我们需要更高效的办法。

## 优化思路：单调栈

这道题的经典做法是：

- 用栈保存“还没有找到下一个更高温度”的下标
- 栈中下标对应的温度保持单调不增

习惯上我们会把它叫做：

- 单调递减栈

更准确地说，是“栈底到栈顶温度单调不增”，
因为相同温度也可以同时留在栈里。

## 为什么想到用栈

当我们从左到右遍历温度时，
当前这一天的温度，可能正好可以帮助前面某几天“结算答案”。

比如当前温度是 `72`，
如果栈顶那一天的温度是 `69`，
那么我们立刻就知道：

- `72` 是 `69` 后面遇到的第一个更高温度

于是可以把那一天从栈里弹出，并更新答案。

如果继续看栈顶，发现前一天温度是 `71`，
那 `72` 也同样能帮它结算答案。

所以这里不是简单的 `if`，
而是要不断地弹栈：

```python
while stack and temperatures[i] > temperatures[stack[-1]]:
```

## 为什么栈里存的是下标，不是温度

这是这道题特别容易写错的地方。

栈里必须存下标，原因有两个：

### 1. 题目要的是“等几天”

我们最后要计算的是：

```python
i - prev_index
```

如果只存温度，就无法知道两天之间相隔多少天。

### 2. 通过下标才能回头修改答案

当我们发现某一天的下一个更高温度时，
需要把答案写回到对应位置：

```python
answer[prev_index] = i - prev_index
```

所以栈里一定要保存位置。

## 栈中维护的是什么

栈里保存的是：

- 那些还没有找到下一个更高温度的天数下标

并且这些下标对应的温度满足：

- 从栈底到栈顶单调不增

为什么能保持这个性质？

因为当我们遍历到 `temperatures[i]` 时：

- 只要它比栈顶温度高，就把栈顶弹出
- 直到栈为空，或者栈顶温度大于等于当前温度
- 然后再把当前下标入栈

这样入栈之后，栈的单调性就继续成立。

## 用示例手推一遍

以：

```text
temperatures = [73,74,75,71,69,72,76,73]
```

为例。

初始：

- `answer = [0,0,0,0,0,0,0,0]`
- `stack = []`

### 第 1 天：73

- 栈为空，直接入栈下标 `0`

```text
stack = [0]
```

### 第 2 天：74

- `74 > 73`
- 说明第 `0` 天等到了更高温度

所以：

```text
answer[0] = 1 - 0 = 1
```

弹出 `0` 后，把 `1` 入栈：

```text
stack = [1]
```

### 第 3 天：75

- `75 > 74`
- 弹出 `1`

```text
answer[1] = 2 - 1 = 1
stack = [2]
```

### 第 4 天：71

- `71` 不大于 `75`
- 直接入栈

```text
stack = [2,3]
```

### 第 5 天：69

- `69` 不大于 `71`
- 直接入栈

```text
stack = [2,3,4]
```

### 第 6 天：72

现在开始连续弹栈：

- `72 > 69`，弹出 `4`，`answer[4] = 5 - 4 = 1`
- `72 > 71`，弹出 `3`，`answer[3] = 5 - 3 = 2`
- `72` 不大于 `75`，停止

再把 `5` 入栈：

```text
stack = [2,5]
```

### 第 7 天：76

继续连续弹栈：

- `76 > 72`，弹出 `5`，`answer[5] = 6 - 5 = 1`
- `76 > 75`，弹出 `2`，`answer[2] = 6 - 2 = 4`

然后把 `6` 入栈：

```text
stack = [6]
```

### 第 8 天：73

- `73` 不大于 `76`
- 直接入栈

```text
stack = [6,7]
```

遍历结束后：

- 栈里剩下的 `6` 和 `7`
- 说明它们右边都没有更高温度
- 所以答案保持 `0`

最终结果：

```text
[1,1,4,2,1,1,0,0]
```

## 为什么这样做是对的

关键在于：

当下标 `prev_index` 被当前下标 `i` 弹出时，
当前这一天一定是 `prev_index` 右边第一个更高温度。

原因是：

### 1. 当前温度确实更高

弹栈条件就是：

```python
temperatures[i] > temperatures[prev_index]
```

所以它满足“更高温度”。

### 2. 它一定是第一个满足条件的

如果在 `prev_index` 和 `i` 之间，
已经出现过一个更高温度，
那么 `prev_index` 早就应该在那个位置被弹出了，
不可能一直留到现在。

所以当它此刻被弹出时，
当前下标 `i` 一定就是最近的那个更高温度位置。

### 3. 栈里剩下的元素确实没有答案

遍历结束后，栈里还有一些下标没被弹出，
说明它们右边再也没有更高温度，
因此这些位置答案自然就是 `0`。

## 算法步骤

1. 创建结果数组 `answer`，初始全为 `0`
2. 创建一个空栈 `stack`
3. 从左到右遍历每一天的温度下标 `i`
4. 当栈不为空且当前温度大于栈顶下标对应温度时，持续弹栈
5. 对每个弹出的下标 `prev_index`，更新 `answer[prev_index] = i - prev_index`
6. 当前下标 `i` 入栈
7. 遍历结束后直接返回 `answer`

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 每个下标最多入栈一次
- 每个下标最多出栈一次

所以虽然代码里有 `while`，
但总操作次数仍然是线性的。

### 空间复杂度

`O(n)`

原因是：

- 最坏情况下，栈中可能存下所有下标

例如温度一直递减时：

```text
[80,79,78,77,76]
```

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        answer = [0] * n
        stack = []

        for i in range(n):
            # 当前温度如果比栈顶对应温度高，
            # 说明当前这一天就是栈顶那一天等待的更高温度。
            while stack and temperatures[i] > temperatures[stack[-1]]:
                prev_index = stack.pop()
                answer[prev_index] = i - prev_index

            # 当前下标入栈，等待未来更高温度来结算。
            stack.append(i)

        return answer
```

## 这段代码最值得记住的地方

真正要记住的主线其实很短：

```python
for i in range(n):
    while stack and temperatures[i] > temperatures[stack[-1]]:
        prev_index = stack.pop()
        answer[prev_index] = i - prev_index
    stack.append(i)
```

这段逻辑可以概括成一句话：

**用单调栈保存还没找到答案的下标，一旦当前温度更高，就帮前面那些天批量结算答案。**

## 常见错误

### 1. 栈里只存温度，不存下标

这样会导致：

- 没法计算相隔几天
- 没法把答案写回正确位置

所以栈里必须存下标。

### 2. 用 `if` 代替 `while`

错误写法类似：

```python
if stack and temperatures[i] > temperatures[stack[-1]]:
```

这样一次只会处理一个位置，
但实际上当前温度可能连续解决前面很多天的答案。

所以必须用 `while` 连续弹栈。

### 3. 把严格大于写成大于等于

题目要求的是“更高温度”，
不是“更高或相等”。

所以判断必须写成：

```python
temperatures[i] > temperatures[stack[-1]]
```

不能写成：

```python
>=
```

### 4. 忘记把答案数组初始化为全 `0`

那些最终没有找到更高温度的位置，
本来就应该返回 `0`。

所以最自然的做法就是：

```python
answer = [0] * n
```

## 适合自己默写的精简版本

```python
from typing import List


class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        answer = [0] * len(temperatures)
        stack = []

        for i, temp in enumerate(temperatures):
            while stack and temp > temperatures[stack[-1]]:
                prev_index = stack.pop()
                answer[prev_index] = i - prev_index
            stack.append(i)

        return answer
```

## 一句话总结

这道题的关键是：

**用一个存下标的单调栈维护“还没等到更高温度的那些天”，当前温度一旦更高，就不断弹栈并更新等待天数，这样可以把时间复杂度优化到 `O(n)`。**
