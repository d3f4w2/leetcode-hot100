# 084. 柱状图中最大的矩形

## 所属专题

- 栈

## 题目描述

给定 `n` 个非负整数 `heights`，
用来表示柱状图中各个柱子的高度。

每个柱子彼此相邻，且宽度都为 `1`。

请你求出在这个柱状图中，
能够勾勒出的矩形的最大面积。

## 示例

### 示例 1

```text
输入：heights = [2,1,5,6,2,3]
输出：10
解释：最大矩形由高度 5 和 6 这两根柱子组成，宽度为 2，面积为 10。
```

### 示例 2

```text
输入：heights = [2,4]
输出：4
```

## 题意理解

这道题看起来是在一堆柱子里找“最大的矩形”，
但真正的关键不是找最高的柱子，
而是要理解：

- 一个矩形一定对应一段连续区间
- 这段区间的高度，不是由最高柱子决定
- 而是由这段区间里最矮的柱子决定

例如：

```text
heights = [2,1,5,6,2,3]
```

如果我们选中连续区间：

```text
[5,6]
```

那么这段区间能形成的矩形高度是：

```text
min(5,6) = 5
```

宽度是：

```text
2
```

所以面积是：

```text
5 * 2 = 10
```

因此这道题本质上可以转化成：

**对于每一根柱子，假设它是这个矩形里最矮的柱子，那么它最远能向左和向右扩展到哪里？**

只要能快速找到：

- 左边第一个比它矮的柱子
- 右边第一个比它矮的柱子

这根柱子作为“最矮高度”时的最大面积就能算出来。

## 最直接的想法：枚举每根柱子，向两边扩展

最容易想到的方法是：

1. 枚举每一根柱子 `heights[i]`
2. 向左找第一个比它矮的位置
3. 向右找第一个比它矮的位置
4. 计算它作为最矮柱子时能形成的最大面积

这样做的思路没问题，
但如果每个位置都要向左右扫描，
最坏情况下时间复杂度会退化成：

```text
O(n^2)
```

例如单调递增数组：

```text
[1,2,3,4,5,6]
```

几乎每根柱子都要扫描很多次，
效率不够高。

所以我们要继续想：

**能不能在一次遍历里，就把“左右第一个更矮的位置”高效地找出来？**

## 优化思路：单调递增栈

这道题的经典做法是：

- 使用一个单调递增栈
- 栈里存的是柱子的下标
- 栈中对应的高度始终保持递增

### 为什么想到单调栈

我们想解决的问题是：

- 某根柱子什么时候可以确定右边界？

答案是：

**当我们第一次遇到一个比它更矮的柱子时，它的右边界就确定了。**

比如栈顶柱子高度是 `6`，
当前遍历到的柱子高度是 `2`，
那就说明：

- 高度为 `6` 的柱子不能再往右扩展了
- 因为再往右就碰到了更矮的柱子 `2`

这时我们就可以立刻结算：

- 以这根高度为 `6` 的柱子作为最矮柱子时，
- 它能形成的最大矩形面积是多少

### 为什么栈里存下标，而不是直接存高度

因为我们不仅需要知道“高度是多少”，
还需要知道：

- 它左边第一个更矮的位置在哪
- 它右边第一个更矮的位置在哪
- 从而算出矩形宽度

所以必须存下标，
这样才能通过位置来计算宽度。

### 核心结论

当我们遍历到位置 `i`，当前高度是 `h = heights[i]` 时：

- 如果 `h` 大于等于栈顶对应的高度，直接入栈
- 如果 `h` 小于栈顶对应的高度，就说明栈顶柱子的右边第一个更矮柱子找到了

此时不断弹栈，
直到栈重新恢复“单调递增”为止。

每弹出一根柱子 `mid`：

- 它的高度是 `heights[mid]`
- 它右边第一个更矮的位置就是当前的 `i`
- 它左边第一个更矮的位置就是弹栈后的新栈顶

于是：

```text
宽度 = 右边界位置 - 左边界位置 - 1
```

面积就是：

```text
heights[mid] * 宽度
```

## 为什么宽度公式是 `i - stack[-1] - 1`

这是这道题最容易写错的地方。

假设我们刚刚弹出了某根柱子 `mid`。

此时：

- 当前下标 `i` 是它右边第一个更矮的位置
- 弹栈后的新栈顶 `stack[-1]` 是它左边第一个更矮的位置

那么真正能扩展成矩形的区间是：

```text
(stack[-1], i)
```

注意这里是开区间，
因为两侧那两个位置都比它矮，
不能包含进去。

所以宽度应该是：

```text
i - stack[-1] - 1
```

如果弹栈之后栈空了，
说明左边没有更矮的柱子，
可以认为左边界在 `-1`。

这时宽度就是：

```text
i - (-1) - 1 = i
```

也就是代码里的：

```python
width = i if not stack else i - stack[-1] - 1
```

遍历结束后，
栈里还可能剩下一些柱子没有被结算。

对这些柱子来说：

- 它们右边没有更矮的柱子
- 可以把右边界看成数组末尾 `n`

所以清算时宽度写成：

```python
width = n if not stack else n - stack[-1] - 1
```

## 用示例手推一遍

以：

```text
heights = [2,1,5,6,2,3]
```

为例。

我们维护一个单调递增栈，栈中存下标。

### `i = 0, h = 2`

- 栈为空，直接入栈

```text
stack = [0]
```

### `i = 1, h = 1`

当前高度 `1` 小于栈顶高度 `2`，
说明下标 `0` 这根柱子的右边界找到了。

弹出 `0`：

- 高度 = `2`
- 左边没有更矮柱子
- 右边界是 `i = 1`
- 宽度 = `1`
- 面积 = `2 * 1 = 2`

更新后再把 `1` 入栈：

```text
stack = [1]
max_area = 2
```

### `i = 2, h = 5`

- `5` 大于栈顶高度 `1`
- 直接入栈

```text
stack = [1,2]
```

### `i = 3, h = 6`

- `6` 大于栈顶高度 `5`
- 直接入栈

```text
stack = [1,2,3]
```

### `i = 4, h = 2`

当前高度 `2` 小于栈顶高度 `6`，
开始弹栈结算。

先弹出下标 `3`：

- 高度 = `6`
- 左边第一个更矮的是下标 `2`
- 右边第一个更矮的是下标 `4`
- 宽度 = `4 - 2 - 1 = 1`
- 面积 = `6 * 1 = 6`

继续看栈顶下标 `2`，高度 `5`，
仍然大于当前高度 `2`，继续弹出：

- 高度 = `5`
- 左边第一个更矮的是下标 `1`
- 右边第一个更矮的是下标 `4`
- 宽度 = `4 - 1 - 1 = 2`
- 面积 = `5 * 2 = 10`

此时最大面积更新为 `10`。

然后把当前下标 `4` 入栈：

```text
stack = [1,4]
max_area = 10
```

### `i = 5, h = 3`

- `3` 大于栈顶高度 `2`
- 直接入栈

```text
stack = [1,4,5]
```

### 遍历结束后清算栈

此时数组已经走完，
剩余柱子的右边界都可以看成 `n = 6`。

弹出下标 `5`：

- 高度 = `3`
- 左边第一个更矮的是下标 `4`
- 宽度 = `6 - 4 - 1 = 1`
- 面积 = `3`

弹出下标 `4`：

- 高度 = `2`
- 左边第一个更矮的是下标 `1`
- 宽度 = `6 - 1 - 1 = 4`
- 面积 = `8`

弹出下标 `1`：

- 高度 = `1`
- 左边没有更矮柱子
- 宽度 = `6`
- 面积 = `6`

最终最大面积仍然是：

```text
10
```

## 算法步骤

1. 创建空栈 `stack`，用于存放柱子下标
2. 创建变量 `max_area` 记录最大面积
3. 从左到右遍历每个位置 `i`
4. 当当前柱子高度小于栈顶柱子高度时，不断弹栈并计算面积
5. 弹栈时：
   - 当前下标 `i` 是右边第一个更矮的位置
   - 弹栈后的新栈顶是左边第一个更矮的位置
6. 结算完后，把当前下标压入栈中
7. 遍历结束后，继续清算栈中剩余柱子
8. 返回 `max_area`

## 为什么时间复杂度是 `O(n)`

很多人看到：

- 一个 `for`
- 里面还有一个 `while`

就会担心是不是 `O(n^2)`。

其实不是。

原因在于：

- 每个下标最多只会入栈一次
- 每个下标最多只会出栈一次

也就是说，
虽然看起来有嵌套循环，
但所有弹栈操作加起来一共也只有 `n` 次。

所以总时间复杂度仍然是：

```text
O(n)
```

## 复杂度分析

### 时间复杂度

`O(n)`

原因：

- 每个位置最多入栈一次、出栈一次

### 空间复杂度

`O(n)`

原因：

- 最坏情况下栈里可能存下所有下标

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        stack = []
        max_area = 0
        n = len(heights)

        for i, h in enumerate(heights):
            # 当前柱子更矮，说明栈顶柱子的右边界已经确定。
            while stack and heights[stack[-1]] > h:
                height = heights[stack.pop()]

                # 如果栈空，左边界视为 -1；
                # 否则新的栈顶就是左边第一个更矮的位置。
                width = i if not stack else i - stack[-1] - 1
                max_area = max(max_area, height * width)

            stack.append(i)

        # 遍历结束后，栈里剩余柱子的右边界都是 n。
        while stack:
            height = heights[stack.pop()]
            width = n if not stack else n - stack[-1] - 1
            max_area = max(max_area, height * width)

        return max_area
```

## 这段代码最值得记住的地方

真正需要记住的不是整段代码本身，
而是下面这条主线：

```python
while stack and heights[stack[-1]] > h:
    height = heights[stack.pop()]
    width = i if not stack else i - stack[-1] - 1
    max_area = max(max_area, height * width)
```

它的含义是：

**一旦遇到更矮的柱子，就立刻结算栈顶柱子作为最矮高度时的最大矩形。**

## 常见错误

### 1. 栈里存高度，不存下标

如果只存高度，
你就没办法准确计算矩形宽度。

这道题栈里一定要存：

- 下标

### 2. 宽度公式写错

很多人会写成：

```python
i - stack[-1]
```

但这是不对的。

因为左右两边那两个位置都是“第一个更矮的柱子”，
它们本身不能算进矩形宽度里，
所以一定要减 `1`。

正确写法是：

```python
i - stack[-1] - 1
```

### 3. 忘记清算遍历结束后栈里的元素

如果你只在遍历过程中弹栈，
却忘了最后再处理一遍栈，
很多以数组末尾为右边界的答案就会漏掉。

### 4. 把这题理解成“找最高柱子”

最大矩形不一定包含最高柱子，
也不一定是单根柱子本身。

关键是：

- 连续区间的宽度
- 和这段区间最小高度之间的平衡

### 5. 以为 `for` 里面套 `while` 就一定是 `O(n^2)`

这道题不是按“循环层数”看复杂度，
而是按“每个元素被处理几次”来看。

每个下标只会：

- 入栈一次
- 出栈一次

所以整体依然是线性的。

## 一句话总结

这道题的关键是：

**用单调递增栈维护还没有确定右边界的柱子，一旦遇到更矮的柱子，就结算栈顶柱子作为最矮高度时能扩展出的最大矩形面积。**
