# 322. 零钱兑换

## 所属专题
- 动态规划

## 题目描述

给你一个整数数组 `coins`，表示不同面额的硬币；以及一个整数 `amount`，表示总金额。

请你计算并返回：

- 凑成总金额所需的 **最少硬币个数**

如果没有任何一种硬币组合能够组成总金额，返回：

```text
-1
```

题目还说明：

- 每种硬币的数量都是无限的

这意味着同一种面额可以重复使用很多次。

## 示例

### 示例 1

```text
输入：coins = [1,2,5], amount = 11
输出：3
解释：11 = 5 + 5 + 1
```

### 示例 2

```text
输入：coins = [2], amount = 3
输出：-1
```

### 示例 3

```text
输入：coins = [1], amount = 0
输出：0
```

## 题意理解

这道题不是问：

- 有多少种方法可以凑出 `amount`

而是问：

- 在所有可行方案里，最少要用多少枚硬币

也就是说，
这是一道典型的“最优解”问题。

例如：

```text
coins = [1,2,5], amount = 11
```

可以凑成 `11` 的方法有很多：

- `5 + 5 + 1`
- `5 + 2 + 2 + 2`
- `2 + 2 + 2 + 2 + 2 + 1`
- ...

但题目只关心：

- 哪一种方案用的硬币数量最少

所以答案是：

```text
3
```

因为 `5 + 5 + 1` 只用了三枚硬币。

这类“最少个数”“最优方案”的题，
非常适合往动态规划方向去想。

## 最直接的想法：暴力尝试所有组合

最容易想到的是：

- 每次尝试选一个硬币
- 看剩下的金额还能不能继续凑
- 把所有可能方案都递归试一遍
- 最后取使用硬币数最少的那个

这个思路理论上是能做出来的，
但会有大量重复计算。

比如：

- 凑 `11` 的过程中可能会反复去求“凑 `6` 最少要几枚”
- 凑 `6` 的过程中又会反复去求“凑 `1` 最少要几枚”

也就是说：

- 很多子问题会被重复求解

这正是动态规划的典型使用场景。

## 优化思路：动态规划

### 状态定义

定义：

```text
dp[i] = 凑成金额 i 所需要的最少硬币数
```

那么题目要求的答案就是：

```text
dp[amount]
```

### 状态转移方程

如果我们当前想求 `dp[i]`，
那么最后放入的一枚硬币，可能是：

- `1`
- `2`
- `5`
- 或者 `coins` 里的任意一种面额

假设最后一枚硬币的面额是 `coin`，
那么在放入它之前，
我们必须已经凑出了：

```text
i - coin
```

于是就有：

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

前提是：

- `i >= coin`

因为只有当前金额至少不小于硬币面额时，
这个硬币才有机会被使用。

这就是这道题最核心的状态转移。

## 为什么这个转移是对的

因为对于金额 `i` 来说，
任何一个合法方案，最后一定会以某枚硬币结束。

如果最后一枚硬币是 `coin`，
那前面的部分一定已经构成了金额：

```text
i - coin
```

并且前面的这部分也应该尽可能使用最少硬币，
也就是：

```text
dp[i - coin]
```

再加上当前这一枚硬币，
总数就是：

```text
dp[i - coin] + 1
```

把所有可能的硬币都试一遍，
取最小值，
自然就得到 `dp[i]` 的最优解。

## 初始条件为什么是这样

### `dp[0] = 0`

凑成金额 `0`，
不需要任何硬币。

所以：

```text
dp[0] = 0
```

### 其他位置初始化为正无穷

对于还没有求出来的金额，
我们先认为它“暂时无法凑出”，
所以初始化成：

```python
float('inf')
```

这样后面在做：

```python
min(dp[i], dp[i - coin] + 1)
```

时就很方便。

它表达的含义就是：

- 当前这个金额还没有被有效方案更新过

## 用示例手推一遍

以：

```text
coins = [1,2,5], amount = 11
```

为例。

我们定义：

- `dp[i]` 表示凑成金额 `i` 的最少硬币数

初始时：

```text
dp[0] = 0
其余位置都是 inf
```

### 金额 `1`

- 用硬币 `1`：`dp[1] = dp[0] + 1 = 1`

所以：

```text
dp[1] = 1
```

### 金额 `2`

- 用硬币 `1`：`dp[2] = dp[1] + 1 = 2`
- 用硬币 `2`：`dp[2] = dp[0] + 1 = 1`

取最小值：

```text
dp[2] = 1
```

### 金额 `3`

- 用硬币 `1`：`dp[3] = dp[2] + 1 = 2`
- 用硬币 `2`：`dp[3] = dp[1] + 1 = 2`

所以：

```text
dp[3] = 2
```

### 金额 `4`

- `1 + 1 + 1 + 1`
- `2 + 2`

最优是：

```text
dp[4] = 2
```

### 金额 `5`

- 用一个 `5`

所以：

```text
dp[5] = 1
```

后面继续推：

- `dp[6] = 2`
- `dp[7] = 2`
- `dp[8] = 3`
- `dp[9] = 3`
- `dp[10] = 2`
- `dp[11] = 3`

最终得到：

```text
dp[11] = 3
```

对应方案之一就是：

```text
5 + 5 + 1
```

## 为什么这样写

### 1. 这是一个典型的“从小问题推到大问题”

如果我们已经知道：

- 金额 `1` 最少要几枚
- 金额 `2` 最少要几枚
- 金额 `3` 最少要几枚

那么更大的金额就可以在这些结果基础上继续推出。

这正是动态规划最核心的思想。

### 2. 每个金额都只和更小的金额有关

要凑出金额 `i`，
最后一枚硬币拿掉之后，
剩下的金额一定比 `i` 小。

所以我们可以按照：

- 从小到大

的顺序来填 `dp` 数组。

### 3. 这道题本质上是“完全背包”模型

因为：

- 每种硬币都可以使用无限次

这正对应完全背包的特点。

不过如果你当前还在刷 Hot100，
其实不必先死记“完全背包”这个名字，
更重要的是理解：

- `dp[i]` 表示凑出金额 `i` 的最优解
- 每次尝试把一种硬币接到更小金额的最优解后面

## 算法步骤

1. 创建长度为 `amount + 1` 的数组 `dp`
2. 将所有位置初始化为 `inf`
3. 设置 `dp[0] = 0`
4. 从金额 `1` 遍历到 `amount`
5. 对每种硬币 `coin` 进行尝试
6. 如果 `i >= coin`，就更新：`dp[i] = min(dp[i], dp[i - coin] + 1)`
7. 最后判断 `dp[amount]` 是否仍然是 `inf`
8. 如果是，返回 `-1`；否则返回 `dp[amount]`

## 复杂度分析

### 时间复杂度

`O(amount * n)`

其中：

- `amount` 是目标金额
- `n` 是硬币种类数

原因是：

- 每个金额都会遍历一遍所有硬币

### 空间复杂度

`O(amount)`

原因是：

- 使用了一个长度为 `amount + 1` 的一维数组 `dp`

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        dp = [float('inf')] * (amount + 1)
        dp[0] = 0

        for i in range(1, amount + 1):
            for coin in coins:
                if i >= coin:
                    dp[i] = min(dp[i], dp[i - coin] + 1)

        return dp[amount] if dp[amount] != float('inf') else -1
```

## 这段代码最值得记住的地方

最核心的一句就是：

```python
dp[i] = min(dp[i], dp[i - coin] + 1)
```

它的含义是：

- 如果最后用一枚 `coin`
- 那就看“凑出 `i - coin` 的最优解”再加 `1`

整道题本质上都在重复这件事。

## 常见错误

### 1. 把这题理解成“有多少种组合”

这题问的是：

- 最少硬币数

不是：

- 方案总数

这两类题的 `dp` 定义完全不同。

### 2. 初始化写错

如果把 `dp` 全部初始化成 `0`，
就无法正确表达：

- 某些金额暂时还无法凑出

所以应该初始化成：

```python
float('inf')
```

### 3. 忘记处理无法凑出的情况

例如：

```text
coins = [2], amount = 3
```

这时 `dp[3]` 最终仍然会是 `inf`，
答案应该返回：

```text
-1
```

### 4. 没有处理 `amount = 0`

当目标金额是 `0` 时，
答案应该直接是：

```text
0
```

而 `dp[0] = 0` 正好自然处理了这个边界。

### 5. 误以为每种硬币只能用一次

题目已经明确说明：

- 每种硬币数量无限

所以同一个面额可以重复使用。

## 适合自己默写的精简版本

```python
from typing import List


class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        dp = [float('inf')] * (amount + 1)
        dp[0] = 0

        for i in range(1, amount + 1):
            for coin in coins:
                if i >= coin:
                    dp[i] = min(dp[i], dp[i - coin] + 1)

        return -1 if dp[amount] == float('inf') else dp[amount]
```

## 一句话总结

这道题的关键是：

**定义 `dp[i]` 为凑成金额 `i` 的最少硬币数，然后枚举最后一枚硬币，用更小金额的最优解去更新当前金额。**
