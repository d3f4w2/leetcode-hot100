# 121. 买卖股票的最佳时机

## 所属专题
- 动态规划

## 题目描述

给定一个数组 `prices`，其中 `prices[i]` 表示某只股票在第 `i` 天的价格。

你只能选择 **某一天买入** 这只股票，并在 **未来某一天卖出**。

请你设计一个算法，计算所能获得的最大利润。

如果你不能获得任何利润，就返回 `0`。

## 示例

### 示例 1

```text
输入：prices = [7,1,5,3,6,4]
输出：5
解释：
在第 2 天价格为 1 时买入，
在第 5 天价格为 6 时卖出，
最大利润 = 6 - 1 = 5。
```

### 示例 2

```text
输入：prices = [7,6,4,3,1]
输出：0
解释：
股票价格一直在下降，无法获得正利润，
所以返回 0。
```

## 题意理解

这道题有两个关键限制：

- 只能买一次
- 只能卖一次，而且卖出必须在买入之后

所以本质上是在问：

- 对于每一天作为卖出日
- 之前有没有一个更低的买入价格
- 让利润 `卖出价 - 买入价` 最大

也就是说，
我们并不是要找“两个数的最大差值”那么简单，
而是要找：

- 前面某一天的最低价格
- 和当前价格之间的最大差值

这正是这道题的核心。

## 最直接的想法：枚举买入日和卖出日

最容易想到的方法是：

- 枚举每一天作为买入日
- 再枚举它后面的每一天作为卖出日
- 计算所有可能利润的最大值

这样当然能做出来，
但时间复杂度是：

```text
O(n^2)
```

因为：

- 每个买入日都要和后面的很多天比较
- 数据一大就会比较慢

所以我们要继续想：

- 能不能一边遍历，一边顺手维护“到目前为止最适合买入的价格”？

## 优化思路：一次遍历

我们在遍历价格数组时，只需要维护两个变量：

- `min_price`：到当前为止见过的最低价格
- `max_profit`：到当前为止能获得的最大利润

### 为什么只需要这两个量

假设今天价格是 `price`，
如果今天决定卖出，
那最好的买入时机一定是：

- 今天之前价格最低的那一天

也就是说，
今天卖出的最大收益就是：

```text
price - min_price
```

然后我们再把这个收益和历史最大收益比较，更新：

```text
max_profit = max(max_profit, price - min_price)
```

同时，遍历到今天之后，
也要更新“到目前为止最低价格”：

```text
min_price = min(min_price, price)
```

这样每走一步：

- 都知道之前最便宜的买入价
- 都能计算今天卖出能赚多少
- 都能维护全局最大利润

## 用示例手推一遍

以：

```text
prices = [7,1,5,3,6,4]
```

为例。

### 初始状态

- `min_price = +∞`
- `max_profit = 0`

### 第 1 天，价格 = 7

- 更新最低价：`min_price = 7`
- 今天卖出利润：`7 - 7 = 0`
- 更新最大利润：`max_profit = 0`

### 第 2 天，价格 = 1

- 更新最低价：`min_price = 1`
- 今天卖出利润：`1 - 1 = 0`
- 更新最大利润：`max_profit = 0`

### 第 3 天，价格 = 5

- 当前最低价仍然是 `1`
- 今天卖出利润：`5 - 1 = 4`
- 更新后：`max_profit = 4`

### 第 4 天，价格 = 3

- 当前最低价仍然是 `1`
- 今天卖出利润：`3 - 1 = 2`
- 最大利润仍然是 `4`

### 第 5 天，价格 = 6

- 当前最低价仍然是 `1`
- 今天卖出利润：`6 - 1 = 5`
- 更新后：`max_profit = 5`

### 第 6 天，价格 = 4

- 当前最低价仍然是 `1`
- 今天卖出利润：`4 - 1 = 3`
- 最大利润仍然是 `5`

最终答案：

```text
5
```

## 为什么这样写

### 1. 卖出日一旦固定，最佳买入日只需要关注“之前的最低价”

比如今天价格是 `6`，
那你不用关心之前所有天的全部组合，
只需要关心：

- 之前最小的价格是多少

因为：

- 买得越便宜，利润越大

所以每一天作为卖出日时，
只要拿它减去“历史最低价”即可。

### 2. 遍历一次就够了

我们从左到右扫数组时：

- 左边是已经看过的历史价格
- 当前值是今天卖出的价格

这样天然保证了：

- 买入发生在卖出之前

所以不用额外判断顺序问题。

### 3. 题目允许“不交易”

如果股票一路下跌，
那么任何一次交易都会亏钱。

但题目要求的是：

- 如果不能获利，就返回 `0`

所以 `max_profit` 初始设为 `0` 很合理，
表示：

- 最差情况就什么都不做

## 算法步骤

1. 初始化 `min_price = float('inf')`
2. 初始化 `max_profit = 0`
3. 遍历数组中的每个价格 `price`
4. 更新当前最低价格 `min_price = min(min_price, price)`
5. 计算今天卖出时的利润 `price - min_price`
6. 用它更新最大利润 `max_profit`
7. 遍历结束后返回 `max_profit`

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 整个数组只遍历一次
- 每次循环只做常数次操作

### 空间复杂度

`O(1)`

原因是：

- 只用了两个额外变量
- 没有使用额外数组或哈希表

## Python 参考实现（详细注释）

```python
class Solution:
    def maxProfit(self, prices):
        # 记录到当前为止遇到的最低价格
        min_price = float('inf')

        # 记录最大利润
        max_profit = 0

        for price in prices:
            # 先更新最低买入价
            min_price = min(min_price, price)

            # 再计算如果今天卖出，最多能赚多少
            max_profit = max(max_profit, price - min_price)

        return max_profit
```

## 这段代码最值得记住的地方

核心就两句：

```python
min_price = min(min_price, price)
max_profit = max(max_profit, price - min_price)
```

第一句负责维护：

- 到目前为止最便宜的买入价格

第二句负责维护：

- 到目前为止最大的卖出收益

你可以把整道题记成一句话：

**一边遍历，一边记录历史最低价，并尝试让当前价格作为卖出点去更新最大利润。**

## 常见错误

### 1. 写成双重循环，时间复杂度过高

虽然双重循环能做出来，
但会把时间复杂度写成：

```text
O(n^2)
```

这道题更推荐使用一次遍历。

### 2. 忘记“买入必须在卖出之前”

如果只是机械地找数组中的最大值和最小值，
可能会出现：

- 最小值在最大值后面

这种情况实际上不能交易成功。

而一次遍历维护历史最低价，
就天然避免了这个问题。

### 3. 把利润写反了

正确写法是：

```python
price - min_price
```

而不是：

```python
min_price - price
```

否则利润符号会反。

### 4. 没有处理“全程不赚钱”的情况

例如：

```text
[7,6,4,3,1]
```

这时答案应该是：

```text
0
```

而不是负数。

所以最大利润初始值应该设成 `0`。

## 适合自己默写的精简版本

```python
class Solution:
    def maxProfit(self, prices):
        min_price = float('inf')
        max_profit = 0

        for price in prices:
            min_price = min(min_price, price)
            max_profit = max(max_profit, price - min_price)

        return max_profit
```

## 一句话总结

这道题的关键是：

**遍历过程中持续记录历史最低价，并把当前价格当作卖出价去更新最大利润。**
