# 070. 爬楼梯

## 所属专题
- 动态规划

## 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶？

## 示例

### 示例 1

```text
输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶
```

### 示例 2

```text
输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶
```

## 题意理解

这道题表面上像是在数“爬楼梯的方法数”，
但本质上是在问：

**到达第 `n` 阶，一共有多少种走法。**

题目里给了一个非常关键的限制：

- 每次只能走 `1` 阶
- 或者走 `2` 阶

所以到达某一阶时，你最后一步只可能来自两种情况：

- 从前一阶走 `1` 步上来
- 从前两阶走 `2` 步上来

这就说明：

- 到达第 `n` 阶的方法数
- 和到达第 `n - 1` 阶、`n - 2` 阶的方法数有关

这正是动态规划最典型的信号。

## 最直接的想法：暴力递归

最容易想到的方式是：

- 要到第 `n` 阶
- 可以先走到第 `n - 1` 阶，再迈 `1` 步
- 或者先走到第 `n - 2` 阶，再迈 `2` 步

于是可以写出递归：

```text
f(n) = f(n - 1) + f(n - 2)
```

比如：

- `f(3) = f(2) + f(1)`
- `f(4) = f(3) + f(2)`

这个思路本身是对的，
但如果直接递归，会有很多重复计算。

例如计算 `f(5)` 时：

- 会计算 `f(4)` 和 `f(3)`
- 而计算 `f(4)` 时又会再次计算 `f(3)` 和 `f(2)`

也就是说：

- 同一个子问题会被反复求很多次
- 时间复杂度会快速变大

所以暴力递归虽然好想，
但效率不够高。

## 优化思路：动态规划

### 核心想法

既然：

```text
f(n) = f(n - 1) + f(n - 2)
```

那我们完全可以把前面算过的答案保存下来，
后面直接复用。

这就是动态规划的核心：

- 大问题拆成小问题
- 小问题答案保存下来
- 避免重复计算

### 定义状态

定义：

```text
dp[i] = 到达第 i 阶的方法数
```

那么题目要求的就是：

```text
dp[n]
```

### 状态转移方程

到达第 `i` 阶，最后一步只有两种可能：

#### 情况 1：最后走了 1 阶

那前面一定已经到达了第 `i - 1` 阶。

这种情况的方法数是：

```text
dp[i - 1]
```

#### 情况 2：最后走了 2 阶

那前面一定已经到达了第 `i - 2` 阶。

这种情况的方法数是：

```text
dp[i - 2]
```

把两种情况加起来：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

这就是这道题最核心的状态转移方程。

### 初始条件为什么是 `dp[1] = 1`、`dp[2] = 2`

#### 到第 1 阶

只有一种方法：

- 走 `1` 步

所以：

```text
dp[1] = 1
```

#### 到第 2 阶

有两种方法：

- `1 + 1`
- `2`

所以：

```text
dp[2] = 2
```

有了这两个起点，后面的值就都能推出来了。

## 用示例手推一遍

以 `n = 5` 为例：

### 第 1 步：初始化

- `dp[1] = 1`
- `dp[2] = 2`

### 第 2 步：计算 `dp[3]`

```text
dp[3] = dp[2] + dp[1] = 2 + 1 = 3
```

也就是：

- `1 + 1 + 1`
- `1 + 2`
- `2 + 1`

### 第 3 步：计算 `dp[4]`

```text
dp[4] = dp[3] + dp[2] = 3 + 2 = 5
```

### 第 4 步：计算 `dp[5]`

```text
dp[5] = dp[4] + dp[3] = 5 + 3 = 8
```

所以答案是：

```text
8
```

## 为什么这样写

### 1. 到第 `i` 阶，只和前两阶有关

因为每次只能走 `1` 阶或 `2` 阶，
所以最后一步的来源只可能是：

- `i - 1`
- `i - 2`

这正好构成一个非常典型的递推关系。

### 2. 这道题本质上和斐波那契数列很像

你会发现：

- `1, 2, 3, 5, 8, ...`

它和斐波那契数列的形式非常接近。

原因就在于它们的递推公式一样，
都是当前值由前两个值相加得到。

### 3. 不一定要真的开一个 `dp` 数组

因为 `dp[i]` 只依赖：

- `dp[i - 1]`
- `dp[i - 2]`

所以更早的值一旦用完，
其实就不需要再保留了。

这就意味着：

- 不用整个数组
- 只用两个变量滚动更新就够了

### 4. 这就是“空间优化”的动态规划

我们可以用：

- `a` 表示前前一个状态
- `b` 表示前一个状态

每次更新：

```python
a, b = b, a + b
```

最后 `b` 就是答案。

## 算法步骤

1. 如果 `n <= 2`，直接返回 `n`
2. 用两个变量记录到前两阶的方法数
3. 从第 `3` 阶开始循环到第 `n` 阶
4. 每次用前两个状态更新当前状态
5. 循环结束后返回最终答案

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 从 `3` 一直计算到 `n`
- 每一阶只做一次常数时间更新

### 空间复杂度

`O(1)`

原因是：

- 只使用了两个额外变量
- 没有开与 `n` 成比例的数组

## Python 参考实现（详细注释）

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        a = 1
        b = 2

        for _ in range(3, n + 1):
            a, b = b, a + b

        return b
```

## 这段代码最值得记住的地方

最核心的是这句状态更新：

```python
a, b = b, a + b
```

它表示：

- 原来的 `b` 变成新的前一个状态
- 原来的 `a + b` 变成新的当前状态

本质上就是在滚动维护：

- `dp[i - 2]`
- `dp[i - 1]`

这也是这道题空间优化的关键。

## 常见错误

### 1. 把这题写成暴力递归，导致超时

递归公式虽然容易想到，
但如果不做记忆化或动态规划，
会有大量重复计算。

### 2. 初始条件写错

最容易错的是：

- `dp[1] = 1`
- `dp[2] = 2`

如果初始值错了，后面全都会错。

### 3. 没有处理 `n <= 2`

如果不先特判：

- `n = 1`
- `n = 2`

后面的循环和变量初始化可能会出问题。

### 4. 知道是动态规划，但没意识到可以优化空间

开数组当然没问题，
但这题更值得记住的是：

- 只依赖前两个状态
- 所以可以压缩成两个变量

## 适合你自己再写一遍的版本

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        a, b = 1, 2
        for _ in range(3, n + 1):
            a, b = b, a + b

        return b
```

## 一句话总结

这道题的关键不是单纯记住公式，而是：

**把“到第 `n` 阶的方法数”理解成由“到第 `n - 1` 阶”和“到第 `n - 2` 阶”的方法数相加得到，然后用动态规划滚动计算。**
