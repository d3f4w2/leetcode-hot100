# 300. 最长递增子序列

## 所属专题
- 动态规划

## 题目描述

给你一个整数数组 `nums`，找到其中 **最长严格递增子序列** 的长度。

这里的“子序列”指的是：

- 可以从原数组中删除一些元素
- 也可以一个都不删
- 但剩下元素的相对顺序不能改变

例如：

```text
[3,6,2,7]
```

是数组：

```text
[0,3,1,6,2,2,7]
```

的一个子序列。

## 示例

### 示例 1

```text
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列之一是 [2,3,7,101]，长度为 4。
```

### 示例 2

```text
输入：nums = [0,1,0,3,2,3]
输出：4
```

### 示例 3

```text
输入：nums = [7,7,7,7,7,7,7]
输出：1
```

## 题意理解

这道题要求的不是：

- 连续递增子数组

而是：

- 递增子序列

这意味着：

- 中间可以跳过一些元素
- 只要顺序不乱就可以

同时还要注意一个词：

- **严格递增**

也就是说：

- 后一个数必须大于前一个数
- 相等不算递增

所以像：

```text
[7,7]
```

并不能算递增子序列。

这道题最常见有两种思路：

- 动态规划，容易理解
- 贪心 + 二分查找，效率更高

## 方法一：动态规划

### 状态定义

定义：

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

这个定义很关键。

注意它不是说：

- 前 `i` 个数里的最长递增子序列

而是明确要求：

- 必须以 `nums[i]` 作为结尾

### 状态转移方程

如果想让 `nums[i]` 接在某个递增子序列后面，
那前一个元素 `nums[j]` 必须满足：

```text
0 <= j < i 且 nums[j] < nums[i]
```

这样我们就可以把 `nums[i]` 接到以 `nums[j]` 结尾的递增子序列后面。

所以有：

```text
dp[i] = max(dp[j] + 1)
```

其中 `0 <= j < i` 且 `nums[j] < nums[i]`。

如果前面没有任何数能接到 `nums[i]` 前面，
那么它自己单独也能构成长度为 `1` 的递增子序列：

```text
dp[i] = 1
```

### 初始条件

一开始每个位置都至少可以单独成为一个长度为 `1` 的递增子序列，
所以：

```text
dp[i] = 1
```

### 最终答案

因为最长递增子序列不一定恰好以最后一个元素结尾，
所以答案应该是：

```text
max(dp)
```

### 用示例手推一遍

以：

```text
nums = [10,9,2,5,3,7,101,18]
```

为例。

初始时：

```text
dp = [1,1,1,1,1,1,1,1]
```

#### i = 0，nums[0] = 10

- 前面没有元素
- 所以 `dp[0] = 1`

#### i = 1，nums[1] = 9

- `10 < 9` 不成立
- 所以 `dp[1] = 1`

#### i = 2，nums[2] = 2

- 前面没有更小元素
- 所以 `dp[2] = 1`

#### i = 3，nums[3] = 5

前面比 `5` 小的有：

- `2`

所以：

```text
dp[3] = dp[2] + 1 = 2
```

#### i = 4，nums[4] = 3

前面比 `3` 小的有：

- `2`

所以：

```text
dp[4] = dp[2] + 1 = 2
```

#### i = 5，nums[5] = 7

前面比 `7` 小的有：

- `2`
- `5`
- `3`

取其中最长的：

```text
dp[5] = max(dp[2], dp[3], dp[4]) + 1
      = max(1, 2, 2) + 1
      = 3
```

#### i = 6，nums[6] = 101

前面几乎所有数都比它小，
最长的可以接在 `7` 后面：

```text
dp[6] = dp[5] + 1 = 4
```

#### i = 7，nums[7] = 18

前面比 `18` 小的有很多，
最长的也可以接在 `7` 后面：

```text
dp[7] = dp[5] + 1 = 4
```

最终：

```text
dp = [1,1,1,2,2,3,4,4]
```

答案是：

```text
max(dp) = 4
```

### 复杂度分析

#### 时间复杂度

`O(n^2)`

原因是：

- 外层枚举每个位置 `i`
- 内层回头看所有 `j < i`

#### 空间复杂度

`O(n)`

原因是：

- 使用了长度为 `n` 的 `dp` 数组

## 方法二：贪心 + 二分查找

动态规划容易理解，
但如果想进一步优化时间复杂度，
可以使用：

- 贪心
- 二分查找

### 核心思想

我们维护一个数组：

```text
tails
```

其中：

```text
tails[i] = 长度为 i + 1 的递增子序列的最小结尾元素
```

这句话是整道题最关键、也最容易绕的地方。

它的意思不是：

- `tails` 就是一条真实的最长递增子序列

而是说：

- 对于每一种长度
- 我们尽量让这个长度对应的结尾值更小

因为：

- 结尾越小
- 后面越容易接上更大的数

所以“小结尾”比“大结尾”更有潜力。

### 遍历时怎么更新

对于当前数字 `num`：

#### 情况 1：`num` 比 `tails` 中所有元素都大

说明它可以接在当前最长递增子序列后面，
于是：

- 直接把它加到 `tails` 末尾

#### 情况 2：`num` 不能直接接到末尾

这时我们就找到 `tails` 中第一个 **大于等于** `num` 的位置，
然后用 `num` 去替换它。

这样做的目的不是立刻得到答案，
而是让当前这个长度的递增子序列拥有一个更小的结尾，
方便以后继续延长。

### 为什么可以二分查找

`tails` 数组始终保持递增，
所以我们可以在里面二分查找：

- 第一个大于等于 `num` 的位置

这就把查找位置的时间从 `O(n)` 降到了 `O(log n)`。

### 用示例手推一遍

还是以：

```text
nums = [10,9,2,5,3,7,101,18]
```

为例。

#### 处理 10

```text
tails = [10]
```

#### 处理 9

找到第一个大于等于 `9` 的位置，即下标 `0`，替换：

```text
tails = [9]
```

#### 处理 2

替换下标 `0`：

```text
tails = [2]
```

#### 处理 5

`5` 大于所有元素，直接追加：

```text
tails = [2,5]
```

#### 处理 3

找到第一个大于等于 `3` 的位置，即下标 `1`，替换：

```text
tails = [2,3]
```

#### 处理 7

追加：

```text
tails = [2,3,7]
```

#### 处理 101

追加：

```text
tails = [2,3,7,101]
```

#### 处理 18

找到第一个大于等于 `18` 的位置，即下标 `3`，替换：

```text
tails = [2,3,7,18]
```

最后：

```text
len(tails) = 4
```

这就是最长递增子序列的长度。

### 为什么这样写

#### 1. 我们不关心某个长度对应的具体序列长什么样

我们真正关心的是：

- 某个长度能不能继续延长

而想让它更容易延长，
就应该让结尾尽量小。

所以维护“最小结尾”是非常自然的贪心策略。

#### 2. 替换不会破坏答案

如果某个长度原来结尾是 `10`，
现在我们把它替换成 `7`，
那么：

- 长度没有变短
- 但结尾更小了

这只会让后续更容易接上新数字，
不会让最优答案变差。

#### 3. `tails` 的长度就是答案

因为：

- `tails[0]` 表示长度为 `1` 的某种最优结尾
- `tails[1]` 表示长度为 `2` 的某种最优结尾
- ...

所以 `tails` 有多长，
就说明目前最长递增子序列能有多长。

### 复杂度分析

#### 时间复杂度

`O(n log n)`

原因是：

- 需要遍历每个数字一次
- 每次在 `tails` 中二分查找位置

#### 空间复杂度

`O(n)`

原因是：

- 最坏情况下 `tails` 长度可能达到 `n`

## Python 参考实现（优化方法）

```python
class Solution:
    def lengthOfLIS(self, nums):
        tails = []

        for num in nums:
            left, right = 0, len(tails)

            while left < right:
                mid = (left + right) // 2
                if tails[mid] < num:
                    left = mid + 1
                else:
                    right = mid

            if left == len(tails):
                tails.append(num)
            else:
                tails[left] = num

        return len(tails)
```

## 适合入门理解的动态规划版本

```python
class Solution:
    def lengthOfLIS(self, nums):
        n = len(nums)
        dp = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    dp[i] = max(dp[i], dp[j] + 1)

        return max(dp)
```

## 这段代码最值得记住的地方

如果你是第一次学这题，
建议先记住动态规划版本：

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

如果你已经熟悉 DP，
那就再进一步记住优化版的核心：

```text
tails[i] = 长度为 i + 1 的递增子序列的最小结尾
```

这两句话理解透了，
这题基本就掌握了。

## 常见错误

### 1. 把“子序列”看成“子数组”

子数组通常要求连续，
而子序列不要求连续。

这两个概念千万不要混。

### 2. 忘记“严格递增”

这题要求的是：

```text
nums[j] < nums[i]
```

不是：

```text
nums[j] <= nums[i]
```

相等不能接上去。

### 3. 误以为 `tails` 就是最终答案对应的真实序列

`tails` 只是在维护每个长度的最优结尾，
并不一定是某一条真实的最长递增子序列本身。

这点非常容易误解。

### 4. 二分查找时找错位置

应该找的是：

- 第一个大于等于 `num` 的位置

而不是：

- 第一个大于 `num` 的位置

因为题目要求严格递增，
相等时也应该替换。

## 一句话总结

这道题的关键是：

**入门时先理解 `dp[i]` 表示“以 `nums[i]` 结尾”的最长递增子序列长度，进阶时再掌握 `tails` 维护“每种长度的最小结尾”的贪心 + 二分做法。**
