# 045. 跳跃游戏 II

## 所属专题

- 贪心

## 题目描述

给你一个非负整数数组 `nums`，
你最初位于数组的第一个位置。

数组中的每个元素表示你在该位置最多可以向前跳跃的长度。

你的目标是使用**最少的跳跃次数**到达数组的最后一个位置。
题目保证你一定可以到达最后一个位置。

## 示例

### 示例 1

```text
输入：nums = [2,3,1,1,4]
输出：2
解释：先从下标 0 跳到下标 1，再从下标 1 跳到最后一个位置。
```

### 示例 2

```text
输入：nums = [1]
输出：0
```

## 题意理解

这道题不是问：

- 能不能跳到最后

因为题目已经明确说了：

- **一定可以到达最后一个位置**

它真正要问的是：

- **最少需要跳几次**

比如：

```text
nums = [2,3,1,1,4]
```

在下标 `0` 时，最多可以跳到：

- 下标 `1`
- 下标 `2`

如果先跳到 `1`，下一步最远可以直接到 `4`；
如果先跳到 `2`，下一步最多只能到 `3`。

所以最优做法是：

- 第一次跳到一个“让下一步尽量跳得更远”的位置
- 最终用尽可能少的跳跃次数到达终点

这就提示我们：

- 这题适合用**贪心**

## 为什么适合用贪心

如果你站在某个位置，
你当然可以枚举“下一步跳到哪里”。

但题目要的是：

- 最少跳几次

这类“最少步数”问题，
可以把它理解成一层一层往外扩展。

也就是说：

- 跳 `1` 次能到哪些位置
- 跳 `2` 次能到哪些位置
- 跳 `3` 次能到哪些位置

当我们在当前这层范围内扫描时，
只需要关心一件事：

- **下一次跳跃最远能覆盖到哪里**

因此我们不需要真的决定“这一步精确跳到哪个下标”，
而是维护当前层和下一层的最远边界即可。

这正是这道题贪心的核心。

## 贪心中的三个变量

我们维护三个变量：

### 1. `jumps`

表示当前已经跳了多少次。

### 2. `end`

表示在当前跳跃次数下，
最远可以到达的位置。

你可以把它理解成：

- 当前这一层的右边界

### 3. `max_pos`

表示在扫描当前层的过程中，
下一次跳跃最远能够到达的位置。

也可以理解成：

- 下一层的最远边界

## 具体过程在做什么

我们从左到右遍历数组，
但注意只需要遍历到 `len(nums) - 2`。

因为：

- 到达最后一个位置时，不需要再继续起跳
- 如果还处理最后一个位置，容易多加一次跳跃

对于每个位置 `i`：

```python
max_pos = max(max_pos, i + nums[i])
```

这一步表示：

- 如果当前站在 `i`，最远可以跳到 `i + nums[i]`
- 我们要在当前层所有位置里，更新出下一层最远边界

然后判断：

```python
if i == end:
```

这表示：

- 当前这一层已经扫描完了
- 必须进行一次新的跳跃

于是：

```python
jumps += 1
end = max_pos
```

含义就是：

- 跳跃次数加一
- 进入下一层
- 新一层的右边界更新为 `max_pos`

## 用示例手推一遍

以：

```text
nums = [2,3,1,1,4]
```

为例。

初始状态：

```text
jumps = 0
end = 0
max_pos = 0
```

### 第 1 步：处理下标 0

```text
i = 0
```

更新：

```text
max_pos = max(0, 0 + 2) = 2
```

此时 `i == end`，说明当前层扫描结束，
需要跳一次：

```text
jumps = 1
end = 2
```

这表示：

- 用 1 次跳跃，最远已经可以覆盖到下标 `2`

### 第 2 步：处理下标 1

```text
i = 1
```

更新：

```text
max_pos = max(2, 1 + 3) = 4
```

说明如果下一次从当前层里选最佳落点，
最远可以到 `4`。

### 第 3 步：处理下标 2

```text
i = 2
```

更新：

```text
max_pos = max(4, 2 + 1) = 4
```

此时 `i == end`，说明这一层也扫描完了，
所以再跳一次：

```text
jumps = 2
end = 4
```

现在已经覆盖到最后一个位置，
所以最少跳跃次数就是：

```text
2
```

## 为什么这样贪心一定正确

关键点在于：

- 当前层中的所有位置，使用的跳跃次数都一样

既然它们都属于“同一次数”能到达的位置，
那么在这一层里，
我们最关心的就不是具体落在哪个点，
而是：

- 从这一层出发，下一次最远能扩展到哪里

所以：

- 在当前层扫描期间，不急着增加跳跃次数
- 先把这一层能带来的最远范围全部算出来
- 等扫描到 `end` 时，再统一跳一次

这样做相当于按层进行 BFS，
只不过这里不需要真的建图。

因此第一次到达某一层时使用的跳数，
就一定是最少跳数。

## 算法步骤

1. 初始化 `jumps = 0`、`end = 0`、`max_pos = 0`
2. 从左到右遍历数组，下标范围是 `0` 到 `len(nums) - 2`
3. 对每个位置更新 `max_pos = max(max_pos, i + nums[i])`
4. 如果 `i == end`，说明当前层扫描结束
5. 跳跃次数加一：`jumps += 1`
6. 更新下一层边界：`end = max_pos`
7. 遍历结束后返回 `jumps`

## Python 参考实现

```python
def jump(nums):
    jumps = 0
    end = 0
    max_pos = 0

    for i in range(len(nums) - 1):
        max_pos = max(max_pos, i + nums[i])
        if i == end:
            jumps += 1
            end = max_pos

    return jumps
```

## 为什么这段代码是对的

因为它始终维护了两个边界：

- `end`：当前跳数下的最远覆盖范围
- `max_pos`：下一跳能够达到的最远位置

当我们在区间 `[当前层起点, end]` 内扫描时，
所有这些位置都表示：

- 用同样多的跳跃次数可以到达

所以扫描这一整层时，
只要记录它们能扩展出的最远位置即可。

一旦扫描到 `end`，
说明当前层已经全部看完，
此时必须增加一次跳跃，
并把新的边界更新成 `max_pos`。

因此每次 `jumps += 1` 都是必要的，
而且每次更新后的覆盖范围又是当前能做到的最远范围，
所以最终得到的一定是最少跳跃次数。

## 复杂度分析

### 时间复杂度

`O(n)`

因为只遍历了一次数组。

### 空间复杂度

`O(1)`

因为只使用了常数个额外变量。

## 常见错误

### 1. 遍历到最后一个下标

如果循环写成：

```python
for i in range(len(nums)):
```

那么在最后一个位置可能会多加一次跳跃。

正确写法是：

```python
for i in range(len(nums) - 1):
```

### 2. 每走一步都把 `jumps` 加一

`jumps` 不是“走过几个下标”，
而是“完成了几次跳跃”。

只有当扫描到当前层边界 `end` 时，
才说明必须真正跳一次。

### 3. 搞混 `end` 和 `max_pos`

- `end` 是当前层边界
- `max_pos` 是下一层最远边界

这两个变量一个表示“现在”，
一个表示“下一步”，不能混用。

### 4. 把这题写成 `O(n^2)` 的动态规划

动态规划当然也能做，
但这题有更优的贪心解法，
时间复杂度只需要 `O(n)`。

### 5. 忘记考虑 `nums = [1]`

如果数组长度本来就是 `1`，
说明你一开始就站在终点，
答案应该是 `0`。

而这份代码由于循环不会进入，
自然会正确返回 `0`。

## 一句话总结

**这道题的关键就是：把“最少跳跃次数”理解成按层扩展，每次扫描完当前能到达的范围后再跳一次，并用贪心维护下一层能到达的最远边界。**
