# 055. 跳跃游戏

## 所属专题
- 贪心

## 题目描述

给定一个非负整数数组 `nums`，你最初位于数组的第一个下标。

数组中的每个元素 `nums[i]` 表示你在位置 `i` 最多可以向前跳跃的长度。

请你判断：

- 是否能够从下标 `0`
- 最终到达数组的最后一个下标

## 示例

### 示例 1

```text
输入：nums = [2,3,1,1,4]
输出：true
解释：
先从下标 0 跳到下标 1，
再从下标 1 跳到最后一个下标。
```

### 示例 2

```text
输入：nums = [3,2,1,0,4]
输出：false
解释：
无论怎么跳，都会被下标 3 的 0 卡住，无法到达最后一个下标。
```

## 题意理解

这道题不是让我们求：

- 最少跳几步
- 一共有多少种跳法

而是只问一件事：

- **最后能不能到达终点**

因此我们不需要真的把每一种跳法都枚举出来，
只需要关心：

- 走到当前为止
- 我们最远能到哪里

这就是这道题的贪心切入点。

## 最直接的想法：回溯枚举所有跳法

最容易想到的方法是：

- 从当前位置出发
- 枚举可以跳的每一步
- 递归尝试后续位置

这样当然能判断能不能到终点，
但会有大量重复搜索，效率很低。

因为题目只问“能不能到”，
并不需要真的把路径找出来，
所以没有必要把所有可能都试一遍。

## 贪心思路

### 核心想法

维护一个变量：

```text
max_reach
```

表示：

- 在当前已经扫描过的位置中
- 我们最远可以到达的下标是多少

遍历数组时，如果当前来到位置 `i`，那么：

- 前提是这个位置必须可达
- 如果 `i` 都到不了，那后面更不可能到达

一旦 `i` 可达，我们就可以利用当前位置的跳跃能力更新：

```text
max_reach = max(max_reach, i + nums[i])
```

意思是：

- 原来最远能到 `max_reach`
- 现在站在 `i` 上，还能跳到 `i + nums[i]`
- 两者取更远的那个即可

## 为什么这个贪心是对的

因为我们并不关心：

- 具体是怎么跳的
- 每一步跳几格

我们只关心：

- 当前所有可达位置中
- 能把“最远边界”推进到哪里

如果某个位置 `i` 满足：

```text
i > max_reach
```

说明当前这个位置根本到不了。

既然连 `i` 都到不了，
那后面的 `i + 1`、`i + 2` 更不可能从前面跳过去，
因此可以直接返回 `False`。

反过来，只要在遍历过程中出现：

```text
max_reach >= len(nums) - 1
```

就说明最后一个下标已经处在我们可达的范围内，
可以直接返回 `True`。

## 用示例手推一遍

以：

```text
nums = [2,3,1,1,4]
```

为例。

### 初始状态

```text
max_reach = 0
```

表示一开始只能站在下标 `0`。

### 位置 0

当前：

```text
i = 0
```

因为：

```text
0 <= max_reach
```

所以位置 `0` 可达。

更新最远位置：

```text
max_reach = max(0, 0 + 2) = 2
```

说明现在最远可以到下标 `2`。

### 位置 1

```text
i = 1
```

因为：

```text
1 <= max_reach
```

所以位置 `1` 也可达。

更新：

```text
max_reach = max(2, 1 + 3) = 4
```

这时：

```text
max_reach = 4
```

已经大于等于最后一个下标 `4`，
所以可以直接判断答案是 `True`。

## 再看一个失败例子

```text
nums = [3,2,1,0,4]
```

扫描过程：

- 在下标 `0`，最远到 `3`
- 在下标 `1`，最远还是到 `3`
- 在下标 `2`，最远还是到 `3`
- 在下标 `3`，因为 `nums[3] = 0`，最远仍然是 `3`

接下来来到：

```text
i = 4
```

但这时：

```text
4 > max_reach
```

说明下标 `4` 根本到不了，
因此返回 `False`。

## 算法步骤

1. 初始化 `max_reach = 0`
2. 从左到右遍历数组下标 `i`
3. 如果 `i > max_reach`，说明当前位置不可达，直接返回 `False`
4. 否则更新最远可达位置：`max_reach = max(max_reach, i + nums[i])`
5. 如果 `max_reach >= len(nums) - 1`，说明终点已可达，直接返回 `True`
6. 遍历结束后仍未失败，返回 `True`

## Python 参考实现

```python
def canJump(nums):
    max_reach = 0

    for i in range(len(nums)):
        if i > max_reach:
            return False

        max_reach = max(max_reach, i + nums[i])

        if max_reach >= len(nums) - 1:
            return True

    return True
```

## 为什么最后还能 `return True`

因为如果整个遍历过程中都没有出现：

```text
i > max_reach
```

说明数组里的每一个被访问到的位置都在可达范围内。

而只要我们能一路顺利遍历到最后，
就说明最后一个位置没有被“卡住”，
因此答案就是 `True`。

另外，这里的提前返回：

```python
if max_reach >= len(nums) - 1:
    return True
```

只是一个优化。

即使删掉这两行，
最后保留结尾的：

```python
return True
```

逻辑上仍然是对的。

## 复杂度分析

### 时间复杂度

```text
O(n)
```

只需要从左到右遍历数组一次。

### 空间复杂度

```text
O(1)
```

只使用了一个额外变量 `max_reach`。

## 常见错误

### 1. 误以为必须找到具体跳法

这道题只问能不能到，
不要求输出路径。

所以重点不是“怎么跳”，
而是“最远能扩展到哪里”。

### 2. 把它写成动态规划或回溯但没有必要

当然也能做，
但这道题有更直接的贪心解法，
时间和空间都更优。

### 3. 不理解 `i > max_reach` 的含义

这不是在比较数值大小本身，
而是在判断：

- 当前下标 `i`
- 是否落在我们目前能到达的最远范围之外

如果已经超出这个范围，
说明当前位置根本无法落脚，
自然也不可能继续往后跳。

## 一句话总结

这道题的关键就是：

**一边遍历数组，一边维护当前能到达的最远位置 `max_reach`；如果当前位置已经超过这个最远边界，就说明走不下去了，否则不断更新边界，直到覆盖最后一个下标。**
