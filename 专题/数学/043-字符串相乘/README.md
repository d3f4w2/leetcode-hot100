# 043. 字符串相乘

## 所属专题

- 数学

## 题目描述

给定两个以字符串形式表示的非负整数 `num1` 和 `num2`，返回它们的乘积，结果也要以字符串形式表示。

注意：

- 不能使用任何内置的 `BigInteger` 库
- 不能直接把整个输入转换为整数再相乘

## 示例

### 示例 1

```text
输入：num1 = "2", num2 = "3"
输出："6"
```

### 示例 2

```text
输入：num1 = "123", num2 = "456"
输出："56088"
```

## 题意理解

这道题的重点不在于“会不会乘法”，
而在于：

- 输入是字符串
- 输出也必须是字符串
- 题目明确禁止把整个字符串直接转成整数

所以我们不能写成：

```python
return str(int(num1) * int(num2))
```

题目真正想考的是：

**如何只依赖字符串中的每一位数字，模拟我们平时手算乘法的过程。**

另外还要先想清楚一个结论：

- 如果 `num1` 有 `m` 位
- `num2` 有 `n` 位
- 那么乘积最多只有 `m + n` 位

例如：

```text
99 × 99 = 9801
```

两个两位数相乘，结果最多四位。

所以我们完全可以先准备一个长度为 `m + n` 的数组，专门用来存结果。

## 最直接的想法：先转整数再乘，但题目不允许

最自然的想法当然是：

1. 把 `num1` 转成整数
2. 把 `num2` 转成整数
3. 直接相乘
4. 再转回字符串

但这正是题目禁止的事情。

如果严格遵守题意，另一个朴素想法是：

- 把乘法看成很多次加法
- 比如用 `num2` 的每一位去和 `num1` 做“重复累加”
- 最后再把所有部分和加起来

这个思路理论上也能做，
但实现会很绕，而且如果真按“加一次算一次”去模拟，效率会比较差。

所以更好的做法是：

**直接模拟竖式乘法。**

## 优化思路：模拟竖式乘法

这题最经典、也最值得掌握的解法，就是把小学的竖式乘法搬到代码里。

### 第一步：先想清楚结果数组为什么开 `m + n`

设：

- `num1` 长度是 `m`
- `num2` 长度是 `n`

那么结果最多有 `m + n` 位。

比如：

- `9 × 9 = 81`，一位数乘一位数，最多两位
- `99 × 99 = 9801`，两位数乘两位数，最多四位
- `999 × 999 = 998001`，三位数乘三位数，最多六位

因此我们可以直接写：

```python
result = [0] * (m + n)
```

数组里的每个位置先放 `0`，
后面再把每一位乘积慢慢累加进去。

### 第二步：每一对数字相乘，应该放到哪里

这是这道题最核心的地方。

假设：

- 当前处理的是 `num1[i]`
- 当前处理的是 `num2[j]`

它们分别代表：

```text
num1[i] × 10^(m - 1 - i)
num2[j] × 10^(n - 1 - j)
```

那么这两个数字相乘后，对应的权重就是：

```text
10^[(m - 1 - i) + (n - 1 - j)]
```

而我们结果数组长度是 `m + n`，
数组下标从左到右是 `0 ~ m + n - 1`。

最后可以得到一个非常重要的结论：

- 当前乘积的个位应该落在 `i + j + 1`
- 当前乘积的进位应该落在 `i + j`

也就是：

```python
p1 = i + j
p2 = i + j + 1
```

其中：

- `p2` 存当前位置的个位
- `p1` 存往前一位的进位

这和手算竖式的规律完全一致。

### 第三步：为什么要先加上 `result[p2]`

很多人第一次写时会忘掉这一点。

原因是：

- 不同位置的乘积，可能会落到同一个结果位置
- 所以这个位置上本来就可能已经有值了

比如在计算过程中，
某一次乘法也许要把结果放到 `result[4]`，
而前一次计算已经往 `result[4]` 里放过数字了。

因此不能只写：

```python
total = mul
```

而必须写：

```python
total = mul + result[p2]
```

意思是：

- 先取出这个位置之前已经累积的值
- 再加上当前这次乘出来的值
- 一起处理进位

### 第四步：为什么进位要写成 `+=`

更新时通常写成：

```python
result[p2] = total % 10
result[p1] += total // 10
```

这里第二行为什么不是 `=`，而是 `+=`？

因为：

- `p1` 这个位置也可能已经被别的乘积贡献过进位
- 当前这次只是“再补一个进位”进去

所以必须累加，不能直接覆盖。

### 第五步：最后为什么还要去掉前导零

因为我们一开始固定开了 `m + n` 个位置，
最高位不一定真的会被用到。

例如：

```text
2 × 3 = 6
```

结果数组可能会是：

```text
[0, 6]
```

前面的 `0` 只是占位，
最后拼接成字符串之前要把这些前导零跳过去。

## 为什么这样写是对的

这套写法本质上是在做两件事：

1. 把每一对数字的乘积，放到它在十进制里应该出现的位置
2. 把所有落到同一位置的贡献正确累加起来，并及时处理进位

为什么它一定正确？

### 1. 每一对数字都被处理到了

双重循环会遍历：

- `num1` 的每一位
- `num2` 的每一位

所以所有可能的“位与位相乘”都不会漏掉。

### 2. 每次相乘都放到了正确的十进制位置

如果当前处理的是 `num1[i]` 和 `num2[j]`，
那么它们的乘积对应的就是：

- 个位放在 `i + j + 1`
- 进位放在 `i + j`

这正好对应手算竖式里“当前这一列”和“它左边那一列”。

### 3. 同一位置的贡献会被正确累加

因为我们不是直接覆盖 `result[p2]`，
而是先把旧值加进来：

```python
total = mul + result[p2]
```

所以所有落在同一列上的结果都会被累计起来。

### 4. 进位也不会丢

`total // 10` 会被加到前一位 `result[p1]`，
这就和竖式里的“向左进一位”完全一致。

因此当所有乘积都处理完之后，
整个 `result` 数组就是最终乘积的十进制展开。

## 算法步骤

1. 如果 `num1` 或 `num2` 有一个是 `"0"`，直接返回 `"0"`
2. 设 `m = len(num1)`，`n = len(num2)`
3. 创建长度为 `m + n` 的数组 `result`，初始都为 `0`
4. 从右到左遍历 `num1` 的每一位
5. 对于 `num1` 的每一位，再从右到左遍历 `num2` 的每一位
6. 计算当前两位乘积 `mul`
7. 令 `p1 = i + j`，`p2 = i + j + 1`
8. 令 `total = mul + result[p2]`
9. 更新 `result[p2] = total % 10`
10. 更新 `result[p1] += total // 10`
11. 循环结束后，跳过 `result` 前面的前导零
12. 把剩余数字拼接成字符串并返回

## 复杂度分析

### 时间复杂度

`O(m × n)`

原因：

- `num1` 的每一位都要和 `num2` 的每一位相乘一次
- 一共会做 `m × n` 次基础计算

### 空间复杂度

`O(m + n)`

原因：

- 额外使用了一个长度为 `m + n` 的结果数组

## Python 参考实现（详细注释）

```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        # 只要有一个数是 0，乘积就一定是 0。
        if num1 == "0" or num2 == "0":
            return "0"

        m, n = len(num1), len(num2)

        # m 位数乘 n 位数，结果最多有 m + n 位。
        result = [0] * (m + n)

        # 从右往左遍历，模拟手算乘法时“先算低位”的过程。
        for i in range(m - 1, -1, -1):
            digit1 = int(num1[i])

            for j in range(n - 1, -1, -1):
                digit2 = int(num2[j])

                # 当前两位数字相乘。
                mul = digit1 * digit2

                # 当前乘积的个位应该放在 p2，
                # 进位应该加到 p1。
                p1 = i + j
                p2 = i + j + 1

                # 这个位置上之前可能已经累加过别的乘积，
                # 所以要把旧值一起算进去。
                total = mul + result[p2]

                # total 的个位留在当前位置。
                result[p2] = total % 10

                # total 的十位及更高位向前进位。
                # 这里必须用 +=，因为前一位也可能已经有别的进位。
                result[p1] += total // 10

        # 固定长度数组前面可能会有前导 0，
        # 比如 2 * 3 的结果数组会是 [0, 6]。
        start = 0
        while start < len(result) and result[start] == 0:
            start += 1

        # 把数字数组重新拼成字符串。
        return "".join(str(digit) for digit in result[start:])
```

## 这段代码最值得记住的地方

你真正要记住的核心只有这几句：

```python
p1 = i + j
p2 = i + j + 1
total = int(num1[i]) * int(num2[j]) + result[p2]
result[p2] = total % 10
result[p1] += total // 10
```

本质上就是一句话：

**每次把两位数相乘得到的结果，按照竖式规则放到正确的位置，个位留在当前列，进位加到前一列。**

## 常见错误

### 1. 直接把整个字符串转成整数

比如直接写：

```python
int(num1) * int(num2)
```

这虽然能得到答案，
但不符合题目要求。

### 2. 把位置写错成别的下标

最容易错的就是：

- `p1 = i + j`
- `p2 = i + j + 1`

如果这里写错一位，
整个结果都会乱掉。

### 3. 忘了把旧的 `result[p2]` 加进去

错误写法像这样：

```python
total = mul
```

这样会把同一列之前累积的值覆盖掉。

正确写法必须是：

```python
total = mul + result[p2]
```

### 4. 进位时写成 `=`

错误写法：

```python
result[p1] = total // 10
```

这样会覆盖前面已经存在的进位信息。

正确写法应该是：

```python
result[p1] += total // 10
```

### 5. 忘记处理 `"0"` 或前导零

如果不提前处理：

```text
num1 = "0" 或 num2 = "0"
```

可能会让后面的逻辑变得啰嗦。

另外，最终拼接字符串前，
也要记得跳过结果数组前面的前导零。

## 适合自己默写的精简版本

```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"

        m, n = len(num1), len(num2)
        result = [0] * (m + n)

        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                mul = int(num1[i]) * int(num2[j])
                p1, p2 = i + j, i + j + 1
                total = mul + result[p2]
                result[p2] = total % 10
                result[p1] += total // 10

        start = 0
        while start < len(result) and result[start] == 0:
            start += 1

        return "".join(str(digit) for digit in result[start:])
```

## 一句话总结

这道题的关键是：

**不要把整个字符串转成整数，而是用一个长度为 `m + n` 的数组，按竖式乘法把每一位乘积放到正确位置，并同步处理进位。**
