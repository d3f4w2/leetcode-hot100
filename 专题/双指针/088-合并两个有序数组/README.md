# 088. 合并两个有序数组

## 所属专题
- 双指针

## 题目描述

给你两个按 **非递减顺序** 排列的整数数组 `nums1` 和 `nums2`，另有两个整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中元素的数目。

请你 **合并 `nums2` 到 `nums1` 中**，使合并后的数组同样按 **非递减顺序** 排列。

注意：

- 最终结果不需要返回
- 而是要直接存储在 `nums1` 中
- `nums1` 的长度是 `m + n`
- 其中前 `m` 个位置是有效元素
- 后 `n` 个位置是预留出来的空位，可以忽略原本的值

## 示例

### 示例 1

```text
输入：nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3
输出：[1,2,2,3,5,6]
解释：需要合并 [1,2,3] 和 [2,5,6]。
合并结果是 [1,2,2,3,5,6]。
```

### 示例 2

```text
输入：nums1 = [1], m = 1, nums2 = [], n = 0
输出：[1]
```

### 示例 3

```text
输入：nums1 = [0], m = 0, nums2 = [1], n = 1
输出：[1]
```

## 题意理解

这道题看起来像“把两个有序数组合成一个新数组”，
但真正的要求其实是：

- 不能额外返回一个新数组作为答案
- 必须把结果直接写回 `nums1`
- `nums1` 后面已经给你留好了足够空间

也就是说，题目的重点不只是“合并有序数组”，
而是：

**如何在原地把 `nums2` 合并进 `nums1`。**

需要特别注意：

- `nums1` 的有效部分只有前 `m` 个元素
- 后面的 `0` 只是占位，不是有效数据
- `nums2` 的有效部分是前 `n` 个元素

比如：

- `nums1 = [1,2,3,0,0,0]`，真正有效的是 `[1,2,3]`
- `nums2 = [2,5,6]`
- 要把它们合并后写回 `nums1`

## 最直接的想法：新开一个数组

最容易想到的方法是：

- 用两个指针分别遍历 `nums1` 的有效部分和 `nums2`
- 谁小就先放进一个新的数组里
- 等合并完后，再把结果拷贝回 `nums1`

这样当然能做出来，
而且时间复杂度也是 `O(m + n)`。

但问题在于：

- 额外使用了一个新数组
- 空间复杂度会变成 `O(m + n)`

而这道题更希望我们利用 `nums1` 后面已经预留好的空间，直接原地完成。

## 优化思路：双指针从后往前合并

### 为什么要从后往前

这是这道题最关键的地方。

如果你尝试从前往后放元素，会遇到一个问题：

- `nums1` 前面的有效元素还没处理完
- 你一旦直接覆盖前面的内容，就可能把后面还要比较的数据弄丢

比如：

- `nums1 = [1,2,3,0,0,0]`
- `nums2 = [2,5,6]`

如果从前往后写：

- 你可能很快就会覆盖掉 `nums1` 原本的 `2`、`3`
- 后面还没来得及比较，就把有用信息破坏了

但如果从后往前写，就完全没有这个问题：

- `nums1` 最右边本来就是空位
- 每次把当前较大的数放到最后面
- 不会影响前面还没处理的有效数据

### 三个指针分别表示什么

我们定义三个指针：

- `i`：指向 `nums1` 有效部分的最后一个元素，也就是 `m - 1`
- `j`：指向 `nums2` 的最后一个元素，也就是 `n - 1`
- `k`：指向合并后应该填入的位置，也就是 `m + n - 1`

也就是说：

- `i` 负责看 `nums1` 里还没处理的最大值
- `j` 负责看 `nums2` 里还没处理的最大值
- `k` 负责把更大的那个放到最终位置上

### 每一步怎么做

在 `i >= 0` 且 `j >= 0` 时：

- 比较 `nums1[i]` 和 `nums2[j]`
- 谁更大，就把谁放到 `nums1[k]`
- 然后移动对应的指针
- 同时让 `k` 左移一位

因为我们每次都在放“当前剩余元素里最大的那个”，
所以从后往前填，结果自然就是有序的。

### 为什么最后只需要处理 `nums2` 的剩余部分

主循环结束后，有两种可能：

#### 情况 1：`nums2` 还有剩余

这时说明：

- `nums2` 里还有一些更小的数没放进去
- 它们必须继续复制到 `nums1` 前面

所以需要一个循环：

```python
while j >= 0:
    nums1[k] = nums2[j]
    j -= 1
    k -= 1
```

#### 情况 2：`nums1` 还有剩余

这时不需要额外处理。

因为：

- `nums1` 剩下的这些元素本来就在正确的位置上
- 它们本来就位于数组前面
- 不用再移动一次

这一步非常容易被忽略，但其实正是这道题的小技巧之一。

## 用示例手推一遍

以示例 1 为例：

```text
nums1 = [1,2,3,0,0,0], m = 3
nums2 = [2,5,6], n = 3
```

初始时：

- `i = 2`，指向 `3`
- `j = 2`，指向 `6`
- `k = 5`，指向最后一个位置

### 第 1 步

- 比较 `3` 和 `6`
- `6` 更大
- 放到 `nums1[5]`

此时：

```text
nums1 = [1,2,3,0,0,6]
```

然后：

- `j -= 1`
- `k -= 1`

### 第 2 步

- 比较 `3` 和 `5`
- `5` 更大
- 放到 `nums1[4]`

此时：

```text
nums1 = [1,2,3,0,5,6]
```

### 第 3 步

- 比较 `3` 和 `2`
- `3` 更大
- 放到 `nums1[3]`

此时：

```text
nums1 = [1,2,3,3,5,6]
```

### 第 4 步

- 比较 `2` 和 `2`
- 谁放都可以
- 按这份代码写法，会优先放 `nums2[j]`
- 把 `2` 放到 `nums1[2]`

此时：

```text
nums1 = [1,2,2,3,5,6]
```

然后 `nums2` 已经处理完，循环结束。

最终结果就是：

```text
[1,2,2,3,5,6]
```

## 为什么这样写

### 1. 从后往前可以避免覆盖 `nums1` 里还没处理的数据

这是整道题最关键的原因。

- 后面的位置本来就是空的
- 把大元素先放到后面，不会破坏前面的有效部分

### 2. 每次放当前两边较大的那个，才能保证末尾有序

因为 `k` 是从后往前走的，
所以我们必须把“当前剩余部分的最大值”放过去。

### 3. 这道题虽然叫“双指针”，但通常会写成三个下标

本质上依然是双指针思想：

- 一个指针看 `nums1`
- 一个指针看 `nums2`

只是额外用一个 `k` 表示写入位置。

### 4. `nums1` 剩余时不用处理，`nums2` 剩余时必须处理

- `nums1` 剩余：说明它们已经在正确位置
- `nums2` 剩余：说明还没真正写入 `nums1`

这一点是很多人第一次做时最容易写错的地方。

## 算法步骤

1. 定义三个指针 `i`、`j`、`k`
2. `i` 指向 `nums1` 有效部分末尾
3. `j` 指向 `nums2` 末尾
4. `k` 指向 `nums1` 最末尾
5. 比较 `nums1[i]` 和 `nums2[j]`
6. 将较大值放到 `nums1[k]`
7. 移动对应指针，并让 `k` 左移
8. 主循环结束后，如果 `nums2` 还有剩余，继续复制到 `nums1`

## 复杂度分析

### 时间复杂度

`O(m + n)`

原因是：

- 两个数组中的元素最多各比较、移动一次
- 整个过程只会线性扫描一遍

### 空间复杂度

`O(1)`

原因是：

- 只使用了几个额外指针变量
- 没有开辟新的与输入规模相关的数组

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i = m - 1
        j = n - 1
        k = m + n - 1

        while i >= 0 and j >= 0:
            if nums1[i] > nums2[j]:
                nums1[k] = nums1[i]
                i -= 1
            else:
                nums1[k] = nums2[j]
                j -= 1
            k -= 1

        while j >= 0:
            nums1[k] = nums2[j]
            j -= 1
            k -= 1
```

## 这段代码最值得记住的地方

最核心的是这几行：

```python
i = m - 1
j = n - 1
k = m + n - 1
```

它们直接决定了整个解法的方向：

- 不从前面填
- 而是从最后一个位置开始填

再加上这一段：

```python
while i >= 0 and j >= 0:
    if nums1[i] > nums2[j]:
        nums1[k] = nums1[i]
        i -= 1
    else:
        nums1[k] = nums2[j]
        j -= 1
    k -= 1
```

就把“从后往前合并两个有序数组”的核心逻辑完整表达出来了。

## 常见错误

### 1. 从前往后直接覆盖 `nums1`

这样很容易把 `nums1` 里原本还没处理的有效元素覆盖掉。

### 2. 把 `nums1` 后面的 `0` 当成有效元素参与比较

题目里已经说明：

- `nums1` 只有前 `m` 个元素有效
- 后面的 `0` 只是占位

所以 `i` 必须从 `m - 1` 开始，不能从 `len(nums1) - 1` 开始。

### 3. 主循环结束后忘记处理 `nums2` 的剩余部分

例如：

- `nums1 = [0]`, `m = 0`
- `nums2 = [1]`, `n = 1`

如果漏掉这一步，答案就错了。

### 4. 误以为 `nums1` 剩余部分也要再复制一遍

其实不需要。

因为 `nums1` 剩下的元素本来就已经在正确的位置上。

```python
        while i >= 0 and j >= 0:
            if nums1[i] > nums2[j]:

                i -= 1
            else:
                nums1[k] = nums2[j]
                j -= 1
            k -= 1

        while j >= 0:
            nums1[k] = nums2[j]
            j -= 1
            k -= 1
```

## 一句话总结

这道题的关键不是“怎么合并”，而是：

**利用 `nums1` 尾部的空位，从后往前比较并填入较大的元素，这样就能原地完成两个有序数组的合并。**
