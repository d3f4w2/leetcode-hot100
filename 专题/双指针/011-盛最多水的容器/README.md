# 011. 盛最多水的容器

## 所属专题

- 双指针

## 题目描述

给定一个长度为 `n` 的整数数组 `height`。

有 `n` 条垂线，第 `i` 条线的两个端点分别是：

- `(i, 0)`
- `(i, height[i])`

请你找出其中的两条线，使得它们与 `x` 轴共同构成的容器可以容纳最多的水。

返回这个容器可以储存的最大水量。

说明：

- 你不能倾斜容器

## 示例

### 示例 1

```text
输入：height = [1,8,6,2,5,4,8,3,7]
输出：49
解释：
选择下标 1 和下标 8 这两条线。
它们的高度分别是 8 和 7，宽度是 8 - 1 = 7。
容器能装的水量由较短的一边决定，所以面积是 7 × 7 = 49。
```

### 示例 2

```text
输入：height = [1,1]
输出：1
```

## 题意理解

这道题表面上是在说“装水”，但本质上是在让我们从数组里选两个位置：

- 一个左边界
- 一个右边界

设它们的下标分别是 `left` 和 `right`，那么它们能形成的容器容量就是：

```text
min(height[left], height[right]) * (right - left)
```

为什么是这个公式？

- `right - left` 表示容器的宽度
- `height[left]` 和 `height[right]` 表示左右两边的高度
- 真正能装多少水，不取决于更高的那一边，而取决于更矮的那一边

所以这道题其实就是：

**在所有下标对 `(i, j)` 中，找到让 `min(height[i], height[j]) * (j - i)` 最大的那一对。**

## 最直接的想法：暴力枚举

最容易想到的方法，就是枚举所有两条线的组合。

具体做法：

- 第一层循环枚举左边界
- 第二层循环枚举右边界
- 对每一对位置都计算一次容量
- 用一个变量记录最大值

这个方法一定能做出来。

但是问题也很明显：

- 一共有大约 `n^2 / 2` 对组合
- 每一对都要算一次面积

所以时间复杂度是 `O(n^2)`。

当数组比较长时，这种方法效率不够好。

于是我们要继续想：

**能不能在不枚举所有组合的前提下，快速排除掉一大批“不可能更优”的情况？**

## 优化思路：双指针

这是这道题最经典、也最重要的做法。

### 第一步：左右指针从两端出发

我们先让：

- `left = 0`
- `right = len(height) - 1`

也就是先看最左边和最右边这两条线。

这样做的原因是：

- 它们之间的宽度最大

虽然高度不一定最好，但宽度已经是极限了。

### 第二步：计算当前容量

当前容量是：

```text
area = min(height[left], height[right]) * (right - left)
```

然后用一个变量 `best` 去维护目前见过的最大值。

### 第三步：移动较短的那一边

这一步是全题最核心的地方。

假设当前：

- `height[left] < height[right]`

那么当前容器的高度上限，其实是由 `height[left]` 决定的。

这时如果你去移动右指针，会发生什么？

- 宽度一定变小
- 决定高度上限的短板 `height[left]` 还没变

那新的面积几乎没有变大的希望。

所以真正有意义的做法是：

- 移动较短的那一边

因为只有这样，才有可能遇到一个更高的短板，从而弥补宽度缩小带来的损失。

同理：

- 如果 `height[right] <= height[left]`
- 就移动 `right`

### 为什么“移动短板”是对的

假设当前左右高度分别是：

- 左边 `a`
- 右边 `b`

并且 `a <= b`。

那么当前面积是：

```text
a * (right - left)
```

如果此时我们不动左边，只移动右边：

- 新宽度会变小
- 新高度最多仍然只能由 `a` 限制，甚至可能更小

所以新面积一定不会比当前更优。

也就是说：

**当左边是短板时，保留左边、只移动右边，没有意义。**

因此可以放心丢掉当前左边，去尝试新的位置。

这就是双指针能成立的关键原因。

## 用示例手推一遍

以示例 1 为例：

```text
height = [1,8,6,2,5,4,8,3,7]
```

### 第 1 步

- `left = 0`，高度 `1`
- `right = 8`，高度 `7`
- 宽度：`8`
- 面积：`min(1, 7) * 8 = 8`

当前最大值：

```text
best = 8
```

因为左边更短，所以移动 `left`。

### 第 2 步

- `left = 1`，高度 `8`
- `right = 8`，高度 `7`
- 宽度：`7`
- 面积：`min(8, 7) * 7 = 49`

更新最大值：

```text
best = 49
```

因为右边更短，所以移动 `right`。

### 第 3 步

- `left = 1`，高度 `8`
- `right = 7`，高度 `3`
- 宽度：`6`
- 面积：`min(8, 3) * 6 = 18`

没有超过 `49`。

因为右边更短，继续移动 `right`。

### 第 4 步

- `left = 1`，高度 `8`
- `right = 6`，高度 `8`
- 宽度：`5`
- 面积：`min(8, 8) * 5 = 40`

仍然没有超过 `49`。

继续按照短板移动指针，最后会发现最大值始终是：

```text
49
```

也就是由下标 `1` 和下标 `8` 这两条线构成的容器。

## 为什么这样写

这道题的关键并不是“双指针”这三个字本身，而是你要真正理解：

### 1. 面积由“短板 × 宽度”决定

不是谁高就听谁的，而是：

- 高度取较小值
- 宽度取下标差

所以你每次都在权衡两件事：

- 指针移动后，宽度会变小
- 但短板有机会变高

### 2. 宽度每次都会减少，所以只能寄希望于短板变高

一旦移动任意一个指针，`right - left` 一定变小。

既然宽度不可能变大，那如果还想让面积变大，就只能期待：

- `min(height[left], height[right])` 变大

而这只有在移动短板时才有可能发生。

### 3. 移动长板没有意义

如果当前是左低右高：

- 左边决定了当前高度上限
- 你去动右边，只会让宽度减少
- 但左边这个限制还在

所以没有必要。

### 4. 这不是在“瞎试”，而是在“有依据地剪枝”

双指针之所以高效，不是因为它试得快，而是因为它每次都能排除掉一类不可能更优的情况。

这就是为什么它能从 `O(n^2)` 优化到 `O(n)`。

## 算法步骤

1. 初始化两个指针：`left = 0`，`right = len(height) - 1`
2. 初始化答案 `best = 0`
3. 当 `left < right` 时循环：
   - 计算当前宽度 `right - left`
   - 计算当前高度 `min(height[left], height[right])`
   - 更新最大面积 `best`
   - 如果左边更短，`left += 1`
   - 否则，`right -= 1`
4. 当两个指针相遇时，循环结束
5. 返回 `best`

## 复杂度分析

### 时间复杂度

`O(n)`

原因：

- 两个指针从两端向中间移动
- 每一步至少有一个指针向中间靠近
- 整个过程最多遍历数组一遍

### 空间复杂度

`O(1)`

原因：

- 只使用了几个额外变量
- 没有使用额外与输入规模相关的存储空间

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def maxArea(self, height: List[int]) -> int:
        # 左指针从最左边开始，右指针从最右边开始。
        left = 0
        right = len(height) - 1

        # best 用来记录目前见过的最大容量。
        best = 0

        # 当 left 和 right 还没有相遇时，
        # 就说明还能继续形成容器。
        while left < right:
            # 当前容器的宽度，就是两个下标的差。
            width = right - left

            # 当前容器的有效高度，取决于较短的那一边。
            current_height = min(height[left], height[right])

            # 当前这对边界形成的容量。
            area = current_height * width

            # 用它来更新全局最大值。
            best = max(best, area)

            # 谁更短，就移动谁。
            # 因为移动更高的一边，只会让宽度变小，
            # 却不能突破当前短板带来的高度限制。
            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return best
```

## 这段代码最值得记住的地方

你在自己手写的时候，重点记住下面这条主线：

```python
left, right = 0, len(height) - 1
best = 0

while left < right:
    area = min(height[left], height[right]) * (right - left)
    best = max(best, area)

    if height[left] < height[right]:
        left += 1
    else:
        right -= 1
```

本质上就是一句话：

**每次先算当前面积，再丢掉较短的那一边，因为只有换掉短板，才有可能得到更大的面积。**

## 常见错误

### 1. 用较高的那一边作为高度

容器真正能装多少水，取决于较短的一边。

所以必须写：

```python
min(height[left], height[right])
```

而不是：

```python
max(height[left], height[right])
```

### 2. 移动了较高的那一边

这会破坏这道题最核心的剪枝逻辑。

正确规则是：

- 谁短，移动谁

### 3. 宽度写错

宽度是两个下标之间的距离：

```python
right - left
```

不是元素个数，也不是：

```python
right - left + 1
```

### 4. 先移动指针，再计算面积

推荐固定顺序：

- 先计算当前这对边界的面积
- 再根据短板移动指针

否则很容易漏掉当前这一组答案。

```python
from typing import List


class Solution:
    def maxArea(self, height: List[int]) -> int:
        left, right = 0, len(height) - 1
        best = 0

```

## 一句话总结

这道题的关键不是“把所有组合都试一遍”，而是：

**用双指针从两端向中间收缩，每次保留更高的那一边、移动较短的那一边，因为面积的瓶颈始终是短板。**
