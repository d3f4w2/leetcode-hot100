# 344. 反转字符串

## 所属专题
- 双指针

## 题目描述

编写一个函数，其作用是将输入的字符串反转过来。输入字符串以字符数组 `s` 的形式给出。

不要给另外的数组分配额外的空间，你必须原地修改输入数组，并使用 `O(1)` 的额外空间解决这一问题。

## 示例

### 示例 1

```text
输入：s = ["h","e","l","l","o"]
输出：["o","l","l","e","h"]
```

### 示例 2

```text
输入：s = ["H","a","n","n","a","h"]
输出：["h","a","n","n","a","H"]
```

### 示例 3

```text
输入：s = ["a"]
输出：["a"]
```

## 题意理解

这道题看起来很简单，但题目里其实强调了两个重点：

- 输入不是普通字符串，而是字符数组 `s`
- 必须原地修改，不能新开一个同样大小的数组

也就是说，这道题不是让我们：

- 返回一个新的反转结果

而是要直接把原数组改成反过来的样子。

比如：

- 原数组是 `["h","e","l","l","o"]`
- 反转后应该直接变成 `["o","l","l","e","h"]`

最关键的一点是：

**左右两端的字符交换位置后，数组就会逐渐变成反转后的结果。**

## 最直接的想法：新开数组或直接切片

最容易想到的方法有两种：

- 新建一个数组，从后往前把字符放进去
- 直接写成 `s[::-1]`

这样当然能得到反转后的内容，
但它们都有问题。

### 问题 1：不符合原地修改要求

如果新开数组，
空间复杂度就变成了 `O(n)`，
不满足题目要求的 `O(1)` 额外空间。

### 问题 2：很多写法并没有真正修改原数组

比如你写：

```python
s = s[::-1]
```

这只是让局部变量 `s` 指向了一个新的列表，
并没有按题目要求“原地修改传入的字符数组”。

所以我们需要一种：

- 不额外开数组
- 直接在原数组里完成反转

的做法。

## 优化思路：双指针

### 核心想法

反转数组时，最左边的字符应该和最右边的字符交换：

- 第 `0` 个和最后一个交换
- 第 `1` 个和倒数第二个交换
- 第 `2` 个和倒数第三个交换

也就是说，我们每次都在处理一对“对称位置”的字符。

这就很适合用双指针：

- `left` 指向数组左端
- `right` 指向数组右端

每次交换：

```python
s[left], s[right] = s[right], s[left]
```

然后让：

- `left += 1`
- `right -= 1`

不断向中间靠拢。

### 什么时候停止

当 `left >= right` 时，说明：

- 偶数长度数组：所有成对位置都交换完了
- 奇数长度数组：中间那个字符不需要动

所以循环条件写成：

```python
while left < right:
```

就刚刚好。

## 用示例手推一遍

以：

```text
s = ["h","e","l","l","o"]
```

为例。

初始时：

- `left = 0`，指向 `"h"`
- `right = 4`，指向 `"o"`

### 第 1 步

交换 `s[0]` 和 `s[4]`：

```text
["o","e","l","l","h"]
```

然后：

- `left = 1`
- `right = 3`

### 第 2 步

交换 `s[1]` 和 `s[3]`：

```text
["o","l","l","e","h"]
```

然后：

- `left = 2`
- `right = 2`

### 第 3 步

此时 `left` 已经不小于 `right`，
说明中间位置已经不需要再处理了。

最终结果就是：

```text
["o","l","l","e","h"]
```

## 为什么这样写

### 1. 左右两端互换，正好符合“反转”的本质

反转不是重新排列很多次，
而是把对称位置的元素交换。

例如：

- 最左边的字符最终一定去最右边
- 最右边的字符最终一定去最左边

所以直接交换最自然。

### 2. 每次交换后，两端都已经处理完了

一旦 `s[left]` 和 `s[right]` 完成交换：

- `left` 位置已经是最终答案
- `right` 位置也已经是最终答案

所以两个指针都可以向中间移动。

### 3. 不需要额外空间

整个过程中只用了两个变量：

- `left`
- `right`

所以额外空间是 `O(1)`。

### 4. 奇数和偶数长度都能统一处理

如果数组长度是奇数：

- 中间那个字符不需要交换

如果数组长度是偶数：

- 最后会正好全部成对处理完

`while left < right` 这个条件可以统一覆盖这两种情况。

## 算法步骤

1. 定义左指针 `left = 0`
2. 定义右指针 `right = len(s) - 1`
3. 当 `left < right` 时，交换 `s[left]` 和 `s[right]`
4. 然后让 `left += 1`，`right -= 1`
5. 循环结束后，数组已经被原地反转

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 两个指针从两端向中间移动
- 每个字符最多参与一次交换

### 空间复杂度

`O(1)`

原因是：

- 只使用了常数个额外变量
- 没有额外创建新数组

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def reverseString(self, s: List[str]) -> None:
        # left 指向左边待交换的位置
        left = 0
        # right 指向右边待交换的位置
        right = len(s) - 1

        # 当 left 和 right 还没有相遇时，
        # 说明还有成对的字符需要交换
        while left < right:
            # 交换左右两个位置的字符
            s[left], s[right] = s[right], s[left]

            # 交换完成后，左右指针向中间靠拢
            left += 1
            right -= 1
```

## 这段代码最值得记住的地方

最核心的就是这几行：

```python
left, right = 0, len(s) - 1

while left < right:
    s[left], s[right] = s[right], s[left]
    left += 1
    right -= 1
```

你可以把它理解成一句话：

**每次交换最左边和最右边，然后一起向中间收缩。**

这是一类非常经典的双指针写法。

## 常见错误

### 1. 返回一个新数组，而不是原地修改

这道题要求的是：

- 直接修改传入的 `s`

不是：

- 返回一个新的反转数组

所以像下面这种思路就不符合题意：

```python
return s[::-1]
```

### 2. 写成 `s = s[::-1]`

这也是很常见的错误。

它只是让变量 `s` 重新指向一个新列表，
不一定算真正按题意修改原数组。

### 3. 循环条件写错

正确写法是：

```python
while left < right:
```

如果你把边界处理写乱了，
就可能导致：

- 少交换一次
- 或者多做无意义的交换

### 4. 忘记同时移动两个指针

每交换一次之后，都要写：

```python
left += 1
right -= 1
```

如果只移动一个指针，
逻辑就会出错，甚至可能进入死循环。

## 适合你自己再写一遍的版本

```python
from typing import List


class Solution:
    def reverseString(self, s: List[str]) -> None:
        left, right = 0, len(s) - 1

        while left < right:
            s[left], s[right] = s[right], s[left]
            left += 1
            right -= 1
```

## 一句话总结

这道题的关键就是：

**用双指针分别指向数组两端，不断交换并向中间收缩，从而在 `O(1)` 额外空间内原地完成反转。**
