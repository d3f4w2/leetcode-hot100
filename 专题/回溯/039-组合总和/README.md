# 039. 组合总和

## 所属专题

- 回溯

## 题目描述

给你一个**无重复元素**的整数数组 `candidates` 和一个目标整数 `target`，
找出 `candidates` 中所有可以使数字和为 `target` 的**不同组合**，
并以列表形式返回。

你可以按**任意顺序**返回这些组合。

题目还有两个非常重要的条件：

- `candidates` 中的每个数字都可以被**无限次重复使用**
- 如果至少一个数字的选取次数不同，那么两种组合就算不同

例如：

- `[2,2,3]` 和 `[7]` 是不同组合
- `[2,3,2]` 和 `[2,2,3]` 本质上是同一种组合，不应重复加入答案

## 示例

### 示例 1

```text
输入：candidates = [2,3,6,7], target = 7
输出：[[2,2,3],[7]]
```

解释：

- `2 + 2 + 3 = 7`
- `7 = 7`

仅有这两种组合。

### 示例 2

```text
输入：candidates = [2,3,5], target = 8
输出：[[2,2,2,2],[2,3,3],[3,5]]
```

### 示例 3

```text
输入：candidates = [2], target = 1
输出：[]
```

## 题意理解

这道题不是在问：

- 能不能凑出 `target`
- 也不是只要找到一种方案就结束

而是要求我们：

- 把所有能凑出 `target` 的组合都找出来
- 同时还要避免重复组合

例如：

```text
candidates = [2,3,6,7]
target = 7
```

我们可以这样想：

- 先尝试选 `2`
- 再继续尝试选 `2`
- 再尝试选 `3`

这就得到一个答案：

```text
[2,2,3]
```

同时也可以直接选：

```text
[7]
```

所以这题本质上是在做：

- 枚举所有可能的选法
- 只保留和为 `target` 的组合
- 并且保证同一组合不会因为顺序不同而重复出现

## 最直接的想法：每次尝试选一个数字

我们可以把整个过程看成：

- 当前已经选了一些数字，形成了一个组合 `path`
- 还剩下一部分和没有凑出来
- 接下来继续从 `candidates` 里选数字去补

每次都有若干种选择：

- 选 `2`
- 选 `3`
- 选 `6`
- 选 `7`

如果选完之后和还不够，
就继续往下选。

如果刚好凑满，
就得到一个答案。

如果已经超过了 `target`，
这条路就不可能再变成正确答案了，
应该立刻停止。

这种“尝试一个选择 -> 继续向下搜索 -> 走不通就返回换别的选择”的过程，
就是典型的回溯。

## 这道题里最关键的两个问题

### 1. 为什么可以重复使用同一个数字

题目明确说了：

- 同一个数字可以无限次使用

所以当我们这一步选择了 `2`，
下一步仍然可以继续选择 `2`。

这意味着递归进入下一层时，
不能直接跳到下一个位置，
而是应该允许当前数字继续被选。

### 2. 为什么不能出现重复组合

虽然数字可以重复使用，
但组合不能因为顺序不同而重复。

例如：

- `[2,2,3]`
- `[2,3,2]`
- `[3,2,2]`

这三个其实是同一种组合。

所以我们要想办法保证：

- 组合里的数字只按照固定顺序被选择

最常见的做法就是：

- 递归时传入一个 `start` 下标
- 下一层只能从当前下标及其后面继续选

这样就不会走回头路，
也就不会产生顺序不同但本质相同的重复组合。

## 为什么先排序

在回溯之前，
我们通常会先写：

```python
candidates.sort()
```

排序有两个好处。

### 1. 方便剪枝

如果当前数字已经大于“剩余要凑的值”，
那么后面更大的数字也一定不行，
可以直接 `break`。

例如当前还差：

```text
remain = 3
```

如果现在枚举到 `6`，
那后面的数只会更大，
这一层就没必要继续试了。

### 2. 组合顺序更稳定

排序后，
我们始终按从小到大的顺序去尝试数字，
更容易保证不会生成重复组合。

## 回溯函数怎么定义

我们可以定义：

```python
backtrack(start, path, current_sum)
```

它表示：

- 当前从下标 `start` 开始枚举候选数字
- `path` 是当前已经选出的组合
- `current_sum` 是当前组合的和

这个函数的目标就是：

- 从当前状态继续往下搜索
- 找到所有能让总和变成 `target` 的组合

## 回溯过程中怎么判断

### 1. 如果当前和等于 `target`

说明已经找到一个合法组合：

```python
if current_sum == target:
    result.append(path[:])
    return
```

这里要注意：

- 加入答案时要用 `path[:]` 复制一份

因为后面还会继续回溯修改 `path`。

### 2. 如果当前和超过 `target`

这一条路已经不可能成功了，
可以直接停止。

不过由于我们已经排好序，
通常会把这个判断写进循环里做剪枝：

```python
if current_sum + candidates[i] > target:
    break
```

### 3. 如果还没达到 `target`

就继续枚举后面的候选数字。

## 为什么递归时传 `i` 而不是 `i + 1`

这是这道题最关键的细节之一。

假设当前选中了：

```text
candidates[i] = 2
```

由于题目允许重复使用同一个数字，
所以下一层仍然应该可以继续选 `2`。

因此递归应该写成：

```python
backtrack(i, path, current_sum + candidates[i])
```

而不是：

```python
backtrack(i + 1, path, current_sum + candidates[i])
```

如果你写成 `i + 1`，
就意味着当前数字只能使用一次，
那就变成另一道题了。

## 用示例手推一遍

以：

```text
candidates = [2,3,6,7]
target = 7
```

为例。

先排序后仍然是：

```text
[2,3,6,7]
```

初始状态：

```text
path = []
current_sum = 0
start = 0
```

### 第一步：先尝试选 `2`

```text
path = [2]
current_sum = 2
```

因为还没到 `7`，
继续递归。

### 第二步：还可以继续选 `2`

因为同一个数字允许重复使用，
所以下一层依然可以从 `2` 开始选：

```text
path = [2,2]
current_sum = 4
```

### 第三步：继续尝试

先再选一个 `2`：

```text
path = [2,2,2]
current_sum = 6
```

这时再加 `2` 会超过 `7`，
所以这条分支不能继续。

然后回溯，
改为尝试 `3`：

```text
path = [2,2,3]
current_sum = 7
```

刚好凑满，
得到一个答案：

```text
[2,2,3]
```

### 第四步：继续回溯搜索其他分支

回到更上层后，
还会继续尝试：

- 从 `3` 开始
- 从 `6` 开始
- 从 `7` 开始

最终当选择：

```text
path = [7]
```

时，
也能得到另一个答案：

```text
[7]
```

所以最终结果是：

```text
[[2,2,3],[7]]
```

## 为什么这样不会重复

关键就在于：

- 我们每一层都从 `start` 开始往后枚举

这意味着一旦当前层已经选到某个位置，
后面递归时就不会再回头去选它前面的数字。

例如已经选了 `3` 之后，
下一层就不会再回去选 `2`，
因此像：

- `[2,2,3]`
- `[2,3,2]`
- `[3,2,2]`

这种只是顺序不同的重复情况就自然被避免了。

## 算法步骤

1. 对 `candidates` 排序
2. 定义结果数组 `result`
3. 定义回溯函数 `backtrack(start, path, current_sum)`
4. 如果 `current_sum == target`，把 `path` 的拷贝加入结果
5. 从下标 `start` 开始枚举每个候选数字
6. 如果当前数字会让和超过 `target`，直接 `break`
7. 把当前数字加入 `path`
8. 递归调用 `backtrack(i, path, current_sum + candidates[i])`
9. 递归返回后撤销选择
10. 最后返回所有结果

## Python 参考实现

```python
def combinationSum(candidates, target):
    result = []
    candidates.sort()

    def backtrack(start, path, current_sum):
        if current_sum == target:
            result.append(path[:])
            return

        for i in range(start, len(candidates)):
            if current_sum + candidates[i] > target:
                break

            path.append(candidates[i])
            backtrack(i, path, current_sum + candidates[i])
            path.pop()

    backtrack(0, [], 0)
    return result
```

## 为什么这样写是对的

因为整个搜索过程中，
我们始终满足下面几点：

- `path` 中的数字和始终等于 `current_sum`
- 每次递归只会继续选择当前下标及其后面的数字，所以不会产生重复组合
- 递归传入的是 `i`，所以当前数字可以被重复使用
- 排序后遇到超过 `target` 的情况就直接停止，剪枝是正确的

当 `current_sum == target` 时，
当前 `path` 就一定是一个合法答案。

而所有可能的合法选择路径都会被搜索到，
所以最终结果既不会漏解，
也不会重复。

## 复杂度分析

### 时间复杂度

时间复杂度不太容易用一个简单公式精确表示。

通常可以写作：

`O(S)`

其中 `S` 表示所有可行解的长度之和。

因为：

- 这道题本身就是在枚举所有答案
- 输出多少答案，运行时间就至少要和答案规模相关

另外还有一次排序开销：

`O(n log n)`

其中 `n` 是 `candidates` 的长度。

### 空间复杂度

如果不算结果数组，
递归栈和当前路径所占空间主要取决于搜索深度。

可以近似记作：

`O(target)`

更准确一点地说，
深度上界与：

```text
target / min(candidates)
```

有关。

## 常见错误

### 1. 递归时写成 `backtrack(i + 1, ...)`

这样会导致当前数字只能选一次，
就无法得到像：

```text
[2,2,3]
```

这样的答案。

### 2. 每一层都从 `0` 开始枚举

如果不使用 `start` 限制范围，
就容易同时生成：

- `[2,2,3]`
- `[2,3,2]`
- `[3,2,2]`

从而产生重复答案。

### 3. 没排序却直接 `break`

只有在数组已经排好序时，
遇到：

```python
current_sum + candidates[i] > target
```

才能放心 `break`。

如果没有排序，
后面可能还会有更小的数，
这时直接 `break` 会漏解。

### 4. 忘记加入答案时要复制 `path`

如果写成：

```python
result.append(path)
```

那么后续回溯继续修改 `path` 时，
结果里的内容也会跟着变。

正确写法是：

```python
result.append(path[:])
```

## 一句话总结

这道题的关键就是：

**用回溯枚举所有组合，利用 `start` 避免重复组合，利用递归传 `i` 实现数字可重复使用，再配合排序后的剪枝高效搜索答案。**
