# 022. 括号生成

## 所属专题

- 回溯

## 题目描述

数字 `n` 代表生成括号的对数，
请你设计一个函数，
用于生成所有可能的并且**有效**的括号组合。

这里的“有效”意思是：

- 每个左括号 `(` 都能找到对应的右括号 `)`
- 括号的闭合顺序也必须正确

例如：

```text
"()()" 是有效的
"(())" 也是有效的
"())(" 是无效的
"(()" 也是无效的
```

## 示例

### 示例 1

```text
输入：n = 3
输出：["((()))","(()())","(())()","()(())","()()()"]
```

### 示例 2

```text
输入：n = 1
输出：["()"]
```

## 题意理解

这道题不是让我们随便拼出长度为 `2 * n` 的括号字符串，
而是要求：

- 一共要用掉 `n` 个左括号
- 一共要用掉 `n` 个右括号
- 并且任意时刻都不能出现“右括号比左括号更多”的情况

比如当我们正在拼接字符串时：

```text
())
```

这个前缀已经不可能变成合法答案了，
因为右括号数量已经超过左括号数量。

所以这题的重点不是“最后再检查合不合法”，
而是：

**在构造过程中就保证它始终合法。**

## 为什么适合用回溯

我们要生成的是：

- 所有可能的合法组合

这种“列出所有方案”的题，
往往都适合考虑：

- 深度优先搜索
- 回溯

因为我们可以把构造字符串的过程看成一棵决策树：

- 每一步都尝试添加一个 `(`
- 或者尝试添加一个 `)`

但不是所有分支都能继续走，
只有满足规则的分支才保留。

这正是回溯的典型思路：

- 尝试一种选择
- 如果合法，就继续递归
- 如果不合法，就立刻剪枝

## 回溯中的两个核心限制

假设：

- `left` 表示已经使用了多少个左括号
- `right` 表示已经使用了多少个右括号

那么在任意时刻都必须满足下面两个条件。

### 1. 左括号数量不能超过 `n`

也就是：

```python
left < n
```

只有在这个条件成立时，
我们才能继续加左括号。

### 2. 右括号数量不能超过左括号数量

也就是：

```python
right < left
```

只有这样，
我们才能继续加右括号。

因为如果 `right >= left` 还继续加右括号，
就会出现不合法前缀。

## 回溯函数在做什么

我们可以定义一个函数：

```python
backtrack(path, left, right)
```

它表示：

- 当前已经拼出的字符串是 `path`
- 已使用左括号数量是 `left`
- 已使用右括号数量是 `right`

这个函数的任务就是：

- 在当前基础上继续往后拼
- 直到凑出一个完整合法答案

### 什么时候找到一个答案

当：

```python
len(path) == 2 * n
```

说明左右括号总数已经凑满，
而且因为前面的每一步都保证合法，
所以当前 `path` 一定是一个有效组合。

这时直接加入结果集即可。

## 用 `n = 3` 手推一遍

一开始：

```text
path = ""
left = 0
right = 0
```

因为 `left < n`，
所以可以先放左括号：

```text
"("
```

此时：

- `left = 1`
- `right = 0`

接下来有两种可能：

- 再放左括号
- 放右括号

如果继续放左括号：

```text
"(("
```

再继续：

```text
"((("
```

这时左括号已经用满，
只能不断补右括号：

```text
"((()"
"((())"
"((()))"
```

于是得到第一个答案：

```text
"((()))"
```

然后回溯到上一步，
去尝试别的分支，
最终还会得到：

- `(()())`
- `(())()`
- `()(())`
- `()()()`

## 为什么不会漏答案

因为回溯会枚举所有合法决策：

- 能放 `(` 的时候就尝试放 `(`
- 能放 `)` 的时候就尝试放 `)`

只要某条路径仍然可能形成合法答案，
它都会被继续探索。

而那些已经不可能合法的路径，
会被规则提前剪掉。

所以：

- 不会漏掉合法答案
- 也不会加入非法答案

## 算法步骤

1. 准备结果数组 `result`
2. 定义回溯函数 `backtrack(path, left, right)`
3. 如果 `len(path) == 2 * n`，把 `path` 加入结果
4. 如果 `left < n`，递归尝试加入 `(`
5. 如果 `right < left`，递归尝试加入 `)`
6. 从空字符串开始递归
7. 返回所有结果

## Python 参考实现

```python
def generateParenthesis(n):
    result = []

    def backtrack(path, left, right):
        if len(path) == 2 * n:
            result.append(path)
            return

        if left < n:
            backtrack(path + '(', left + 1, right)

        if right < left:
            backtrack(path + ')', left, right + 1)

    backtrack('', 0, 0)
    return result
```

## 为什么这样写是对的

因为整个递归过程中，
我们始终维护了两个重要不变量：

- 左括号总数不会超过 `n`
- 右括号总数不会超过左括号总数

这保证了当前构造出的任何前缀都不可能非法。

而当长度达到 `2 * n` 时，
说明：

- 左右括号都已经恰好用完
- 前缀过程始终合法

因此最终字符串一定是合法括号组合。

## 复杂度分析

### 时间复杂度

`O(4^n / √n)`

更准确地说，
生成的合法括号组合数量与第 `n` 个卡特兰数同阶，
所以总时间复杂度可以写作：

`O(C_n)`

其中 `C_n` 约等于：

```text
4^n / (n^(3/2))
```

很多资料也会近似写成：

`O(4^n / √n)`

本质上想表达的都是：

- 这题的复杂度主要取决于答案总数

### 空间复杂度

`O(n)`

因为：

- 递归栈深度最多是 `2 * n`
- 但数量级仍然可以记作 `O(n)`

如果不算结果数组本身，
额外空间主要就是递归调用栈。

## 常见错误

### 1. 只有最后才判断是否合法

有些人会先生成所有长度为 `2 * n` 的括号串，
最后再逐个检查是否合法。

这样虽然能做，
但会生成大量无效字符串，
效率很低。

更好的做法是：

- 在递归过程中直接剪枝

### 2. 把条件写成 `right < n`

右括号并不是只要没用完就能加。

真正的限制是：

```python
right < left
```

因为右括号必须和前面已有的左括号配对。

### 3. 终止条件写错

终止条件应该是：

```python
len(path) == 2 * n
```

而不是只看 `left == n`。

因为即使左括号已经用完，
右括号也可能还没补齐。

### 4. 忘记这是“生成所有答案”

这题不是判断是否存在一种方案，
而是要把所有合法组合都收集起来。

所以找到一个答案后：

- 不能直接返回整个函数
- 而是要加入结果，然后继续回溯

## 一句话总结

这道题的关键就是：

**用回溯逐步构造括号字符串，在构造过程中始终保证“左括号不超过 `n`、右括号不超过左括号”，这样就能高效生成所有合法答案。**
