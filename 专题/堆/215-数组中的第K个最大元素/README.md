# 215. 数组中的第K个最大元素

## 所属专题
- 堆

## 题目描述

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，这里找的是：

- 排序后第 `k` 个最大的元素

而不是：

- 第 `k` 个不同的元素

也就是说，如果数组里有重复数字，重复数字也要参与排名。

## 示例

### 示例 1

```text
输入：nums = [3,2,1,5,6,4], k = 2
输出：5
```

### 示例 2

```text
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
```

## 题意理解

这道题要我们做的事情其实很明确：

- 把数组按照从大到小的“排名”来理解
- 找到排在第 `k` 位的那个数

比如：

```text
nums = [3,2,1,5,6,4], k = 2
```

如果从大到小排好序：

```text
[6,5,4,3,2,1]
```

第 `2` 个最大的元素就是：

```text
5
```

还要特别注意一句题意：

**不是第 `k` 个不同的元素。**

例如：

```text
nums = [5,5,4], k = 2
```

从大到小排序后是：

```text
[5,5,4]
```

第 `2` 个最大的元素仍然是 `5`，而不是 `4`。

## 最直接的想法：排序

最容易想到的方法是：

1. 先把数组排序
2. 再取出第 `k` 个最大的元素

如果按从小到大排序：

```python
nums.sort()
return nums[-k]
```

如果按从大到小排序：

```python
nums.sort(reverse=True)
return nums[k - 1]
```

这个方法非常直观，也很容易写对。

但是问题在于：

- 排序会把整个数组都排好
- 可我们其实只关心第 `k` 个最大的元素

所以它的时间复杂度是：

```text
O(n log n)
```

可以继续优化。

## 优化思路：维护大小为 k 的最小堆

这是这道题最常用、也最好理解的优化方法。

### 核心想法

我们不需要把整个数组都排好，只需要始终保留：

- 当前见过的最大的 `k` 个元素

怎么保留？

- 用一个 **大小为 `k` 的最小堆**

最小堆有一个很重要的特点：

- 堆顶永远是堆里最小的元素

如果这个堆里装的正好是“当前最大的 `k` 个元素”，那么：

- 堆顶这个最小值
- 就正好是“当前第 `k` 大的元素”

遍历完整个数组之后：

- 堆里保存的就是“整个数组里最大的 `k` 个元素”
- 堆顶自然就是“整个数组里第 `k` 个最大元素”

### 为什么要用最小堆，而不是最大堆

因为我们想保留的是：

- 最大的 `k` 个数

当堆的大小超过 `k` 时，我们应该删掉谁？

- 删掉这 `k + 1` 个数里最小的那个

这样才能确保堆里剩下的，仍然是最大的 `k` 个数。

而最小堆恰好可以：

- 在 `O(log k)` 的时间内删除当前最小值

这就是它最合适的原因。

### 具体过程在做什么

遍历数组中的每个数字 `num`：

1. 先把 `num` 放进最小堆
2. 如果堆的大小超过了 `k`
3. 就把堆顶最小元素弹出去

也就是说，任何时候我们都让堆的大小不超过 `k`。

这样最后堆里剩下的，一定是：

- 遍历过的所有数字里最大的 `k` 个

而堆顶就是其中最小的那个，也就是答案。

### 为什么这个思路一定正确

你可以这样理解：

假设我们已经扫描了一部分数组，并且堆里正好保存着：

- 这部分数字里最大的 `k` 个

这时又来了一个新数字 `num`：

- 如果它比较小，那么它就算进堆，之后也会很快被弹出去
- 如果它足够大，那么它会挤掉原来那批数中更小的那个

所以每处理完一个数字，堆里始终都保持着：

- 当前为止最大的 `k` 个元素

遍历结束时，这个结论自然就扩展到整个数组。

注意这里有一个非常关键的结论：

**堆里不要求有序，只要求它始终保存“最大的 `k` 个元素”。**

只要这一点成立，堆顶就是答案。

## 用示例手推一遍

以：

```text
nums = [3,2,1,5,6,4], k = 2
```

为例。

为了讲清楚过程，下面把堆里的元素按“从小到大”写出来。

注意：

- 实际上 `heapq` 内部存储不一定长这样
- 但“堆顶是最小值”这个性质是不变的

### 初始状态

```text
heap = []
```

### 处理 3

放入堆中：

```text
heap = [3]
```

堆大小没有超过 `k = 2`，不用弹出。

### 处理 2

放入堆中：

```text
heap = [2,3]
```

堆大小还是 `2`，不用弹出。

### 处理 1

放入堆中：

```text
heap = [1,2,3]
```

现在堆大小变成 `3`，超过了 `k`，要弹出最小值：

```text
弹出 1
heap = [2,3]
```

这说明当前保留下来的，是目前最大的 `2` 个数：`2` 和 `3`。

### 处理 5

放入堆中：

```text
heap = [2,3,5]
```

超过大小限制，弹出最小值：

```text
弹出 2
heap = [3,5]
```

现在保留下来的，是目前最大的 `2` 个数：`3` 和 `5`。

### 处理 6

放入堆中：

```text
heap = [3,5,6]
```

超过大小限制，弹出最小值：

```text
弹出 3
heap = [5,6]
```

### 处理 4

放入堆中：

```text
heap = [4,5,6]
```

超过大小限制，弹出最小值：

```text
弹出 4
heap = [5,6]
```

遍历结束后：

```text
heap = [5,6]
```

堆顶是：

```text
5
```

所以答案就是：

```text
5
```

## 为什么最后 `heap[0]` 就是答案

最后这个堆中保存的是：

- 整个数组里最大的 `k` 个元素

在这 `k` 个元素里：

- 最小的那个
- 恰好就是第 `k` 大

举个最简单的例子：

如果最大的 `3` 个数是：

```text
[10, 8, 7]
```

那么：

- 第 `1` 大是 `10`
- 第 `2` 大是 `8`
- 第 `3` 大是 `7`

也就是说：

- “最大的 `k` 个数里面最小的那个”
- 就是“第 `k` 大”

这正是最小堆堆顶的含义。

## 进一步优化：快速选择（了解即可）

这道题还有一种很经典的方法：

- 快速选择 `Quick Select`

它和快速排序很像，核心思想是：

- 每次选一个基准值 `pivot`
- 把数组划分成“小于 pivot”和“大于 pivot”的两边
- 根据基准值最终落下的位置，判断第 `k` 大到底在左边还是右边

这样就不需要像快排那样把两边都排完。

它的平均时间复杂度可以做到：

```text
O(n)
```

但是：

- 写法比堆更难
- 理解成本更高
- 最坏情况下会退化到 `O(n^2)`

所以如果你现在主要目标是：

- 先把这道题稳定写对
- 先掌握一类常见的 Top K 做法

那么优先掌握：

- **最小堆**

会更合适。

## 算法步骤

1. 创建一个空的最小堆 `heap`
2. 遍历数组中的每个元素 `num`
3. 把 `num` 加入堆中
4. 如果堆的大小超过 `k`，就弹出堆顶最小元素
5. 遍历结束后，返回 `heap[0]`

## 复杂度分析

### 排序做法

时间复杂度：

```text
O(n log n)
```

空间复杂度：

```text
视排序实现而定，通常写作 O(1) 或 O(log n)
```

### 最小堆做法

时间复杂度：

```text
O(n log k)
```

原因是：

- 一共遍历 `n` 个元素
- 每次入堆 / 出堆的代价是 `O(log k)`

空间复杂度：

```text
O(k)
```

因为堆中最多只保存 `k` 个元素。

### 快速选择

平均时间复杂度：

```text
O(n)
```

最坏时间复杂度：

```text
O(n^2)
```

空间复杂度：

```text
O(1)
```

如果按原地划分来写，额外空间可以看作常数级。

## Python 参考实现（详细注释）

```python
from typing import List
import heapq


class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        # heapq 在 Python 里实现的是“最小堆”。
        # 也就是说，heap[0] 永远是当前堆中最小的那个元素。
        heap = []

        # 依次扫描数组中的每个数字。
        for num in nums:
            # 先把当前数字放进堆里。
            heapq.heappush(heap, num)

            # 如果堆的大小超过了 k，
            # 说明现在堆里有 k + 1 个数字。
            # 我们只想保留“最大的 k 个数字”，
            # 所以应该把其中最小的那个删掉。
            if len(heap) > k:
                heapq.heappop(heap)

        # 遍历结束后，heap 里正好保存着整个数组中最大的 k 个元素。
        # 而堆顶 heap[0] 是这 k 个元素里最小的那个，
        # 也就是整个数组的第 k 大元素。
        return heap[0]
```

## 这段代码最值得记住的地方

核心其实就这几句：

```python
heapq.heappush(heap, num)
if len(heap) > k:
    heapq.heappop(heap)
return heap[0]
```

你可以把它背成一句话：

**始终用最小堆保留最大的 `k` 个元素，最后堆顶就是第 `k` 大。**

## 常见错误

### 1. 误以为是“第 k 个不同的元素”

题目说的是：

- 第 `k` 个最大元素

不是：

- 第 `k` 个不同元素

重复数字也要参与排名。

### 2. 不明白为什么堆大小要控制在 `k`

如果不控制堆大小，堆里会放下所有元素，那就失去了“只保留最大的 `k` 个”的意义。

我们每次让堆大小不超过 `k`，本质上就是在不断淘汰较小的元素。

### 3. 误以为堆里的元素必须整体有序

堆和排序数组不是一回事。

堆只保证：

- 堆顶最小

并不保证其余元素从小到大完全排好。

但这已经足够解决这道题。

### 4. 想用最大堆直接做，却忽略了 Python 默认只有最小堆

Python 的 `heapq` 默认是：

- 最小堆

所以这题最自然的写法就是：

- 用大小为 `k` 的最小堆

而不是直接维护一个最大堆。

### 5. 把复杂度写错成 `O(n log n)`

如果使用的是“大小最多为 `k` 的堆”，那么每次调整堆的代价是：

```text
O(log k)
```

不是 `O(log n)`。

所以总时间复杂度是：

```text
O(n log k)
```

## 适合自己再写一遍的版本

```python
from typing import List
import heapq


class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        heap = []
        for num in nums:
            heapq.heappush(heap, num)
            if len(heap) > k:
                heapq.heappop(heap)
        return heap[0]
```

## 一句话总结

这道题的关键就是：

**不要想着把整个数组都排好，而是始终用一个大小为 `k` 的最小堆保留当前最大的 `k` 个元素，最后堆顶就是第 `k` 个最大元素。**
