# 347. 前 K 个高频元素

## 所属专题

- 哈希表
- 堆

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，请你返回其中出现频率前 `k` 高的元素。

你可以按 **任意顺序** 返回答案。

## 示例

### 示例 1

```text
输入：nums = [1,1,1,2,2,3], k = 2
输出：[1,2]
```

### 示例 2

```text
输入：nums = [1], k = 1
输出：[1]
```

## 题意理解

这道题要找的不是：

- 数组里最大的 `k` 个数
- 或者前 `k` 个不同元素

而是：

- **出现次数最多的 `k` 个元素**

比如：

```text
nums = [1,1,1,2,2,3], k = 2
```

这里每个数字出现的次数分别是：

- `1` 出现了 `3` 次
- `2` 出现了 `2` 次
- `3` 出现了 `1` 次

所以出现频率前 `2` 高的元素就是：

```text
[1,2]
```

题目还说：

- 返回顺序可以任意

这意味着我们只要找对元素集合即可，不需要额外维护输出顺序。

## 最直接的想法：先统计，再整体排序

最容易想到的做法是：

1. 先统计每个元素出现了多少次
2. 再按出现次数从大到小排序
3. 最后取前 `k` 个元素

例如：

```python
count = Counter(nums)
sorted_items = sorted(count.items(), key=lambda x: x[1], reverse=True)
answer = [num for num, freq in sorted_items[:k]]
```

这个方法很好理解，而且也能做出来。

但是它的问题是：

- 统计频率是 `O(n)`
- 排序不同元素需要 `O(m log m)`

其中 `m` 是不同元素的个数。

这个复杂度不算差，但我们还可以进一步优化：

**既然我们只要前 `k` 个，能不能没必要把所有元素都完整排一遍？**

## 正确思路：哈希表 + 最小堆

这道题非常经典的做法是：

- 用哈希表统计频率
- 用大小为 `k` 的最小堆维护“当前频率最高的 `k` 个元素”

### 第一步：统计频率

我们先用 `Counter` 统计每个元素出现了几次：

```python
count = Counter(nums)
```

例如：

```text
nums = [1,1,1,2,2,3]
```

统计结果就是：

```python
{
    1: 3,
    2: 2,
    3: 1
}
```

到这里，我们已经知道了：

- 每个元素的频率是多少

接下来要解决的问题就变成了：

- 怎样高效保留频率最高的前 `k` 个元素

### 第二步：为什么用最小堆

我们维护一个 **最小堆**，堆里放：

```python
(freq, num)
```

也就是：

- 频率
- 对应的元素

最小堆的特点是：

- 堆顶永远是当前堆里“最小”的那个元素

在这道题里，“最小”指的是：

- **频率最小**

这就非常适合拿来维护“前 `k` 大”。

因为我们的策略可以是：

- 遇到一个元素，就先放进堆
- 如果堆的大小超过了 `k`
- 就把堆顶弹出去

被弹出去的，恰好就是：

- 当前这批元素里频率最小的那个

这样一轮处理完后，堆里剩下的自然就是：

- 频率最高的 `k` 个元素

## 为什么堆大小只保留 `k`

这是这道题最值得记住的地方。

我们的目标不是把所有元素排好序，
而只是保留一个“候选集合”：

- 集合大小始终不超过 `k`
- 里面存的是当前看过的元素里最有希望进入答案的那些

如果当前堆已经有 `k` 个元素了，
又来了一个新元素：

- 如果它频率更高，它就应该留下
- 如果它频率更低，它就应该被淘汰

而最小堆正好能让我们快速完成这件事。

因为：

- 堆顶是当前 `k` 个候选里最弱的那个

一旦堆大小超过 `k`，我们把堆顶删掉，
就等于把“最不配留在前 `k`”的元素踢出去。

## 用示例手推一遍

以示例 1 为例：

```text
nums = [1,1,1,2,2,3], k = 2
```

先统计频率：

```python
count = {
    1: 3,
    2: 2,
    3: 1
}
```

初始化：

```python
heap = []
```

### 处理 `(1, 3)`

把 `(3, 1)` 放入堆：

```python
heap = [(3, 1)]
```

堆大小没有超过 `2`，不用弹出。

### 处理 `(2, 2)`

把 `(2, 2)` 放入堆：

```python
heap = [(2, 2), (3, 1)]
```

堆大小还是 `2`，不用弹出。

### 处理 `(3, 1)`

把 `(1, 3)` 放入堆：

```python
heap = [(1, 3), (3, 1), (2, 2)]
```

这时堆大小变成了 `3`，超过了 `k = 2`，
所以弹出堆顶：

```python
(1, 3)
```

也就是频率最小的那个元素 `3` 被淘汰。

此时堆里剩下：

```python
[(2, 2), (3, 1)]
```

对应的元素就是：

- `2`
- `1`

所以答案可以返回：

```text
[1,2]
```

或者：

```text
[2,1]
```

都算正确。

## 算法步骤

1. 用哈希表统计每个元素出现的频率
2. 创建一个最小堆 `heap`
3. 遍历每个 `(num, freq)`
4. 把 `(freq, num)` 压入堆中
5. 如果堆的大小超过 `k`，弹出堆顶
6. 遍历结束后，堆中剩下的就是频率前 `k` 高的元素
7. 提取堆中所有元素对应的数字并返回

## 为什么时间复杂度是 `O(n log k)`

设：

- `n` 是数组长度
- `m` 是不同元素个数

先看两部分：

### 1. 统计频率

这一部分是：

`O(n)`

### 2. 维护大小为 `k` 的最小堆

我们会遍历每个不同元素一次，也就是 `m` 次。

每次：

- `heappush` 是 `O(log k)`
- 超过大小时 `heappop` 也是 `O(log k)`

而堆的大小始终不超过 `k`，
所以单次操作代价是 `O(log k)`，不是 `O(log m)`。

因此这一部分总复杂度是：

`O(m log k)`

在最坏情况下，`m <= n`，
所以整体可以写成：

`O(n log k)`

## 复杂度分析

### 时间复杂度

`O(n log k)`

原因：

- 统计频率需要 `O(n)`
- 维护最小堆需要 `O(m log k)`
- 最坏情况下 `m <= n`

### 空间复杂度

`O(n)`

原因：

- 哈希表最坏要存下所有不同元素的频率
- 堆最多存 `k` 个元素
- 综合来看主导空间仍然是哈希表

## Python 参考实现

```python
import heapq
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        heap = []

        for num, freq in count.items():
            heapq.heappush(heap, (freq, num))

            if len(heap) > k:
                heapq.heappop(heap)

        return [num for freq, num in heap]
```

## 这段代码最值得记住的地方

如果你想自己默写，最核心的是下面这条主线：

```python
count = Counter(nums)
heap = []

for num, freq in count.items():
    heapq.heappush(heap, (freq, num))
    if len(heap) > k:
        heapq.heappop(heap)
```

它表达的就是：

- 先统计频率
- 再用最小堆保留频率最高的 `k` 个

本质上就是一句话：

**堆满了以后，谁频率最小，谁先出去。**

## 常见错误

### 1. 误以为要找“数值最大的前 `k` 个”

这道题比较的是：

- 出现频率

不是：

- 数值大小

### 2. 堆里放反了顺序

推荐写成：

```python
(freq, num)
```

因为我们要按频率比较，
所以频率应该放在元组前面。

### 3. 忘记在堆大小超过 `k` 时弹出

如果只入堆不弹出，
那堆里最后会保留所有元素，
就失去了“只维护前 `k` 个”的意义。

### 4. 误以为返回结果必须按频率排序

题目已经说明：

- 可以按任意顺序返回

所以直接返回堆中的元素即可。

### 5. 把复杂度写成 `O(n log n)`

如果你用的是“大小固定为 `k` 的最小堆”，
那堆操作的复杂度应当是：

`O(log k)`

不是 `O(log n)`。

## 一句话总结

这道题的关键就是：

**先用哈希表统计频率，再用大小固定为 `k` 的最小堆持续淘汰频率最小的元素，最后堆里剩下的就是前 `k` 个高频元素。**
