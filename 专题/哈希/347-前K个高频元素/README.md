# 347. 前 K 个高频元素

## 所属专题

- 哈希表
- 堆

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，请你返回其中出现频率前 `k` 高的元素。

你可以按 **任意顺序** 返回答案。

## 示例

### 示例 1

```text
输入：nums = [1,1,1,2,2,3], k = 2
输出：[1,2]
```

### 示例 2

```text
输入：nums = [1], k = 1
输出：[1]
```

## 题意理解

这道题比较的不是：

- 数值本身谁更大

而是：

- 谁出现得更频繁

例如：

```text
nums = [1,1,1,2,2,3], k = 2
```

每个数字的出现次数分别是：

- `1` 出现了 `3` 次
- `2` 出现了 `2` 次
- `3` 出现了 `1` 次

所以前 `2` 个高频元素就是：

```text
[1,2]
```

题目还额外告诉我们：

- 返回顺序可以任意

这意味着：

- 我们只需要把正确的 `k` 个元素找出来
- 不需要再额外把答案按频率排好

## 最直接的想法：先统计，再整体排序

最容易想到的做法是：

1. 先统计每个元素出现了多少次
2. 再按频率从大到小排序
3. 取前 `k` 个元素

例如：

```python
count = Counter(nums)
sorted_items = sorted(count.items(), key=lambda x: x[1], reverse=True)
answer = [num for num, freq in sorted_items[:k]]
```

这个做法很好理解，也比较容易写对。

但是问题在于：

- 我们其实只需要前 `k` 个
- 没必要把所有不同元素都完整排序一遍

所以我们可以继续优化。

## 正确思路：哈希表 + 最小堆

这道题最经典的写法就是：

- 先用哈希表统计频率
- 再用大小为 `k` 的最小堆维护当前频率最高的 `k` 个元素

### 第一步：用哈希表统计频率

我们先用 `Counter` 统计每个元素出现的次数：

```python
count = Counter(nums)
```

例如：

```text
nums = [1,1,1,2,2,3]
```

统计后得到：

```python
{
    1: 3,
    2: 2,
    3: 1
}
```

这一步完成之后，问题就变成了：

- 在这些 `(元素, 频率)` 中
- 找到频率最高的前 `k` 个

### 第二步：为什么用最小堆

我们维护一个 **大小最多为 `k` 的最小堆**。

堆里放的是：

```python
(freq, num)
```

也就是：

- 当前元素的频率
- 当前元素本身

最小堆有一个重要特点：

- 堆顶永远是堆里最小的那个

而这里的“最小”，优先比较的是元组的第一个值，也就是：

- 频率

所以堆顶表示的是：

- 当前堆里频率最小的那个元素

这就很适合维护“前 `k` 个高频元素”。

因为我们的策略可以写成：

1. 遍历每个 `(num, freq)`
2. 先把 `(freq, num)` 放进堆
3. 如果堆大小超过 `k`
4. 就把堆顶弹出去

被弹出去的是谁？

- 当前候选集合里频率最小的那个

这样最后堆里剩下的，自然就是：

- 频率最高的 `k` 个元素

### 为什么堆的大小只保留 `k`

这是这道题最值得记住的地方。

我们的目标不是保存所有元素，
而是始终维护一个“答案候选区”：

- 大小最多为 `k`
- 里面放的是当前最有希望进入最终答案的元素

如果当前堆里已经有 `k` 个元素，
这时又来了一个新元素：

- 如果它频率高，它应该把更弱的那个挤出去
- 如果它频率低，它自己就会被淘汰

而最小堆正好可以让我们在 `O(log k)` 的时间里完成这件事。

### 为什么堆里放 `(freq, num)` 而不是 `(num, freq)`

因为我们要比较的是：

- 频率

不是：

- 数值大小

Python 的堆在比较元组时，会先比较第一个位置。

所以我们要把频率放在前面：

```python
(freq, num)
```

这样堆顶才会自动对应“频率最小”的那个元素。

## 用示例手推一遍

以示例 1 为例：

```text
nums = [1,1,1,2,2,3], k = 2
```

先统计频率：

```python
count = {
    1: 3,
    2: 2,
    3: 1
}
```

初始化：

```python
heap = []
```

### 处理数字 `1`

它的频率是 `3`，把 `(3, 1)` 放进堆：

```python
heap = [(3, 1)]
```

堆大小没有超过 `2`，不用弹出。

### 处理数字 `2`

它的频率是 `2`，把 `(2, 2)` 放进堆：

```python
heap = [(2, 2), (3, 1)]
```

堆大小还是 `2`，不用弹出。

### 处理数字 `3`

它的频率是 `1`，把 `(1, 3)` 放进堆：

```python
heap = [(1, 3), (3, 1), (2, 2)]
```

现在堆大小变成了 `3`，超过了 `k = 2`，
所以要弹出堆顶：

```python
(1, 3)
```

这说明：

- 频率最低的元素 `3`
- 被淘汰了

此时堆里剩下：

```python
[(2, 2), (3, 1)]
```

对应的元素就是：

- `2`
- `1`

所以最后答案可以返回：

```text
[1,2]
```

或者：

```text
[2,1]
```

都算正确。

## 为什么这样写

你可以把这道题的核心理解成一句话：

**先把“每个元素出现几次”算出来，再不断淘汰频率最小的候选，只保留前 `k` 个。**

也就是说：

- `Counter` 负责回答“谁出现了几次”
- 最小堆负责回答“前 `k` 个里谁最该被淘汰”

这样分工以后，代码就会很自然：

- 统计阶段用哈希表
- 选择前 `k` 阶段用堆

这也是为什么这题通常会同时归到：

- 哈希表
- 堆

## 算法步骤

1. 用 `Counter(nums)` 统计每个元素出现的频率
2. 创建一个空的最小堆 `heap`
3. 遍历频率表中的每一组 `(num, freq)`
4. 把 `(freq, num)` 加入堆
5. 如果堆大小超过 `k`，弹出堆顶
6. 遍历结束后，堆中剩下的就是前 `k` 个高频元素
7. 提取堆中每个二元组里的 `num` 并返回

## 复杂度分析

设：

- `n` 是数组长度
- `m` 是不同元素的个数

### 时间复杂度

```text
O(n + m log k)
```

原因：

- 统计频率需要 `O(n)`
- 遍历每个不同元素需要 `m` 次
- 每次入堆 / 出堆的代价是 `O(log k)`

因为 `m <= n`，
所以很多时候也会把它写成：

```text
O(n log k)
```

### 空间复杂度

```text
O(m + k)
```

原因：

- 哈希表要存每个不同元素的频率
- 堆最多保存 `k` 个元素

在最坏情况下 `m` 可能接近 `n`，
所以也可以写成：

```text
O(n)
```

## Python 参考实现（详细注释）

```python
import heapq
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        # Counter 会帮我们统计每个元素出现了多少次。
        # 例如：
        # nums = [1,1,1,2,2,3]
        # count = {1: 3, 2: 2, 3: 1}
        count = Counter(nums)

        # Python 的 heapq 是最小堆。
        # 这里堆里存的是 (频率, 元素)。
        # 这样堆顶就是“当前堆里频率最小的那个元素”。
        heap = []

        # 遍历每个不同元素及其频率。
        for num, freq in count.items():
            # 先把当前元素放进堆中。
            heapq.heappush(heap, (freq, num))

            # 如果堆的大小超过了 k，
            # 说明当前候选元素太多了，
            # 我们就把频率最小的那个弹出去。
            if len(heap) > k:
                heapq.heappop(heap)

        # 遍历结束后，
        # 堆中剩下的就是频率前 k 高的元素。
        # 题目允许任意顺序返回，
        # 所以直接把每个二元组中的 num 取出来即可。
        return [num for freq, num in heap]
```

## 补充：如果想得更快一点

这道题还有一种常见做法：

- 桶排序

它可以做到接近线性的复杂度。

不过对于现在这个阶段来说，
最小堆做法更统一，也更容易和：

- 第 K 大元素
- 前 K 个问题

这一类题目形成同一套思路。

所以这题优先掌握：

- `Counter + 最小堆`

是很合适的。

## 常见错误

### 1. 把这题理解成“找数值最大的前 `k` 个”

这题比较的是：

- 频率

不是：

- 数值大小

### 2. 堆里放成 `(num, freq)`

如果这样放，堆优先比较的就是 `num`，
逻辑就错了。

正确写法应该是：

```python
(freq, num)
```

### 3. 忘记在堆大小超过 `k` 时弹出

如果只入堆不弹出，
最后堆里会保留所有元素，
就失去了“只保留前 `k` 个”的意义。

### 4. 误以为返回结果必须排好序

题目明确说了：

- 可以按任意顺序返回

所以不需要额外再排序答案。

### 5. 把时间复杂度写成 `O(n log n)`

如果你维护的是：

- 大小最多为 `k` 的堆

那么堆操作的复杂度是：

```text
O(log k)
```

不是：

```text
O(log n)
```

## 适合自己再写一遍的版本

```python
import heapq
from collections import Counter


class Solution:
    def topKFrequent(self, nums, k):
        count = Counter(nums)
        heap = []

        for num, freq in count.items():
            heapq.heappush(heap, (freq, num))
            if len(heap) > k:
                heapq.heappop(heap)

        return [num for freq, num in heap]
```

## 一句话总结

这道题的关键就是：

**先用哈希表统计每个元素的出现频率，再用大小固定为 `k` 的最小堆持续淘汰频率最小的候选，最后堆里剩下的就是前 `k` 个高频元素。**
