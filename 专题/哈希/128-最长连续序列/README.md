# 128. 最长连续序列

## 所属专题

- 哈希表

## 题目描述

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

## 示例

### 示例 1

```text
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长连续序列是 [1,2,3,4]，长度为 4。
```

### 示例 2

```text
输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
解释：最长连续序列是 [0,1,2,3,4,5,6,7,8]，长度为 9。
```

## 题意理解

这道题容易有两个误区：

- 题目找的是“值连续”的序列，不是“下标连续”的子数组
- 题目只要求返回最长长度，不要求把整个序列返回出来

例如：

```text
nums = [100,4,200,1,3,2]
```

虽然 `1、3、2、4` 在原数组里是分散开的，
但只要把它们按值来看，就是一段连续序列：

```text
1,2,3,4
```

所以答案是 `4`。

同时题目还要求时间复杂度必须是 `O(n)`，
这意味着：

- 排序虽然能做
- 但排序是 `O(n log n)`
- 不符合这道题的进阶要求

因此这道题的核心不是“怎么判断连续”，而是：

**怎么在不排序的前提下，高效地找到每一段连续序列的长度。**

## 最直接的想法：先排序

很多人第一反应会是：

1. 先把数组排序
2. 然后线性扫描
3. 统计最长连续段

比如：

```text
[100,4,200,1,3,2]
排序后变成
[1,2,3,4,100,200]
```

这样确实很容易找到最长连续段 `[1,2,3,4]`。

但是这个方法的问题在于：

- 排序需要 `O(n log n)`
- 题目明确要求 `O(n)`

所以我们得继续想：

**有没有一种结构，能让我们在 `O(1)` 的平均时间内判断某个数是否存在？**

答案就是：

- 哈希集合 `set`

## 正确思路：哈希集合

### 第一步：先把所有数字放进集合

我们先把数组里的所有数字放进哈希集合：

```python
num_set = set(nums)
```

这样做的好处是：

- 可以去重
- 可以在平均 `O(1)` 时间判断某个数在不在集合里

例如：

```text
nums = [100,4,200,1,3,2]
num_set = {100, 4, 200, 1, 3, 2}
```

### 第二步：不是每个数都要往后找

如果我们对集合中的每个数字都去尝试：

- `num + 1` 在不在
- `num + 2` 在不在
- `num + 3` 在不在

那会产生大量重复计算。

比如连续序列是：

```text
1,2,3,4
```

如果从 `1` 开始找，会得到长度 `4`；
如果又从 `2` 开始找，还会再算一次；
从 `3` 开始找，还会继续重复。

所以真正关键的一步是：

**我们只从“连续序列的起点”开始向后统计。**

### 什么叫“起点”

如果一个数字 `num` 的前一个数 `num - 1` 不在集合里，
那它就是某段连续序列的起点。

也就是说：

```python
if num - 1 not in num_set:
```

满足这个条件时，才有必要从 `num` 开始往后找。

为什么？

因为如果 `num - 1` 已经存在，说明 `num` 不是开头，
它一定属于前面某一段已经能统计到的连续序列。

## 为什么只从起点出发就够了

这是整道题最重要的优化。

以这段连续序列为例：

```text
1,2,3,4
```

我们检查每个数：

- `1` 的前一个数是 `0`，不存在，所以 `1` 是起点
- `2` 的前一个数是 `1`，存在，所以 `2` 不是起点
- `3` 的前一个数是 `2`，存在，所以 `3` 不是起点
- `4` 的前一个数是 `3`，存在，所以 `4` 不是起点

因此这一整段只会从 `1` 被统计一次。

接着我们从 `1` 开始不断判断：

- `2` 在不在
- `3` 在不在
- `4` 在不在
- `5` 在不在

直到中断为止，就能得到这一段的长度。

这样就避免了重复遍历，保证整体仍然是线性的。

- 所以 `200` 是起点

向后检查：

- `201` 不在集合里

- `0` 不在集合里

- `1` 在集合里

```text
4
```

## 算法步骤

1. 如果数组为空，直接返回 `0`
2. 把数组中的所有数字放入哈希集合 `num_set`
3. 初始化答案 `longest = 0`
4. 遍历集合中的每个数字 `num`
5. 如果 `num - 1` 不在集合中，说明 `num` 是连续序列起点
6. 从这个起点开始不断判断 `num + 1`、`num + 2` 是否存在
7. 统计当前连续序列长度
8. 用当前长度更新全局最大值 `longest`
9. 遍历结束后返回 `longest`

## 为什么时间复杂度是 `O(n)`

很多人看到里面有一个 `for` 加一个 `while`，会担心是不是 `O(n^2)`。

其实不是。

原因在于：

- 外层确实遍历了每个数字一次
- 但内层 `while` 只会从“起点”出发
- 每个数字最多只会在某一条连续序列里被向后访问一次

换句话说，像 `1,2,3,4` 这一段：

- 不会从 `1` 算一遍
- 再从 `2` 算一遍
- 再从 `3` 算一遍

而是只会从 `1` 这一处完整统计一次。

所以所有 `while` 循环加起来，整体仍然是 `O(n)`。

## 复杂度分析

### 时间复杂度

`O(n)`

原因：

- 建立哈希集合需要 `O(n)`
- 遍历集合需要 `O(n)`
- 每个数字最多被连续序列统计过程访问一次

### 空间复杂度

`O(n)`

原因：

- 需要一个哈希集合存储数组中的所有数字

## Python 参考实现

```python
from typing import List


class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        if not nums:
            return 0

        num_set = set(nums)
        longest = 0

        for num in num_set:
            if num - 1 not in num_set:
                current_num = num
                current_length = 1

                while current_num + 1 in num_set:
                    current_num += 1
                    current_length += 1

                longest = max(longest, current_length)

        return longest
```

## 这段代码最值得记住的地方

你真正要记住的不是整段代码，而是下面这条主线：

```python
num_set = set(nums)

for num in num_set:
    if num - 1 not in num_set:
        current_num = num
        current_length = 1

        while current_num + 1 in num_set:
            current_num += 1
            current_length += 1
```

这段逻辑可以概括成一句话：

**先用集合实现快速查找，再只从连续序列的起点开始往后扩展。**

## 常见错误

### 1. 先排序再做

这样虽然容易想到，也能通过大多数测试，
但时间复杂度是 `O(n log n)`，不符合题目要求的 `O(n)`。

### 2. 对每个数字都向后扩展

如果不写这句：

```python
if num - 1 not in num_set:
```

那么像 `1,2,3,4` 这样的序列会被重复统计很多次，
最坏情况下可能退化成 `O(n^2)`。

### 3. 忽略重复元素

原数组里可能有重复值，比如：

```text
[0,1,1,2]
```

这时候直接转成集合是很自然的做法，
因为重复数字不会对“最长连续长度”产生额外贡献。

### 4. 空数组没有单独处理

如果 `nums = []`，答案应该直接是：

```text
0
```

所以开头最好先判断空数组。

### 5. 把题目理解成连续子数组

这道题找的是“数值连续”，
不是要求这些数在原数组中的位置相邻。

例如：

```text
[100,4,200,1,3,2]
```

虽然 `1,2,3,4` 在原数组里并不连续出现，
但它们仍然构成合法的连续序列。

## 一句话总结

这道题的关键就是：

**把所有数字放进哈希集合中，只从“前一个数不存在”的起点出发向后统计，这样既能避免重复计算，又能把时间复杂度控制在 `O(n)`。**
