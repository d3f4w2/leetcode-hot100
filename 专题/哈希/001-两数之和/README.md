# 001. 两数之和

## 所属专题

- 哈希表

## 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在数组中找出 **和为目标值 `target`** 的那 **两个整数的下标**，并返回这两个下标。

你可以假设每种输入只会对应一个答案，并且同一个元素不能被重复使用。

返回答案的顺序可以任意。

## 示例

### 示例 1

```text
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。
```

### 示例 2

```text
输入：nums = [3,2,4], target = 6
输出：[1,2]
```

### 示例 3

```text
输入：nums = [3,3], target = 6
输出：[0,1]
```

## 题意理解

这道题不是让我们返回两个数本身，而是让我们返回这两个数的 **下标**。

也就是说：

- 先找到两个数，它们的和等于 `target`
- 再返回这两个数在原数组中的位置

同时题目还告诉我们两个非常重要的信息：

1. 一定存在答案
2. 同一个元素不能重复使用

这两个条件能帮助我们放心地设计更高效的做法。

## 最直接的想法：暴力枚举

最容易想到的方法，就是枚举所有两两组合。

具体做法：

- 第一个数从前往后枚举
- 第二个数从第一个数后面继续枚举
- 如果两数之和等于 `target`，就直接返回这两个下标

例如：

- `nums = [2,7,11,15]`
- 先试 `(2,7)`，发现 `2 + 7 = 9`
- 于是返回 `[0,1]`

这个方法肯定能做出来，但是时间复杂度是 `O(n^2)`。

当数组变长时，需要比较的次数会很多，所以我们要思考：

**能不能在遍历数组的时候，快速知道“我现在还差哪个数”？**

## 优化思路：哈希表

这是这道题最经典的做法。

### 核心想法

当我们遍历到当前数字 `num` 时，真正关心的不是“它能和谁配对”，而是：

> 如果想让它和另一个数的和等于 `target`，那我还需要一个什么数？

这个“还需要的数”就是：

```text
need = target - num
```

如果我们能在 `O(1)` 的时间内判断：

- `need` 之前有没有出现过

那么这道题就能高效解决。

哈希表正好擅长做这件事。

### 哈希表里存什么

我们用一个字典 `seen` 来记录：

- **键（key）**：某个已经遍历过的数字
- **值（value）**：这个数字对应的下标

比如遍历到一半时，可能有：

```python
seen = {
    2: 0,
    7: 1
}
```

它表示：

- 数字 `2` 在下标 `0`
- 数字 `7` 在下标 `1`

### 遍历时做什么

对于当前数字 `num`：

1. 先计算 `need = target - num`
2. 看 `need` 是否已经在 `seen` 中
3. 如果在，说明已经找到了答案
4. 如果不在，就把当前数字和它的下标存进 `seen`

注意这个顺序非常重要：

- **先查找，后存入**

这样可以避免把同一个元素用两次。

## 用示例手推一遍

以示例 1 为例：

```text
nums = [2,7,11,15], target = 9
```

### 第 1 步

- 当前数字：`2`
- 还需要：`9 - 2 = 7`
- `7` 不在 `seen` 中
- 把 `2:0` 存入哈希表

此时：

```python
seen = {2: 0}
```

### 第 2 步

- 当前数字：`7`
- 还需要：`9 - 7 = 2`
- `2` 已经在 `seen` 中
- 并且它的下标是 `0`

所以答案就是：

```text
[0, 1]
```

到这里就可以直接返回，不需要继续往后找。

## 为什么一定要“先查再存”

看这个例子：

```text
nums = [3,3], target = 6
```

如果你先把当前元素存进去，再去查找，就有可能错误地把同一个位置用了两次。

而正确做法是：

- 先看 `need` 是否已经出现过
- 确认是“之前的元素”后，再把当前元素存进去

这样就能保证返回的是两个不同的下标。

## 算法步骤

1. 创建一个空哈希表 `seen`
2. 从左到右遍历数组 `nums`
3. 对于当前元素 `num`，计算 `need = target - num`
4. 如果 `need` 在 `seen` 中，返回 `[seen[need], 当前下标]`
5. 如果不在，把 `num` 和当前下标存入 `seen`
6. 遍历结束

由于题目保证一定有解，所以正常情况下遍历过程中一定能返回答案。

## 复杂度分析

### 时间复杂度

`O(n)`

原因：

- 数组只遍历一遍
- 哈希表查询和插入平均是 `O(1)`

### 空间复杂度

`O(n)`

原因：

- 最坏情况下，需要把很多元素都存进哈希表

## Python 参考实现（详细注释）

```python
from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        # 用哈希表记录“已经遍历过的数字”以及它对应的下标。
        # 例如 seen[2] = 0 表示：数字 2 曾经出现在下标 0 的位置。
        seen = {}

        # enumerate(nums) 会同时拿到：
        # 1. 当前元素的下标 index
        # 2. 当前元素的值 num
        for index, num in enumerate(nums):
            # 如果当前数字是 num，想要凑成 target，
            # 那么另外一个数字就必须是 target - num。
            need = target - num

            # 如果 need 已经在 seen 中，说明：
            # 我们之前遍历过某个数字，它正好可以和当前 num 配对。
            if need in seen:
                # seen[need] 是之前那个数字的下标，
                # index 是当前数字的下标。
                # 这两个位置对应的元素之和正好等于 target。
                return [seen[need], index]

            # 如果走到这里，说明当前 num 还没找到配对值。
            # 那就先把当前数字和它的下标存起来，
            # 供后面的元素来查找。
            seen[num] = index

        # 题目保证一定有解，因此理论上不会走到这里。
        # 这里写 return [] 只是为了让函数结构完整。
        return []
```

## 这段代码最值得记住的地方

你在自己手写的时候，重点记住下面这几句：

```python
seen = {}

for index, num in enumerate(nums):
    need = target - num
    if need in seen:
        return [seen[need], index]
    seen[num] = index
```

本质上就是一句话：

**边遍历，边检查“我需要的那个数”之前有没有出现过。**

## 常见错误

### 1. 返回数字而不是下标

题目要的是：

- 下标

不是：

- 数值本身

### 2. 先存后查，导致逻辑混乱

推荐固定写法：

- 先查 `need`
- 再存 `num`

### 3. 忘记哈希表里存的是“值到下标”的映射

要存的是：

```python
seen[num] = index
```

而不是别的方向。

```python
from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for index, num in enumerate(nums):
            need = target - num
            if need in seen:
                return [seen[need], index]
            seen[num] = index
        return []
```

## 一句话总结

这道题的关键不是“找两个数”，而是：

**遍历当前数字时，立刻去问：我还差的那个数，之前见过没有？**

一旦用哈希表把这个问题变成 `O(1)` 查询，这道题就从 `O(n^2)` 优化到了 `O(n)`。
