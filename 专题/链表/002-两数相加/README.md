# 002. 两数相加

## 所属专题

- 链表

## 题目描述

给你两个 **非空** 的链表，表示两个非负整数。

它们每位数字都是按照 **逆序** 的方式存储的，并且每个节点只能存储 **一位数字**。

请你将两个数相加，并以相同形式返回一个表示和的链表。

你可以假设除了数字 `0` 之外，这两个数都不会以 `0` 开头。

## 示例

### 示例 1

```text
输入：l1 = [2,4,3], l2 = [5,6,4]
输出：[7,0,8]
解释：342 + 465 = 807
```

### 示例 2

```text
输入：l1 = [0], l2 = [0]
输出：[0]
```

### 示例 3

```text
输入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
输出：[8,9,9,9,0,0,0,1]
```

## 题意理解

这道题虽然是链表题，但本质上是在模拟我们平时做竖式加法。

不同点在于：

- 数字不是放在数组里
- 也不是直接给你整数
- 而是放在链表里

并且存储顺序还是：

- **个位在前面**
- **高位在后面**

例如：

```text
l1 = [2,4,3]
```

表示的不是 `243`，而是：

```text
342
```

因为：

- 第一个节点 `2` 是个位
- 第二个节点 `4` 是十位
- 第三个节点 `3` 是百位

同理：

```text
l2 = [5,6,4]
```

表示：

```text
465
```

所以题目实际是在求：

```text
342 + 465 = 807
```

最后再把结果按同样的逆序链表形式返回：

```text
[7,0,8]
```

## 最直接的想法：先转成整数再相加

最容易想到的方法是：

1. 先把链表还原成整数
2. 两个整数直接相加
3. 再把结果转回链表

这个思路看上去很自然。

但它并不是最推荐的做法，原因有两个：

### 问题 1：题目本身就是在考“链表逐位处理”

如果把链表先转整数，
就绕开了这道题真正想考的内容。

### 问题 2：数字可能很长

链表长度可能很大。

如果你依赖语言里的整数类型，
就不够“纯粹”，也不够稳妥。

所以更好的做法是：

- 不把它们整体转成整数
- 直接在链表层面做逐位相加

## 优化思路：模拟加法过程

这是这道题最经典、也最应该掌握的做法。

### 核心想法

我们平时做加法时，是怎么做的？

例如：

```text
  342
+ 465
-----
  807
```

其实就是：

1. 先加个位
2. 再加十位
3. 再加百位
4. 每一步都处理进位

而这道题的链表刚好把个位放在最前面，
所以我们可以从头开始，刚好顺着链表做加法。

### 每一步加什么

在当前位置，我们需要计算：

```text
当前位结果 = l1 当前值 + l2 当前值 + 进位 carry
```

假设这一位总和是 `total`，那么：

- 当前新节点的值是 `total % 10`
- 新的进位是 `total // 10`

这和手算加法完全一致。

### 为什么要有 `carry`

比如：

```text
8 + 7 = 15
```

那这一位只能写：

```text
5
```

并把：

```text
1
```

带到下一位。

这个“带过去的 1”，就是 `carry`。

所以这题里，`carry` 就是在保存：

- 上一位加法产生的进位

### 为什么循环条件要写成 `while l1 or l2 or carry`

这是这题很关键的一个细节。

原因是我们不只是要处理：

- `l1` 没走完
- `l2` 没走完

还要处理最后可能剩下的：

- 进位 `carry`

例如：

```text
[9] + [1]
```

计算过程：

- `9 + 1 = 10`
- 当前位写 `0`
- 进位是 `1`

这时两个链表都结束了，
但结果还没结束，
还必须再补一个节点 `1`。

所以循环必须把 `carry` 也算进去。

### 为什么要用 `dummy`

和很多链表题一样，
这里也很适合用虚拟头节点 `dummy`。

它的作用是：

- 统一处理结果链表的第一个节点和后续节点

否则你就要单独判断：

- 结果链表是不是还没创建

有了 `dummy` 以后：

- 所有新节点都直接接到 `curr.next`
- 最后返回 `dummy.next`

代码会整齐很多。

## 用示例手推一遍

以示例 1 为例：

```text
l1 = [2,4,3]
l2 = [5,6,4]
```

实际表示：

```text
342 + 465
```

### 初始状态

- `carry = 0`
- `curr` 指向 `dummy`

### 第 1 步：个位

- `val1 = 2`
- `val2 = 5`
- `total = 2 + 5 + 0 = 7`

所以：

- 当前位写 `7`
- 进位 `carry = 0`

结果链表现在是：

```text
[7]
```

### 第 2 步：十位

- `val1 = 4`
- `val2 = 6`
- `total = 4 + 6 + 0 = 10`

所以：

- 当前位写 `0`
- 进位 `carry = 1`

结果链表变成：

```text
[7,0]
```

### 第 3 步：百位

- `val1 = 3`
- `val2 = 4`
- `carry = 1`
- `total = 3 + 4 + 1 = 8`

所以：

- 当前位写 `8`
- 进位 `carry = 0`

结果链表变成：

```text
[7,0,8]
```

两个链表都走完，进位也为 `0`，结束。

最终答案：

```text
[7,0,8]
```

## 再看一个有最后进位的例子

```text
l1 = [9]
l2 = [1]
```

表示：

```text
9 + 1 = 10
```

### 第 1 步

- `9 + 1 + 0 = 10`
- 当前位写 `0`
- 进位变成 `1`

结果链表：

```text
[0]
```

### 第 2 步

这时：

- `l1` 空了
- `l2` 空了
- 但 `carry = 1`

所以还要继续循环一次：

- `0 + 0 + 1 = 1`

结果链表变成：

```text
[0,1]
```

这正好表示数字 `10` 的逆序形式。

## 为什么这样写

这道题看起来像链表题，其实核心是“逐位模拟加法”。

### 1. 逆序存储正好让我们从低位开始算

如果个位在最后，
链表处理起来会很麻烦。

但现在个位就在头部，
刚好和手算加法顺序一致：

- 先算低位
- 再算高位

### 2. `carry` 把多出来的十位传给下一轮

每一位加法都可能产生进位，
而这个进位必须影响下一位。

所以 `carry` 是整道题的核心状态变量。

### 3. 任意一个链表先结束都没关系

因为我们写的是：

```python
val1 = l1.val if l1 else 0
val2 = l2.val if l2 else 0
```

也就是说：

- 如果某一边没节点了，就按 `0` 处理

这和手算时“某一位不存在就当 0”是一样的。

### 4. 结果链表通常需要新建节点

和“合并两个有序链表”那种直接复用原节点不同，
这题是要创建一条新的结果链表。

因为每一位的值是：

- 现算出来的

并不对应原链表中的某个现成节点。

## 算法步骤

1. 创建虚拟头节点 `dummy`
2. 用指针 `curr` 指向结果链表的当前末尾
3. 初始化进位 `carry = 0`
4. 当 `l1`、`l2`、`carry` 三者中任意一个还存在时继续循环
5. 取出当前位的两个值，不存在的链表按 `0` 处理
6. 计算 `total = val1 + val2 + carry`
7. 创建新节点，值为 `total % 10`
8. 更新进位 `carry = total // 10`
9. 移动 `l1`、`l2`、`curr`
10. 循环结束后返回 `dummy.next`

## 复杂度分析

### 时间复杂度

`O(max(m, n))`

其中：

- `m` 是链表 `l1` 的长度
- `n` 是链表 `l2` 的长度

原因：

- 我们按位处理两个链表
- 每个节点最多访问一次

### 空间复杂度

`O(max(m, n))`

原因：

- 需要新建结果链表
- 最长情况下结果长度可能是 `max(m, n) + 1`

## Python 参考实现（详细注释）

```python
from typing import Optional


# LeetCode 平台会提供 ListNode 定义。
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next


class Solution:
    def addTwoNumbers(
        self,
        l1: Optional[ListNode],
        l2: Optional[ListNode]
    ) -> Optional[ListNode]:
        # dummy 是虚拟头节点，用来统一处理结果链表的连接逻辑。
        dummy = ListNode(0)

        # curr 始终指向结果链表的末尾。
        curr = dummy

        # carry 记录上一位相加后的进位。
        carry = 0

        # 只要两个链表还有节点，或者还有进位，就继续处理。
        while l1 or l2 or carry:
            # 如果某个链表已经为空，就把它这一位当成 0。
            val1 = l1.val if l1 else 0
            val2 = l2.val if l2 else 0

            # 当前位总和 = 两个数字 + 上一位进位。
            total = val1 + val2 + carry

            # 新进位是十位部分。
            carry = total // 10

            # 当前结果节点的值是个位部分。
            curr.next = ListNode(total % 10)
            curr = curr.next

            # 两个链表分别向后移动。
            l1 = l1.next if l1 else None
            l2 = l2.next if l2 else None

        return dummy.next
```

## 这段代码最值得记住的地方

你在自己手写的时候，重点记住下面这条主线：

```python
dummy = ListNode(0)
curr = dummy
carry = 0

while l1 or l2 or carry:
    val1 = l1.val if l1 else 0
    val2 = l2.val if l2 else 0

    total = val1 + val2 + carry
    carry = total // 10

    curr.next = ListNode(total % 10)
    curr = curr.next

    l1 = l1.next if l1 else None
    l2 = l2.next if l2 else None
```

本质上就是一句话：

**把链表当成按位存储的数字，从低位开始逐位相加，同时维护进位并构造结果链表。**

## 常见错误

### 1. 把链表表示的数字顺序理解反了

例如：

```text
[2,4,3]
```

表示的是：

```text
342
```

不是 `243`。

### 2. 忘记处理进位 `carry`

这会导致像：

```text
5 + 5 = 10
```

这种情况出错。

### 3. 最后有进位时没有补节点

例如：

```text
[9] + [1]
```

最终必须得到：

```text
[0,1]
```

所以循环条件一定要把 `carry` 算进去。

### 4. 某一条链表走完后没有按 `0` 处理

这会导致长度不同的链表不能正确相加。

### 5. 误以为可以直接复用原链表节点

这题通常要创建新节点，
因为结果每一位是重新计算出来的。

## 一句话总结

这道题的关键不是把链表转成整数，而是：

**直接按链表的逆序存储方式，从低位开始模拟加法，逐位处理并维护进位。**
