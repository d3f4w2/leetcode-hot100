# 021. 合并两个有序链表

## 所属专题

- 链表

## 题目描述

将两个升序链表合并为一个新的 **升序** 链表并返回。

新链表是通过拼接给定的两个链表的所有节点组成的。

## 示例

### 示例 1

```text
输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]
```

### 示例 2

```text
输入：l1 = [], l2 = []
输出：[]
```

### 示例 3

```text
输入：l1 = [], l2 = [0]
输出：[0]
```

## 题意理解

这道题给了我们两个：

- 已经按升序排好的链表

要求把它们合成一个新的升序链表。

这里最关键的信息是：

- 两个链表本身已经各自有序

这意味着我们不需要“重新排序全部节点”，
而是可以像合并两个有序序列那样：

- 每次比较两个链表当前节点的值
- 把较小的那个接到结果链表后面

直到某一边为空为止。

题目本质上不是让我们创建一堆新节点，
而是让我们把原有节点按顺序重新串起来。

## 最直接的想法：按顺序模拟合并

这道题最直接的想法，其实就是“模拟”。

具体来说：

- 用两个指针分别指向两个链表当前的位置
- 每次比较它们的值
- 谁小，就把谁接到答案链表的末尾
- 然后把对应指针往后移动一格

因为两个链表本来就有序，
所以每次只要在两个当前节点里选较小的那个，
就能保证结果链表仍然有序。

这道题很特别的一点是：

- “最直接的想法”本身就是最优解

不需要像有些题那样先讲一个 `O(n^2)` 的暴力解，
因为这里顺着题意模拟，就是正确而高效的做法。

## 优化思路：双指针 + 虚拟头节点

虽然核心思路很直接，
但真正写代码时有一个非常值得掌握的技巧：

- **虚拟头节点 `dummy`**

### 为什么要有虚拟头节点

如果没有 `dummy`，
你在处理“新链表的第一个节点是谁”时，
就需要额外写很多边界判断。

例如你要区分：

- 当前是不是第一次接节点
- 新链表头节点有没有确定

这些判断会让代码变乱。

而有了 `dummy` 之后：

- 我们就假装新链表前面已经有一个占位节点
- 后面所有真实节点都统一接在它后面

这样写起来就非常整齐。

最后返回：

```text
dummy.next
```

即可。

### 双指针分别表示什么

我们通常用：

- `l1` 指向链表 1 当前节点
- `l2` 指向链表 2 当前节点
- `curr` 指向新链表当前的尾节点

也就是说：

- `l1`、`l2` 负责“读”
- `curr` 负责“接”

### 每一步做什么

当 `l1` 和 `l2` 都还不为空时：

1. 比较 `l1.val` 和 `l2.val`
2. 把较小的节点接到 `curr.next`
3. 对应链表指针向后移动
4. `curr` 也向后移动一格

这个过程一直持续到：

- `l1` 为空，或者
- `l2` 为空

### 为什么剩余部分可以直接接上

当其中一个链表走完之后，
另一个链表剩下的部分本身仍然是升序的。

并且：

- 它里面所有节点都比已经接好的部分更大或相等

所以这时不需要再一个个比较，
直接把剩余链表整体接到结果链表末尾就可以。

也就是：

```python
curr.next = l1 if l1 else l2
```

## 用示例手推一遍

以示例 1 为例：

```text
l1 = [1,2,4]
l2 = [1,3,4]
```

初始状态：

- `l1` 指向值 `1`
- `l2` 指向值 `1`
- `curr` 指向 `dummy`

### 第 1 步

比较：

- `l1.val = 1`
- `l2.val = 1`

如果我们写的是：

```python
if l1.val <= l2.val:
```

那么会先接上 `l1` 这个 `1`。

结果链表现在是：

```text
1
```

然后：

- `l1` 移动到 `2`
- `curr` 移动到刚接上的这个节点

### 第 2 步

现在比较：

- `l1.val = 2`
- `l2.val = 1`

这次 `l2` 更小，所以接上 `l2` 的 `1`。

结果链表变成：

```text
1 -> 1
```

然后：

- `l2` 移动到 `3`
- `curr` 移动到新的尾节点

### 第 3 步

比较：

- `l1.val = 2`
- `l2.val = 3`

接上 `2`。

结果链表变成：

```text
1 -> 1 -> 2
```

### 第 4 步

比较：

- `l1.val = 4`
- `l2.val = 3`

接上 `3`。

结果链表变成：

```text
1 -> 1 -> 2 -> 3
```

### 第 5 步

比较：

- `l1.val = 4`
- `l2.val = 4`

按 `<=` 的写法，先接上 `l1` 的 `4`。

结果链表变成：

```text
1 -> 1 -> 2 -> 3 -> 4
```

### 第 6 步

这时：

- `l1` 已经空了
- `l2` 还剩一个 `4`

于是把 `l2` 剩余部分直接接到结果链表末尾。

最终结果：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4
```

## 为什么这样写

这道题看起来简单，但里面有几个非常值得记住的点。

### 1. 两个链表有序，是整个解法成立的基础

如果两个链表不是有序的，
那你就不能每次只比较头节点。

正因为它们已经各自升序，
当前两个头节点里较小的那个，
一定就是所有剩余节点里应该最先放入结果链表的。

### 2. `dummy` 能极大简化边界处理

很多链表题都会用到虚拟头节点。

它最大的作用是：

- 把“第一个节点”和“后续节点”的处理统一起来

这样你就不需要单独去判断：

- 结果链表头节点是不是还没创建

### 3. 剩余部分可以整体接上

这是因为：

- 前面合并过程已经保证结果链表始终有序
- 剩余那一段本身又是有序的

所以没有必要再继续逐个比较。

### 4. 这道题通常是“复用原节点”，不是“重建节点”

也就是说，
我们一般不是新建一条全新的链表，
而是直接调整原节点之间的 `next` 指向。

这也是为什么额外空间可以做到 `O(1)`。

## 算法步骤

1. 创建一个虚拟头节点 `dummy`
2. 用指针 `curr` 指向 `dummy`
3. 当 `l1` 和 `l2` 都不为空时：
   - 比较 `l1.val` 和 `l2.val`
   - 把较小的节点接到 `curr.next`
   - 对应链表指针后移
   - `curr` 后移
4. 循环结束后，说明至少有一个链表为空
5. 将剩余那个链表整体接到 `curr.next`
6. 返回 `dummy.next`

## 复杂度分析

### 时间复杂度

`O(n + m)`

其中：

- `n` 是链表 `l1` 的长度
- `m` 是链表 `l2` 的长度

原因：

- 每个节点最多只会被访问并接入结果链表一次

### 空间复杂度

`O(1)`

原因：

- 只使用了几个额外指针变量
- 没有新建与输入规模相关的额外存储空间

说明：

- 这里不把返回结果链表本身算作额外空间
- `dummy` 只是一个常数级辅助节点

## Python 参考实现（详细注释）

```python
from typing import Optional


# LeetCode 平台会提供 ListNode 定义。
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next


class Solution:
    def mergeTwoLists(
        self,
        l1: Optional[ListNode],
        l2: Optional[ListNode]
    ) -> Optional[ListNode]:
        # dummy 是虚拟头节点，用来统一处理头节点和后续节点的连接逻辑。
        dummy = ListNode(0)

        # curr 始终指向当前结果链表的末尾。
        curr = dummy

        # 只要两个链表都还有节点，就继续比较并合并。
        while l1 and l2:
            # 谁的值更小，就先接谁。
            if l1.val <= l2.val:
                curr.next = l1
                l1 = l1.next
            else:
                curr.next = l2
                l2 = l2.next

            # 每接上一个节点，curr 都要跟着后移。
            curr = curr.next

        # 走到这里，说明至少有一个链表已经空了。
        # 剩下那个链表本身已经有序，可以直接整体接上。
        curr.next = l1 if l1 else l2

        # dummy 自己只是占位节点，真正答案从 dummy.next 开始。
        return dummy.next
```

## 这段代码最值得记住的地方

你在自己手写的时候，重点记住下面这条主线：

```python
dummy = ListNode(0)
curr = dummy

while l1 and l2:
    if l1.val <= l2.val:
        curr.next = l1
        l1 = l1.next
    else:
        curr.next = l2
        l2 = l2.next
    curr = curr.next

curr.next = l1 if l1 else l2
return dummy.next
```

本质上就是一句话：

**用两个链表指针不断比较当前节点，把较小节点接到结果链表尾部，最后把剩余部分整体接上。**

## 常见错误

### 1. 忘记使用 `dummy`，导致头节点处理很乱

虽然不用 `dummy` 也能写，
但初学时非常容易把：

- 第一个节点
- 后续节点

写成两套逻辑。

### 2. 接完节点后忘记移动 `curr`

如果少了：

```python
curr = curr.next
```

结果链表就不能正确向后延伸。

### 3. 循环结束后忘记接上剩余链表

当某一边先走完时，
另一边剩余节点不能丢掉，
必须整体挂到结果链表后面。

### 4. 返回了 `dummy` 而不是 `dummy.next`

`dummy` 只是一个占位节点，
题目真正要的是它后面的链表。

### 5. 把链表节点值取出来重建新链表

这样虽然也可能做出来，
但没有利用好题目“原节点可直接拼接”的特点。

## 一句话总结

这道题的关键不是“重新排序链表”，而是：

**利用两个有序链表本身已经有序这一点，用双指针按顺序拼接节点，再用虚拟头节点把边界处理统一起来。**
