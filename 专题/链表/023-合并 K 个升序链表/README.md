# 023. 合并 K 个升序链表

## 所属专题

- 链表

## 题目描述

给你一个链表数组 `lists`，
每个链表都已经按升序排列。

请你将所有链表合并到一个升序链表中，
并返回合并后的链表。

## 示例

### 示例 1

```text
输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
```

### 示例 2

```text
输入：lists = []
输出：[]
```

### 示例 3

```text
输入：lists = [[]]
输出：[]
```

## 题意理解

这道题可以看成：

- `021. 合并两个有序链表` 的升级版

之前我们只需要合并两条有序链表，
现在变成了：

- 一次要合并 `k` 条有序链表

最重要的信息仍然是：

- **每条链表本身已经有序**

所以这题不是让我们把所有节点打乱后重新排序，
而是要想办法：

- 高效地从这 `k` 条链表里
- 每次拿出当前最小的那个节点

只要我们能持续做到这一点，
最后拼出来的结果链表自然就是升序的。

## 最直接的想法：把所有节点取出来再排序

最容易想到的方法是：

1. 遍历所有链表
2. 把所有节点值取出来放进数组
3. 对数组排序
4. 再重新建一条新链表

这个方法当然能做出来，
但不够好，原因有两个：

### 1. 没有利用“每条链表已经有序”

题目明明已经告诉我们：

- 每条链表都是升序的

如果还是把所有值摊平后统一排序，
等于浪费了这个信息。

### 2. 额外操作比较多

你不仅要：

- 收集所有值
- 排序

还要：

- 重新创建整条结果链表

所以虽然能做，
但不是这题最值得掌握的思路。

## 优化思路：最小堆

这道题最经典的做法之一就是：

- **优先队列 / 最小堆**

### 核心想法

我们不需要一次看到所有节点，
只需要关心：

- 每条链表当前的头节点

因为每条链表本身有序，
所以：

- 某条链表里，当前头节点一定是这条链表里最小的未处理节点

那么如果我们把：

- 所有链表的头节点

统一放进一个最小堆里，
堆顶元素就一定是：

- 当前所有候选节点中的最小值

这样我们每次弹出堆顶，
接到结果链表后面，
就能保证结果始终有序。

### 弹出一个节点后为什么只需要放它的下一个节点

假设某条链表当前弹出了节点 `node`。

由于这条链表本身是升序的，
那么 `node.next` 就是这条链表接下来最小的未处理节点。

所以：

- 不需要把整条链表剩余部分都放进堆
- 只需要把 `node.next` 放进去即可

这样堆里始终只维护：

- 每条链表当前“最靠前”的那个候选节点

## 为什么最小堆特别适合这题

这题的本质很像：

- 有 `k` 个有序来源
- 每次都要从这 `k` 个来源里选出当前最小值

而最小堆最擅长的就是：

- 动态维护一组元素里的最小值

并且这里堆的大小最多只有：

- `k`

所以每次入堆、出堆的代价都是：

`O(log k)`

如果总共有 `n` 个节点，
那么总复杂度就是：

`O(n log k)`

这正是这道题非常理想的复杂度。

## 用示例手推一遍

以：

```text
lists = [[1,4,5],[1,3,4],[2,6]]
```

为例。

三条链表分别是：

```text
L1 = 1 -> 4 -> 5
L2 = 1 -> 3 -> 4
L3 = 2 -> 6
```

### 第 1 步：先把每条链表的头节点放入最小堆

放进去的是：

- `1`（来自 `L1`）
- `1`（来自 `L2`）
- `2`（来自 `L3`）

此时堆顶最小值是：

```text
1
```

### 第 2 步：弹出堆顶 `1`

把它接到结果链表后面。

结果链表现在是：

```text
1
```

这个 `1` 来自 `L1`，
所以还要把它的下一个节点 `4` 放进堆。

现在堆里是：

- `1`（来自 `L2`）
- `2`（来自 `L3`）
- `4`（来自 `L1`）

### 第 3 步：继续弹出堆顶 `1`

结果链表变成：

```text
1 -> 1
```

这个 `1` 来自 `L2`，
把它的下一个节点 `3` 放进堆。

堆里现在是：

- `2`
- `3`
- `4`

### 第 4 步：弹出 `2`

结果链表变成：

```text
1 -> 1 -> 2
```

它来自 `L3`，
所以把 `6` 放进堆。

堆里现在是：

- `3`
- `4`
- `6`

### 后面继续重复

依次弹出：

- `3`
- `4`
- `4`
- `5`
- `6`

最终得到：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

## 为什么堆里要放三元组

Python 的 `heapq` 在比较元素时，
如果你直接放链表节点对象，
通常会报错，
因为它不知道两个 `ListNode` 该怎么比较大小。

所以常见做法是放：

```python
(node.val, i, node)
```

这三个值分别表示：

- `node.val`：节点值，用来决定大小
- `i`：来自第几条链表，用来在值相同时打破平局
- `node`：真正的节点对象

为什么需要 `i`？

因为如果两个节点值相同，
比如都是 `1`，
Python 会继续比较元组的下一项。

如果没有 `i`，
它就会尝试直接比较两个 `ListNode`，
这通常是不被支持的。

所以加上 `i` 以后，
堆比较就稳定了。

## 为什么这样写

### 1. 每条链表的头节点就是该链表当前最小值

因为每条链表升序，
所以你不需要看整条链表，
只看头节点就够了。

### 2. 堆顶就是所有候选节点中的最小值

把所有当前候选节点放进最小堆后，
每次弹出的都是最小值，
因此可以安全接到结果链表末尾。

### 3. 弹出一个节点后，只补它的下一个节点

因为这一条链表里，
被弹出节点后面的第一个节点，
就是新的候选最小值。

这样既不会漏，
也不会重复。

### 4. `dummy` 依然能简化链表拼接

和很多链表题一样，
这里也建议使用：

- 虚拟头节点 `dummy`

这样不用专门讨论：

- 第一个节点怎么接
- 后续节点怎么接

逻辑会统一很多。

## 算法步骤

1. 如果 `lists` 为空，直接返回 `None`
2. 创建最小堆 `heap`
3. 遍历 `lists`，把所有非空链表的头节点放进堆
4. 创建虚拟头节点 `dummy`
5. 用指针 `current` 指向结果链表末尾
6. 当堆不为空时：
   - 弹出堆顶最小节点
   - 把它接到结果链表后面
   - 如果它还有下一个节点，就把下一个节点再放进堆
7. 堆空时，说明所有节点都处理完成
8. 返回 `dummy.next`

## 复杂度分析

### 时间复杂度

`O(n log k)`

其中：

- `n` 是所有链表节点总数
- `k` 是链表数量

原因是：

- 每个节点都会入堆一次、出堆一次
- 每次堆操作的代价是 `O(log k)`

### 空间复杂度

`O(k)`

原因是：

- 堆里最多同时存放 `k` 个节点

不把结果链表本身算入额外空间。

## Python 参考实现（最小堆）

```python
import heapq
from typing import List, Optional


# LeetCode 平台会提供 ListNode 定义。
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next


class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        heap = []

        # 把每条非空链表的头节点放进最小堆。
        for i, node in enumerate(lists):
            if node:
                heapq.heappush(heap, (node.val, i, node))

        dummy = ListNode(0)
        current = dummy

        while heap:
            val, idx, node = heapq.heappop(heap)

            current.next = node
            current = current.next

            if node.next:
                heapq.heappush(heap, (node.next.val, idx, node.next))

        return dummy.next
```

## 还有一种经典做法：分治

这道题除了最小堆，
还可以用：

- 分治法

思路是把 `k` 条链表不断拆成两半，
最后转化成多次“合并两个有序链表”。

它的时间复杂度同样也是：

`O(n log k)`

所以你可以把这题理解成有两种主流高质量解法：

- 最小堆
- 分治

如果你想练：

- 堆结构，就优先记最小堆
- 链表递归 / 归并思想，就优先记分治

## 常见错误

### 1. 直接把节点对象放进堆

如果写成：

```python
heapq.heappush(heap, node)
```

通常会出问题，
因为 `ListNode` 默认不能直接比较大小。

### 2. 值相同时没有处理“第二关键字”

如果只放：

```python
(node.val, node)
```

当 `node.val` 相同时，
Python 还是会去比较 `node`，
依然可能报错。

所以更稳妥的是：

```python
(node.val, i, node)
```

### 3. 忘记把弹出节点的下一个节点重新入堆

如果少了这一步，
那条链表后面的部分就丢了。

### 4. 忘记处理空输入

例如：

```python
lists = []
```

或者：

```python
lists = [[]]
```

都应该正确返回空链表。

### 5. 返回了 `dummy` 而不是 `dummy.next`

`dummy` 只是占位节点，
真正答案从 `dummy.next` 开始。

## 适合你自己默写的精简版本

```python
import heapq


class Solution:
    def mergeKLists(self, lists):
        heap = []

        for i, node in enumerate(lists):
            if node:
                heapq.heappush(heap, (node.val, i, node))

        dummy = ListNode(0)
        current = dummy

        while heap:
            _, idx, node = heapq.heappop(heap)
            current.next = node
            current = current.next

            if node.next:
                heapq.heappush(heap, (node.next.val, idx, node.next))

        return dummy.next
```

## 一句话总结

这道题的关键是：

**用最小堆维护每条链表当前的头节点，每次取出全局最小节点接到结果链表后面，再把它的下一个节点放回堆里，这样就能以 `O(n log k)` 的复杂度完成合并。**
