# 023. 合并 K 个升序链表

## 所属专题

- 链表

## 题目描述

给你一个链表数组 `lists`，每个链表都已经按升序排列。

请你将所有链表合并到一个升序链表中，
返回合并后的链表。

## 示例

### 示例 1

```text
输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
解释：链表数组如下：
[
  1->4->5,
  1->3->4,
  2->6
]
将它们合并到一个有序链表中得到：
1->1->2->3->4->4->5->6
```

### 示例 2

```text
输入：lists = []
输出：[]
```

### 示例 3

```text
输入：lists = [[]]
输出：[]
```

## 题意理解

这道题可以看成：

- `021. 合并两个有序链表` 的升级版

在 `021` 里，
我们只需要合并两个有序链表。

而这道题变成了：

- 给你 `k` 个有序链表
- 要把它们全部合成一个有序链表

最重要的信息还是：

- **每个链表本身已经有序**

所以问题的关键不在于“怎么排序所有节点”，
而在于：

**怎么高效地把很多条已经排好序的链表合并起来。**

这道题如果直接硬做，
很容易写出能过但不够高效的方法。

因此它的核心在于：

- 利用“有序”这个性质
- 减少重复比较

## 最直接的想法：按顺序一个一个合并

最容易想到的方法是：

- 先把第 `1` 条链表和第 `2` 条链表合并
- 得到一个新链表后
- 再和第 `3` 条链表合并
- 再和第 `4` 条链表合并
- 一直重复，直到全部合完

也就是说：

```text
(((list1 + list2) + list3) + list4) + ...
```

这个思路完全可行，
而且如果你已经写过 `021`，
这题会很自然地想到复用“合并两个链表”的函数。

### 这个方法为什么不够好

问题在于：

- 前面合并出来的长链表，
  后面还会被反复重新遍历和比较

比如：

- 第一轮刚合并好的结果长度可能已经很长了
- 下一轮又要拿这条长链表去和下一条链表比较

这样会造成很多重复工作。

如果总节点数是 `n`，链表数量是 `k`，
这种顺序合并的做法在最坏情况下会接近：

`O(nk)`

当 `k` 很大时，效率就不够理想。

所以我们要继续想：

**能不能像归并排序那样，成对地合并，避免一条大链表被反复拿来和后面的链表逐个比较？**

## 优化思路一：分治法

这是这道题最经典、也最适合和 `021` 联动理解的做法。

### 核心想法

不要按顺序一条一条地合并，
而是：

- 先把 `k` 个链表分成左右两半
- 分别把左边合并成一条链表
- 再把右边合并成一条链表
- 最后把左右两条结果链表再合并起来

这其实就是“分治”的思想。

和归并排序非常像：

- 先拆分
- 再合并

### 为什么分治会更高效

因为它让每个节点参与比较的层数变少了。

更准确地说：

- 每一层分治，所有节点总共只会被处理一遍
- 一共大约有 `log k` 层

所以总时间复杂度就是：

`O(n log k)`

这里：

- `n` 是所有链表节点总数
- `k` 是链表数量

这比顺序合并的 `O(nk)` 要好得多。

### 分治里最关键的复用点

分治的本质并不是发明了新的合并方式，
而是：

- 把“大问题：合并 k 个链表”
- 变成“小问题：合并两个链表”

而“合并两个链表”这件事，
正是 `021` 已经解决过的内容。

所以这题最自然的写法是：

1. 写一个 `mergeTwoLists(l1, l2)`
2. 再写一个 `mergeKLists(lists)` 递归处理数组区间

### 递归过程是怎样的

假设有 4 条链表：

```text
[L1, L2, L3, L4]
```

分治会这样做：

```text
先合并 [L1, L2] -> A
再合并 [L3, L4] -> B
最后合并 A 和 B
```

如果链表更多，
就继续往下拆分，直到：

- 空数组，返回 `None`
- 只剩一条链表，直接返回它自己

## 也可以怎么做：优先队列（最小堆）

这道题还有一种非常经典的做法：

- 用最小堆维护当前每条链表的头节点

具体过程是：

1. 先把所有非空链表的头节点放入最小堆
2. 每次取出堆顶最小节点
3. 把它接到结果链表末尾
4. 如果这个节点还有下一个节点，就把下一个节点再放回堆里
5. 重复直到堆空

这个方法的时间复杂度同样是：

`O(n log k)`

因为：

- 堆里最多同时有 `k` 个节点
- 每个节点都会进堆、出堆一次

不过如果是当前这份题解风格，
以及你前面已经做过 `021`，
那么分治法会更自然，
更适合串联已有知识点。

所以这里把：

- **分治法** 作为主讲解法
- **最小堆** 作为补充理解

## 用示例手推一遍

以示例 1 为例：

```text
lists = [[1,4,5],[1,3,4],[2,6]]
```

也就是三条链表：

```text
L1 = 1 -> 4 -> 5
L2 = 1 -> 3 -> 4
L3 = 2 -> 6
```

### 如果用顺序合并

第一步：

- 先合并 `L1` 和 `L2`

得到：

```text
1 -> 1 -> 3 -> 4 -> 4 -> 5
```

第二步：

- 再把上面的结果和 `L3` 合并

得到最终答案：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

这个例子规模小，
看起来问题不大。

但如果链表数量很多，
这样做就会不断反复处理已经很长的结果链表。

### 如果用分治法

这 3 条链表可以理解成：

- 左半边：`[L1]`
- 右半边：`[L2, L3]`

先处理右半边：

- 合并 `L2` 和 `L3`

得到：

```text
1 -> 2 -> 3 -> 4 -> 6
```

然后再把它和 `L1` 合并：

```text
L1 = 1 -> 4 -> 5
R  = 1 -> 2 -> 3 -> 4 -> 6
```

逐步比较后得到：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

最终答案就是：

```text
[1,1,2,3,4,4,5,6]
```

## 为什么这样写

### 1. 这题本质上是在反复做 `021`

无论是顺序合并、分治法，还是堆做法，
核心都离不开一个基本操作：

- 合并两条有序链表

所以如果 `021` 真的理解透了，
这题只是把“两条”扩展成了“很多条”。

### 2. 分治法避免了一条长链表被反复处理

顺序合并的问题在于：

- 前面合出来的长链表，后面还要继续参加很多轮合并

而分治法尽量让：

- 长度相近的链表先合并
- 每个节点在每一层只处理一次

所以整体更均衡，也更高效。

### 3. `dummy` 节点依然很重要

虽然现在是合并很多条链表，
但最底层的“合并两条链表”仍然建议使用：

- 虚拟头节点 `dummy`

因为它能统一处理：

- 第一个接入的节点
- 后续接入的节点

让代码干净很多。

### 4. 空数组和空链表都要单独想清楚

例如：

- `lists = []`
- `lists = [[]]`

这两种情况都应该返回 `None`。

所以递归的边界和空输入处理都很关键。

## 算法步骤

### 分治法步骤

1. 如果 `lists` 为空，直接返回 `None`
2. 如果 `lists` 只剩一条链表，直接返回它
3. 把 `lists` 从中间分成左右两半
4. 递归地合并左半部分，得到 `left`
5. 递归地合并右半部分，得到 `right`
6. 调用“合并两个有序链表”的函数，把 `left` 和 `right` 合并
7. 返回合并结果

### 合并两条链表步骤

1. 建立虚拟头节点 `dummy`
2. 用指针 `curr` 指向结果链表当前末尾
3. 同时遍历两条链表
4. 每次把较小节点接到 `curr.next`
5. 对应链表指针后移
6. `curr` 后移
7. 一条链表结束后，把另一条剩余部分整体接上
8. 返回 `dummy.next`

## 复杂度分析

### 时间复杂度

#### 分治法

`O(n log k)`

原因：

- 每一层合并时，所有节点总共会被遍历一遍
- 一共有大约 `log k` 层

其中：

- `n` 是所有链表中的节点总数
- `k` 是链表数量

#### 顺序合并

最坏情况下接近 `O(nk)`

因为前面形成的长链表会被后续反复参与合并。

#### 最小堆

`O(n log k)`

因为每个节点都会进行一次入堆和出堆操作，
而堆的大小最多为 `k`。

### 空间复杂度

#### 分治法

如果只计算额外辅助结构，
合并本身不需要额外链表数组，
但递归会带来调用栈开销。

因此通常写作：

`O(log k)`

如果题目只强调除了递归栈外不额外开结构，
也有人会口语化地说“合并过程本身接近 `O(1)` 额外空间”，
但严格来说要把递归栈算进去。

#### 最小堆

`O(k)`

因为堆中最多同时存放 `k` 个节点。

## Python 参考实现（详细注释）

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next


class Solution:
    def mergeKLists(self, lists):
        # 如果链表数组为空，直接返回空链表。
        if not lists:
            return None

        # 调用分治函数，合并整个区间。
        return self.merge_range(lists, 0, len(lists) - 1)

    def merge_range(self, lists, left, right):
        # 区间为空时，不存在链表可合并。
        if left > right:
            return None

        # 区间里只有一条链表时，直接返回它本身。
        if left == right:
            return lists[left]

        mid = (left + right) // 2

        # 分别合并左半部分和右半部分。
        left_merged = self.merge_range(lists, left, mid)
        right_merged = self.merge_range(lists, mid + 1, right)

        # 再把两边合并成一条链表。
        return self.merge_two_lists(left_merged, right_merged)

    def merge_two_lists(self, l1, l2):
        # 虚拟头节点，方便统一处理结果链表。
        dummy = ListNode(0)
        curr = dummy

        # 只要两条链表都还有节点，就不断比较当前值。
        while l1 and l2:
            if l1.val <= l2.val:
                curr.next = l1
                l1 = l1.next
            else:
                curr.next = l2
                l2 = l2.next

            curr = curr.next

        # 把还没走完的那条链表整体接到后面。
        curr.next = l1 if l1 else l2

        return dummy.next
```

## 常见错误

### 1. 直接把所有节点取出来排序

这样当然能做，
但就没有利用“每条链表本身已经有序”这一点。

这道题更想考的是：

- 合并有序链表
- 分治或堆

而不是把所有节点摊平后重新排序。

### 2. 顺序合并写出来了，但以为它已经是最优解

顺序合并是对的，
但当 `k` 很大时不够高效。

要意识到：

- “能做出来”
- 和“复杂度最优”

不是一回事。

### 3. 忘记处理 `lists` 为空的情况

如果：

```python
lists = []
```

就应该直接返回 `None`。

### 4. 合并两条链表时没有用 `dummy`

这样会导致：

- 第一个节点的接法
- 后续节点的接法

需要分开讨论，代码更容易乱。

### 5. 递归边界写错

例如：

- 没处理 `left > right`
- 或者 `left == right` 时没有直接返回

都会导致递归出错。

## 适合自己默写的精简版本

```python
class Solution:
    def mergeKLists(self, lists):
        if not lists:
            return None

        def merge_two(l1, l2):
            dummy = ListNode(0)
            curr = dummy

            while l1 and l2:
                if l1.val <= l2.val:
                    curr.next = l1
                    l1 = l1.next
                else:
                    curr.next = l2
                    l2 = l2.next
                curr = curr.next

            curr.next = l1 if l1 else l2
            return dummy.next

        def divide(left, right):
            if left > right:
                return None
            if left == right:
                return lists[left]

            mid = (left + right) // 2
            return merge_two(divide(left, mid), divide(mid + 1, right))

        return divide(0, len(lists) - 1)
```

## 一句话总结

这道题的关键是把“合并 k 条有序链表”拆成多次“合并两条有序链表”，并通过分治把复杂度从顺序合并的较低效率优化到 `O(n log k)`。
