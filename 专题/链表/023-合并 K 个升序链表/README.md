# 023. 合并 K 个升序链表

## 所属专题
- 链表
- 分治
- 堆

## 题目描述

给你一个链表数组 `lists`，每个链表都已经按升序排列。
请你将所有链表合并到一个升序链表中，并返回合并后的链表。

## 示例

### 示例 1

```text
输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
```

### 示例 2

```text
输入：lists = []
输出：[]
```

### 示例 3

```text
输入：lists = [[]]
输出：[]
```

## 题意理解

这道题可以看成：

- `021. 合并两个有序链表` 的升级版

之前我们只需要合并两条有序链表，现在变成一次要合并 `k` 条有序链表。
关键仍然是：

- 每条链表本身已经有序

所以这题的重点不是重新排序所有节点，而是想办法高效地利用“每条链表有序”这个条件。

## 主解法：分治合并

这份仓库里的 `23.py` 使用的是 **分治**。

核心思路是：

- 如果只剩 1 条链表，直接返回
- 如果有多条链表，就把它们从中间拆成左右两部分
- 先分别合并左半部分和右半部分
- 最后再把两条大链表合并起来

这样就把“合并 k 条链表”转化成了很多次“合并两条有序链表”。

而“合并两条有序链表”我们已经很熟悉了：

- 用两个指针比较当前节点
- 谁小就接到结果链表后面
- 最后把剩余部分直接接上

## 为什么分治适合这题

如果我们按顺序一条一条合并：

- 先合并第 1 条和第 2 条
- 再把结果和第 3 条合并
- 再和第 4 条合并

虽然也能做出来，但前面已经合并出来的长链表会被反复扫描，效率不够好。

分治的好处是：

- 每一层都尽量让链表长度更均衡
- 每个节点在每一层只会参与一次合并
- 总层数大约是 `log k`

所以总时间复杂度可以做到：

`O(n log k)`

其中：

- `n` 是所有链表节点总数
- `k` 是链表个数

## 用示例手推一遍

```text
lists = [[1,4,5],[1,3,4],[2,6]]
```

把它们记成：

```text
L1 = 1 -> 4 -> 5
L2 = 1 -> 3 -> 4
L3 = 2 -> 6
```

### 第一步：分成左右两部分

```text
左边：L1, L2
右边：L3
```

### 第二步：先合并左边

合并 `L1` 和 `L2`：

```text
1 -> 1 -> 3 -> 4 -> 4 -> 5
```

### 第三步：再和右边合并

把上一步结果与 `L3 = 2 -> 6` 合并：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

这就是最终答案。

## 算法步骤

1. 如果 `lists` 为空，直接返回 `None`
2. 调用递归函数，在区间 `[left, right]` 内合并链表
3. 如果区间里只有一条链表，直接返回这条链表
4. 取中点 `mid`，递归合并左半部分和右半部分
5. 把左右两条合并后的链表再做一次“合并两个有序链表”
6. 返回最终结果

## Python 参考实现（与当前代码一致）

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution:
    def mergeKLists(self, lists):
        if not lists:
            return None
        return self.merge_range(lists, 0, len(lists) - 1)

    def merge_range(self, lists, left, right):
        if left > right:
            return None
        if left == right:
            return lists[left]

        mid = (left + right) // 2
        left_list = self.merge_range(lists, left, mid)
        right_list = self.merge_range(lists, mid + 1, right)
        return self.merge_two_lists(left_list, right_list)

    def merge_two_lists(self, l1, l2):
        dummy = ListNode(0)
        cur = dummy

        while l1 and l2:
            if l1.val <= l2.val:
                cur.next = l1
                l1 = l1.next
            else:
                cur.next = l2
                l2 = l2.next
            cur = cur.next

        cur.next = l1 if l1 else l2
        return dummy.next
```

## 为什么这段代码是对的

关键在于两层保证：

### 1. `merge_two_lists` 一定正确

因为两条输入链表本来就是升序的，所以每次取较小节点接到结果后面，最终得到的一定还是升序链表。

### 2. `merge_range` 一定正确

它把原问题不断拆成更小的问题：

- 小问题是“合并一部分链表”
- 最小子问题是“只剩一条链表”，显然正确
- 左半部分和右半部分都正确合并后，再调用 `merge_two_lists` 合并起来

因此整个递归过程是正确的。

## 复杂度分析

### 时间复杂度

`O(n log k)`

原因：

- 每一层递归都会把所有节点合并一遍，总量是 `O(n)`
- 递归层数大约是 `O(log k)`

所以总时间复杂度是：

`O(n log k)`

### 空间复杂度

`O(log k)`

原因：

- 主要来自递归调用栈
- `merge_two_lists` 本身只用了常数级额外指针

## 补充解法：最小堆

你提供的思路也是这题非常经典的解法。

核心做法是：

- 把每条链表的头节点放进最小堆
- 每次弹出堆顶最小节点，接到答案后面
- 如果这个节点还有下一个节点，就把下一个节点继续放进堆
- 直到堆为空

这个方法的本质是：

- 堆里始终维护“每条链表当前最靠前的候选节点”
- 每次都能快速拿到全局最小值

它的复杂度同样是：

- 时间复杂度：`O(n log k)`
- 空间复杂度：`O(k)`

如果你在面试里先想到最小堆，这是完全正确而且很常见的解法。

## 常见错误

### 1. 忘记处理空输入

比如：

```text
lists = []
```

这种情况应该直接返回空链表。

### 2. 递归边界写错

在分治里要注意：

- `left > right` 返回 `None`
- `left == right` 返回 `lists[left]`

这两个边界都不能漏。

### 3. 合并两条链表时漏接剩余部分

当某一条链表先走完时，另一条链表剩下的部分可以直接接到结果后面：

```python
cur.next = l1 if l1 else l2
```

### 4. 把返回值写成 `dummy`

真正答案是：

```python
dummy.next
```

因为 `dummy` 只是辅助头节点。

## 一句话总结

这道题的核心就是：

**把“合并 K 条有序链表”拆成多次“合并两条有序链表”，用分治把整体复杂度控制在 `O(n log k)`；同时也要知道，最小堆也是这题同样经典的标准解法。**
