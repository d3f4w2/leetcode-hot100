# 206. 反转链表

## 所属专题
- 链表

## 题目描述

给你单链表的头节点 `head`，请你反转链表，并返回反转后的链表。

也就是说，原来链表的方向是：

```text
1 -> 2 -> 3 -> 4 -> 5 -> None
```

反转之后要变成：

```text
5 -> 4 -> 3 -> 2 -> 1 -> None
```

## 示例

### 示例 1

```text
输入：head = [1,2,3,4,5]
输出：[5,4,3,2,1]
```

### 示例 2

```text
输入：head = [1,2]
输出：[2,1]
```

### 示例 3

```text
输入：head = []
输出：[]
```

## 题意理解

这道题不是让我们把链表的值倒过来输出，
而是要真正修改链表节点之间的指向关系。

也就是说：

- 不是把值抄出来再倒序放回去
- 而是把每个节点的 `next` 指针反过来

比如原来：

```text
1 -> 2 -> 3 -> None
```

反转后应该是：

```text
3 -> 2 -> 1 -> None
```

这意味着：

- 原来 `1.next = 2`
- 反转后要变成 `2.next = 1`

所以这道题的核心不是“遍历链表”，
而是：

**在遍历过程中，小心地修改每个节点的指针方向。**

## 最直接的想法：把节点值取出来再反着重建

最容易想到的方法是：

- 先遍历链表
- 把所有节点值存进数组
- 再倒序生成一个新链表

这样当然也能得到反转后的结果。

但问题在于：

- 额外用了一个数组
- 甚至还可能新建了一整条链表
- 没有抓住这道题真正想考的“链表指针操作”

所以我们更应该考虑：

**能不能只用常数额外空间，直接原地把链表反转？**

## 优化思路：迭代法

### 核心想法

遍历链表时，把当前节点的 `next` 指针改成指向前一个节点。

为了做到这一点，我们需要同时知道三件事：

- 当前节点是谁
- 当前节点原来的下一个节点是谁
- 当前节点反转后要指向谁

所以通常会用三个指针：

- `prev`：前一个节点
- `curr`：当前节点
- `next_node`：当前节点原本的下一个节点

### 三个指针分别在干什么

#### `curr`

表示当前正在处理的节点。

#### `prev`

表示反转后，当前节点应该指向的那个节点。

一开始：

- `prev = None`

因为原链表的头节点反转后会变成尾节点，
而尾节点应该指向 `None`。

#### `next_node`

这个变量非常关键。

因为一旦你执行：

```python
curr.next = prev
```

当前节点原来的后继就断开了。

如果不提前保存 `curr.next`，
你就再也找不到后面的链表了。

所以必须先记住：

```python
next_node = curr.next
```

### 每一步到底做什么

对于当前节点 `curr`：

1. 先保存原来的下一个节点 `next_node = curr.next`
2. 反转指针，让 `curr.next = prev`
3. 移动 `prev = curr`
4. 移动 `curr = next_node`

这个顺序不能乱。

尤其是：

- 一定要先保存 `curr.next`
- 再修改 `curr.next`

否则后面的链表会丢失。

## 用示例手推一遍

以：

```text
head = [1,2,3,4,5]
```

为例。

初始时：

- `prev = None`
- `curr = 1`

原链表是：

```text
1 -> 2 -> 3 -> 4 -> 5 -> None
```

### 第 1 步：处理节点 `1`

先保存：

- `next_node = 2`

然后反转：

- `1.next = None`

此时局部变成：

```text
1 -> None
```

再移动指针：

- `prev = 1`
- `curr = 2`

### 第 2 步：处理节点 `2`

先保存：

- `next_node = 3`

然后反转：

- `2.next = 1`

现在已经反转好的部分是：

```text
2 -> 1 -> None
```

再移动：

- `prev = 2`
- `curr = 3`

### 第 3 步：处理节点 `3`

同理：

- 保存 `4`
- 让 `3.next = 2`

得到：

```text
3 -> 2 -> 1 -> None
```

### 后面继续重复

最后会得到：

```text
5 -> 4 -> 3 -> 2 -> 1 -> None
```

当循环结束时：

- `curr = None`
- `prev` 正好指向新的头节点 `5`

所以最终返回：

- `prev`

## 为什么这样写

### 1. 链表不能像数组那样直接倒着访问

数组可以通过下标从后往前看，
但单链表只能顺着 `next` 往后走。

所以反转链表的关键不在于“逆序访问”，
而在于“逐个改指针方向”。

### 2. `prev` 表示“已经反转好的链表头”

每处理完一个节点，
就把它接到 `prev` 前面。

这样：

- `prev` 始终指向已经反转好的那一段链表

### 3. `next_node` 是为了防止链表断掉

这是整道题最关键的细节。

如果你先改了：

```python
curr.next = prev
```

却没有提前保存原来的下一个节点，
那后面的链表就找不回来了。

### 4. 最后返回的是 `prev`，不是 `head`

循环结束时：

- 原来的 `head` 已经变成尾节点了
- 新的头节点是最后一次处理过的那个节点
- 也就是 `prev`

## 算法步骤

1. 定义两个主要指针：`prev = None`、`curr = head`
2. 当 `curr` 不为空时，开始遍历链表
3. 先保存 `curr` 原来的下一个节点
4. 把 `curr.next` 改成指向 `prev`
5. 将 `prev` 向前移动到 `curr`
6. 将 `curr` 向前移动到原来的下一个节点
7. 循环结束后，返回 `prev`

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 只遍历了一遍链表
- 每个节点都只处理一次

### 空间复杂度

`O(1)`

原因是：

- 只用了 `prev`、`curr`、`next_node` 这几个额外变量
- 没有使用与链表长度相关的额外空间

## Python 参考实现（详细注释）

```python
from typing import Optional


class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        curr = head

        while curr:
            next_node = curr.next
            curr.next = prev
            prev = curr
            curr = next_node

        return prev
```

## 这段代码最值得记住的地方

最核心的是这四行：

```python
next_node = curr.next
curr.next = prev
prev = curr
curr = next_node
```

它完整体现了反转链表的一次标准操作：

- 先保存后继
- 再反转当前指针
- 然后整体向前推进

你只要真正理解这四行，
这道题就基本掌握了。

## 常见错误

### 1. 先改 `curr.next`，却没有提前保存下一个节点

这是最典型的错误。

一旦直接写：

```python
curr.next = prev
```

却没先保存原来的下一个节点，
后面的链表就丢了。

### 2. 最后返回 `head`

反转后：

- 原来的 `head` 已经变成尾节点

真正的新头节点是：

- `prev`

### 3. 指针移动顺序写乱

这题不是不会写，
而是很容易把顺序写乱。

建议死记这个顺序：

- 先存后继
- 再反转指针
- 再移动 `prev`
- 再移动 `curr`

### 4. 把这题写成“交换节点值”

这道题考的是：

- 链表节点之间的连接关系

不是简单交换节点里的数值。

## 一句话总结

这道题的关键不是“倒着遍历链表”，而是：

**用 `prev`、`curr`、`next_node` 三个指针，在遍历过程中把每个节点的 `next` 方向一个个反过来。**
