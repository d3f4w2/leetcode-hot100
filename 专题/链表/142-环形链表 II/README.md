# 142. 环形链表 II

## 所属专题

- 链表

## 题目描述

给定一个链表的头节点 `head`，返回链表开始入环的第一个节点。

如果链表无环，则返回 `null`。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，
则说明链表中存在环。

为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示：

- 链表尾连接到链表中的位置（索引从 `0` 开始）

如果 `pos = -1`，则表示该链表中没有环。

需要注意的是：

- `pos` **不是函数参数**
- 它只是题目用来描述测试数据的方式

这道题真正要求我们做的是：

- 如果有环，返回**入环的第一个节点**
- 如果没有环，返回 `None`

## 示例

### 示例 1

```text
输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。
```

### 示例 2

```text
输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。
```

### 示例 3

```text
输入：head = [1], pos = -1
输出：null
解释：链表中没有环。
```

## 题意理解

这道题和 `141. 环形链表` 很像，
但要求更进一步。

`141` 只问：

- 有没有环

而这道题问的是：

- 环从哪个节点开始

也就是说，
我们不仅要知道“能不能绕圈”，
还要找到“第一次进入这个圈的位置”。

这里要特别理解：

- 返回的不是节点值
- 也不是索引数字
- 而是**那个入环节点本身**

题目里写“返回索引为 1 的链表节点”，
只是为了帮助我们理解测试数据，
真正函数返回的是节点对象。

## 最直接的想法：用哈希集合记录访问过的节点

最容易想到的方法是：

- 从头节点开始遍历链表
- 每访问一个节点，就把它放进集合中
- 如果某次发现当前节点已经出现过，
  那么这个节点就是“第一次重复进入”的节点
- 也就是环的入口节点

为什么第一次重复访问到的节点就是入口？

因为：

- 从头节点到入环前的路径都只会经过一次
- 真正开始重复时，一定是重新回到了环的入口

例如：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

遍历顺序是：

- `3`
- `2`
- `0`
- `-4`
- 再回到 `2`

这里第一次重复出现的节点就是 `2`，
所以入口就是值为 `2` 的那个节点。

这个方法思路非常直接，
而且也能在 `O(n)` 时间内完成。

但问题是：

- 需要额外使用集合记录节点
- 空间复杂度是 `O(n)`

这道题更经典的做法是：

- **先用快慢指针找到相遇点**
- **再利用数学关系找到入口**

## 优化思路：快慢指针 + 数学关系

### 第一步：先判断有没有环，并找到相遇点

定义两个指针：

- `slow`：每次走 `1` 步
- `fast`：每次走 `2` 步

如果链表无环：

- `fast` 最终会走到 `None`
- 说明不存在入口节点
- 直接返回 `None`

如果链表有环：

- `fast` 和 `slow` 一定会在环内某个位置相遇

注意：

- **这个相遇点不一定就是环入口**

它只是我们后续定位入口的起点。

### 第二步：为什么从相遇点还能找到入口

这是整道题最核心的地方。

设：

- 从头节点到环入口的距离是 `a`
- 从环入口到相遇点的距离是 `b`
- 从相遇点再走到环入口的距离是 `c`

那么环的总长度就是：

```text
b + c
```

当快慢指针第一次相遇时：

- 慢指针走了 `a + b`
- 快指针走了 `a + b + n(b + c)`

这里的 `n` 表示：

- 快指针在环里比慢指针多转了 `n` 圈

又因为快指针速度是慢指针的 `2` 倍，
所以有：

```text
2(a + b) = a + b + n(b + c)
```

化简得到：

```text
a + b = n(b + c)
```

继续整理：

```text
a = n(b + c) - b
  = (n - 1)(b + c) + c
```

这说明什么？

这说明：

- 从头节点走到环入口的距离 `a`
- 等于“从相遇点走到环入口的距离 `c`”
- 再加上若干整圈环长

而“加上若干整圈环长”并不会改变最终落点，
因为在环里多转整整一圈，
还是会回到同一个位置。

所以可以得到结论：

- 一个指针从 `head` 出发
- 另一个指针从“相遇点”出发
- 两个指针都每次走 `1` 步
- 它们最终会在**环入口**相遇

这就是第二阶段写法成立的根本原因。

## 用示例手推一遍

以示例 1 为例：

```text
head = [3,2,0,-4], pos = 1
```

链表结构是：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

环入口是值为 `2` 的节点。

### 第一阶段：找到相遇点

初始化：

- `slow = head`
- `fast = head`

#### 第 1 轮

- `slow` 走到 `2`
- `fast` 走到 `0`

#### 第 2 轮

- `slow` 走到 `0`
- `fast` 走到 `2`

#### 第 3 轮

- `slow` 走到 `-4`
- `fast` 也走到 `-4`

所以：

- 它们在 `-4` 相遇

但这里的 `-4`：

- 不是环入口
- 只是相遇点

### 第二阶段：从头节点和相遇点同时出发

现在：

- 让一个指针回到 `head`
- 另一个指针留在相遇点 `-4`

然后两个指针都每次走一步。

#### 第 1 步

- 从 `head` 出发的指针走到 `2`
- 从相遇点 `-4` 出发的指针也走到 `2`

它们此时相遇在：

- 值为 `2` 的节点

这个节点就是：

- 环的入口节点

所以最终返回该节点。

## 为什么这样写

### 1. 这题本质上是 `141` 的进阶版

先判环，
再找入口。

所以第一阶段完全沿用 `141` 的快慢指针思路。

### 2. 相遇点不是答案，但它能帮我们定位答案

很多人第一次做这题时，
会误以为：

- 快慢指针第一次相遇的地方就是入口

这其实不一定对。

真正正确的是：

- 相遇后，把一个指针移回头节点
- 两个指针同步前进
- 再次相遇的位置才是入口

### 3. 第二阶段两个指针为什么都走一步

因为我们已经通过公式证明了：

- 从头到入口的距离
- 和从相遇点到入口的距离（模环长意义下）

是对应的。

所以第二阶段必须让它们：

- 保持相同速度前进

这样才能在入口相遇。

### 4. 全程不需要额外空间

整个过程中只用了若干个指针变量，
没有使用集合、数组或字典，
所以空间复杂度是 `O(1)`。

## 算法步骤

1. 如果 `head` 为空，或者只有一个节点，直接返回 `None`
2. 定义快慢指针 `slow` 和 `fast`，都从 `head` 出发
3. 不断让 `slow` 走一步、`fast` 走两步
4. 如果 `fast` 或 `fast.next` 为空，说明无环，返回 `None`
5. 如果 `slow == fast`，说明在环内找到了相遇点
6. 让一个指针重新回到 `head`
7. 另一个指针留在相遇点
8. 两个指针都每次走一步
9. 再次相遇时，所在节点就是环入口，返回该节点

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 第一阶段用于判断是否有环并寻找相遇点
- 第二阶段用于从头节点和相遇点同步走到入口
- 两个阶段整体仍然是线性级别

### 空间复杂度

`O(1)`

原因是：

- 只使用了常数个指针变量
- 没有借助额外数据结构

## Python 参考实现（详细注释）

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None


class Solution:
    def detectCycle(self, head):
        # 如果链表为空，或者只有一个节点，
        # 那么不可能形成环。
        if not head or not head.next:
            return None

        slow = head
        fast = head

        # 第一阶段：判断是否有环，并寻找相遇点。
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            # 如果快慢指针相遇，说明链表中有环。
            if slow == fast:
                break
        else:
            # while 正常结束，说明 fast 走到了链表末尾，链表无环。
            return None

        # 第二阶段：一个指针回到头节点，
        # 另一个指针留在相遇点。
        # 两者每次都走一步，再次相遇的位置就是环入口。
        slow = head
        while slow != fast:
            slow = slow.next
            fast = fast.next

        return slow
```

## 常见错误

### 1. 误以为第一次相遇点就是环入口

这是最常见的错误。

快慢指针第一次相遇时：

- 只能说明有环
- 不能直接说明相遇点就是入口

必须再进行第二阶段同步前进。

### 2. 忘记处理无环情况

如果链表无环，
`fast` 最终会走到 `None`。

如果这时还直接进入第二阶段，
代码就会出错。

所以必须先判断：

- 有没有成功相遇

没有相遇就直接返回 `None`。

### 3. 第二阶段把两个指针都重置到头节点

如果你把两个指针都放回 `head`，
那它们当然一开始就相遇了，
这就失去了意义。

正确做法是：

- 一个回到 `head`
- 一个留在第一次相遇点

### 4. 第二阶段还让 `fast` 一次走两步

第二阶段的关键是：

- 两个指针要同速前进

所以它们都必须一次走一步。

## 适合自己默写的精简版本

```python
class Solution:
    def detectCycle(self, head):
        slow = fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow == fast:
                slow = head
                while slow != fast:
                    slow = slow.next
                    fast = fast.next
                return slow

        return None
```

## 一句话总结

这道题的关键是先用快慢指针找到环内相遇点，再利用“头节点到入口距离 = 相遇点到入口距离（模环长）”定位环入口。
