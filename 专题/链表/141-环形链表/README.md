# 141. 环形链表

## 所属专题

- 链表

## 题目描述

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，
则说明链表中存在环。

评测系统内部会用一个整数 `pos` 表示链表尾连接到链表中的位置（索引从 `0` 开始），
如果 `pos = -1`，表示链表中没有环。

需要特别注意的是：

- `pos` **不是函数参数**
- 它只是题目用来描述测试数据的一种方式

我们真正要做的事情只有一件：

- 判断这个链表里是否存在环

## 示例

### 示例 1

```text
输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，链表尾部连接到下标 1 的节点。
```

### 示例 2

```text
输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，链表尾部连接到下标 0 的节点。
```

### 示例 3

```text
输入：head = [1], pos = -1
输出：false
解释：链表中没有环。
```

## 题意理解

这道题并不是让我们去“找到环的入口”，
也不是让我们“计算环的长度”。

它只问：

- 这个链表里到底有没有环

所谓有环，意思是：

- 你顺着 `next` 一直往后走
- 本来正常链表最终应该走到 `None`
- 但如果某个节点的 `next` 又指回了前面某个节点
- 那么你就会一直绕圈，永远走不出去

所以本质上我们要判断的是：

**顺着指针往后走时，会不会重复回到之前经过的节点。**

## 最直接的想法：用哈希集合记录访问过的节点

最容易想到的方法是：

- 从头节点开始遍历链表
- 每经过一个节点，就把这个节点放进集合里
- 如果某次发现“当前节点已经在集合中出现过”，说明有环
- 如果最后走到了 `None`，说明没有环

例如：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

遍历时可能出现：

- 先访问 `3`
- 再访问 `2`
- 再访问 `0`
- 再访问 `-4`
- 下一步又回到 `2`

这时我们就知道：

- `2` 之前已经见过
- 所以链表里有环

这个思路很好理解，
时间复杂度也是 `O(n)`。

但是它要额外使用一个集合来存已经访问过的节点，
空间复杂度是 `O(n)`。

而这道题更经典的地方在于：

- **可以不用额外集合**
- **只用两个指针就判断有没有环**

## 优化思路：快慢指针（Floyd 判圈算法）

### 核心想法

定义两个指针：

- `slow`：每次走 `1` 步
- `fast`：每次走 `2` 步

接下来分两种情况讨论。

### 情况 1：如果链表没有环

如果没有环，
链表就是一条一直向后的单链表。

那么：

- `slow` 会一直往后走
- `fast` 也会一直往后走，但速度更快
- 最终 `fast` 一定会先走到 `None`

一旦：

- `fast is None`，或者
- `fast.next is None`

就说明链表已经走到尽头，
自然也就不存在环。

### 情况 2：如果链表有环

如果链表有环，
那么 `slow` 和 `fast` 进入环之后，
就相当于在一个跑道上追赶。

- `slow` 每次走 1 步
- `fast` 每次走 2 步

`fast` 比 `slow` 每轮多走一步，
因此它们之间的距离会不断变化。

在环里这个距离是“模环长”变化的，
所以 `fast` 迟早会追上 `slow`。

也就是说：

- 如果有环，快慢指针最终一定会相遇

这就是 Floyd 判圈算法的核心。

### 为什么一相遇就能说明有环

因为在一个正常无环链表里：

- 节点只会一路向后
- `fast` 不可能绕回来碰到 `slow`

只有在存在环的时候：

- `fast` 才有可能在环里“转一圈后追上” `slow`

所以只要两者相遇，
就可以直接返回 `True`。

## 用示例手推一遍

以示例 1 为例：

```text
head = [3,2,0,-4], pos = 1
```

实际链表结构是：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

我们令：

- `slow = head`
- `fast = head`

### 第 1 轮

- `slow` 走一步，到值为 `2` 的节点
- `fast` 走两步，到值为 `0` 的节点

此时：

- `slow` 在 `2`
- `fast` 在 `0`

还没有相遇。

### 第 2 轮

- `slow` 再走一步，到值为 `0` 的节点
- `fast` 再走两步：从 `0` 到 `-4`，再从 `-4` 回到 `2`

此时：

- `slow` 在 `0`
- `fast` 在 `2`

还没有相遇。

### 第 3 轮

- `slow` 再走一步，到值为 `-4` 的节点
- `fast` 再走两步：从 `2` 到 `0`，再从 `0` 到 `-4`

此时：

- `slow` 在 `-4`
- `fast` 也在 `-4`

两者相遇，说明链表中存在环。

所以返回：

```text
true
```

## 为什么这样写

### 1. 这是链表里非常经典的“快慢指针”模型

很多链表题都可以从“一个快、一个慢”这个角度去想。

这道题是这个模型最标准的应用之一。

### 2. 不需要修改链表结构

有些人会想到：

- 能不能把访问过的节点做标记

但在面试或题解里，
通常不应该去破坏原链表结构。

快慢指针完全不需要改节点内容或指针，
只靠遍历就能完成判断。

### 3. 空间复杂度更优

和哈希集合做法相比：

- 哈希集合：空间复杂度 `O(n)`
- 快慢指针：空间复杂度 `O(1)`

这也是为什么 Floyd 判圈算法更经典。

### 4. 比较的是“节点对象”，不是“节点值”

这点非常重要。

链表里可能有很多节点值相同，
比如都等于 `1`。

我们判断有没有环，
看的是：

- 是不是回到了**同一个节点**

而不是：

- 见到了相同的数值

所以代码里判断相遇时，
本质上比较的是两个指针是否指向同一个节点。

## 算法步骤

1. 如果 `head` 为空，或者只有一个节点，直接返回 `False`
2. 定义两个指针 `slow` 和 `fast`，都从 `head` 出发
3. 只要 `fast` 和 `fast.next` 不为空，就继续循环
4. 每轮让 `slow = slow.next`
5. 每轮让 `fast = fast.next.next`
6. 如果某一轮发现 `slow == fast`，返回 `True`
7. 如果循环结束都没有相遇，返回 `False`

## 复杂度分析

### 时间复杂度

`O(n)`

原因是：

- 无环时，每个指针最多把链表走一遍左右
- 有环时，进入环后也会在有限步内相遇

所以整体仍然是线性复杂度。

### 空间复杂度

`O(1)`

原因是：

- 只使用了两个指针变量
- 没有借助额外集合或数组

## Python 参考实现（详细注释）

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None


class Solution:
    def hasCycle(self, head) -> bool:
        # 如果链表为空，或者只有一个节点，
        # 那么不可能形成环。
        if not head or not head.next:
            return False

        # slow 每次走一步
        # fast 每次走两步
        slow = head
        fast = head

        # 只有当 fast 和 fast.next 都存在时，
        # fast 才能继续往前走两步。
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            # 如果两个指针指向了同一个节点，
            # 说明 fast 在环中追上了 slow。
            if slow == fast:
                return True

        # 如果 fast 走到了链表末尾，
        # 说明链表无环。
        return False
```

## 常见错误

### 1. 把“节点值相等”当成“节点相遇”

错误想法：

- 只要 `slow.val == fast.val` 就说明有环

这是错的。

因为不同节点完全可能存着相同的值。

正确判断应该是：

- `slow` 和 `fast` 是否指向同一个节点

### 2. 忘记先判断 `fast` 和 `fast.next`

如果直接写：

```python
fast = fast.next.next
```

但没有先确认：

- `fast` 不为空
- `fast.next` 不为空

就可能报空指针错误。

### 3. 一开始把 `fast` 设成 `head.next`，却没处理好边界

这种写法不是不能做，
但边界更容易绕晕。

对于初学阶段，
更推荐统一写成：

- `slow = head`
- `fast = head`

然后在循环内部同时移动。

### 4. 想当然地用修改节点的方式做标记

例如：

- 把访问过的节点值改掉
- 或者把 `next` 改成某个特殊值

这会破坏原链表结构，
通常不推荐。

## 适合自己默写的精简版本

```python
class Solution:
    def hasCycle(self, head) -> bool:
        slow = head
        fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow == fast:
                return True

        return False
```

## 一句话总结

这道题的关键是把“判断是否重复回到某个节点”转化成“快慢指针在环中是否会相遇”。
