# 160. 相交链表

## 所属专题

- 链表

## 题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表相交的起始节点。

如果两个链表不存在相交节点，返回 `null`。

## 示例

### 示例 1

```text
输入：intersectVal = 8, listA = [4,1,8,4,5], listB = [5,6,1,8,4,5], skipA = 2, skipB = 3
输出：Intersected at '8'
解释：
相交节点的值为 8。
在链表 A 中，从下标 2 开始进入公共部分。
在链表 B 中，从下标 3 开始进入公共部分。
```

### 示例 2

```text
输入：intersectVal = 0, listA = [2,6,4], listB = [1,5], skipA = 3, skipB = 2
输出：No intersection
解释：两个链表没有相交节点。
```

## 题意理解

这道题最容易误解的一点是：

- “相交” 不是说两个节点的值一样
- 而是说两个链表从某个节点开始，后面的节点是 **同一批节点**

也就是说，判断相交看的是：

- 节点是不是同一个对象

不是：

- 节点里的数值是否相等

比如下面这种情况：

```text
A: 4 -> 1 -> 8 -> 4 -> 5
B: 5 -> 6 -> 1 -> 8 -> 4 -> 5
```

如果题目说它们在值为 `8` 的地方相交，
真正的意思是：

- `A` 里的那个值为 `8` 的节点
- 和 `B` 里的那个值为 `8` 的节点

其实是 **同一个节点对象**。

所以这道题要求我们返回的是：

- 相交起点那个节点本身

如果不存在相交，返回 `None`。

## 最直接的想法：记录一个链表的所有节点

最容易想到的方法是：

1. 先遍历链表 `A`
2. 把它所有节点都放进一个集合
3. 再遍历链表 `B`
4. 第一次遇到“已经在集合里的节点”时，那个节点就是相交点

这个思路很好理解。

因为：

- 如果两个链表真的共用某一段节点
- 那么从相交点开始，`B` 里的节点一定会出现在 `A` 的节点集合中

这个方法的时间复杂度是：

- `O(m + n)`

已经不错了。

但它有一个问题：

- 需要额外的集合
- 空间复杂度是 `O(m)`

而这道题其实可以做到：

- 不用额外集合
- 只用常数空间

## 优化思路：双指针“走两条路”

这是这道题最经典的做法。

### 核心想法

我们用两个指针：

- `pA` 从 `headA` 出发
- `pB` 从 `headB` 出发

然后两个指针每次都往后走一步。

如果某个指针走到了链表末尾，
就把它切换到另一条链表的头部继续走。

代码形式就是：

```python
pA = pA.next if pA else headB
pB = pB.next if pB else headA
```

最后：

- 如果两个链表相交，两个指针会在相交点相遇
- 如果两个链表不相交，两个指针会同时变成 `None`

### 为什么这样居然会相遇

这是这道题最关键的地方。

假设：

- 链表 `A` 的长度是 `m`
- 链表 `B` 的长度是 `n`

并且它们在某个节点之后共享尾部。

如果一个指针只走自己的链表，
那么两个指针由于“起点不同”，
往往不能同步到达相交点。

但现在我们让它们都走两段路：

- `pA` 先走 `A`，再走 `B`
- `pB` 先走 `B`，再走 `A`

这样两个指针总共走的路径长度都是：

```text
m + n
```

于是：

- 长的那一段差值被抵消掉了
- 它们会在相交点对齐

这就是这个方法最巧妙的地方。

## 用长度差来理解会更直观

假设：

- `A` 比 `B` 前面多一段
- `B` 比 `A` 前面也可能有自己独有的一段
- 后面某一段是共享的

如果两个指针一开始直接一起走，
它们进入公共部分的时间不一样。

但是当：

- `pA` 走完 `A` 再去走 `B`
- `pB` 走完 `B` 再去走 `A`

那么本质上就是：

- `pA` 多走了 `B` 的独有部分
- `pB` 多走了 `A` 的独有部分

最后两边都补齐了“长度差”，
于是就会在公共部分的起点相遇。

## 如果不相交呢

如果两个链表根本不相交，
那么它们没有公共尾部。

此时两个指针各自走完：

- 自己的链表
- 对方的链表

最后都会走到 `None`。

因为：

- `None == None`

所以循环也会结束，最终返回 `None`。

这就是为什么这套写法既能处理“相交”，也能处理“不相交”。

## 用示例手推一遍

以示例 1 为例：

```text
A: 4 -> 1 -> 8 -> 4 -> 5
B: 5 -> 6 -> 1 -> 8 -> 4 -> 5
```

共享尾部是：

```text
8 -> 4 -> 5
```

### 初始状态

- `pA` 在 `A` 的头结点 `4`
- `pB` 在 `B` 的头结点 `5`

两个指针同时向后走。

由于两个链表前面的独有部分长度不同，
它们第一次走的时候不会立刻相遇。

### 当 `pA` 走到末尾

`pA` 先走完整条 `A`，
然后跳到 `headB` 重新开始。

### 当 `pB` 走到末尾

`pB` 先走完整条 `B`，
然后跳到 `headA` 重新开始。

这时两个指针都已经“补走”了对方独有的那一段。

于是当它们再次进入公共部分时，
就会在：

```text
8
```

这个节点相遇。

所以返回这个节点。

## 为什么这样写

这道题的核心，不是单纯记住代码，而是要真正理解这个双指针在“补长度差”。

### 1. 两个指针都走 `A + B` 这两段路

无论谁先走哪条链表，
最终总长度都是一样的：

```text
len(A) + len(B)
```

一旦总路程相同，
原来前面独有部分造成的错位就会被抵消。

### 2. 相交时，相遇点一定是相交起点

因为链表一旦相交，
后面所有节点都完全相同。

所以两个指针第一次相等的位置，
就是公共部分的起点。

### 3. 不相交时，终点 `None` 也能自然收敛

这是这套写法很优雅的地方。

我们不需要额外写：

- “如果不相交怎么办”

因为双指针自然会一起走到 `None`。

### 4. 这里比较的是节点，不是节点值

写代码时一定要记住：

- `pA == pB`

比较的是两个指针是否指向同一个节点对象。

不是在比较：

- `pA.val == pB.val`

## 算法步骤

1. 如果 `headA` 或 `headB` 为空，直接返回 `None`
2. 初始化两个指针 `pA = headA`、`pB = headB`
3. 当 `pA != pB` 时循环：
   - 如果 `pA` 不为空，就移动到 `pA.next`，否则跳到 `headB`
   - 如果 `pB` 不为空，就移动到 `pB.next`，否则跳到 `headA`
4. 循环结束时，`pA` 和 `pB` 要么相遇在相交节点，要么同时为 `None`
5. 返回 `pA`

## 复杂度分析

### 时间复杂度

`O(m + n)`

其中：

- `m` 是链表 `A` 的长度
- `n` 是链表 `B` 的长度

原因：

- 每个指针最多走两条链表各一遍

### 空间复杂度

`O(1)`

原因：

- 只使用了两个额外指针变量
- 没有使用集合、数组等额外结构

## Python 参考实现（详细注释）

```python
from typing import Optional


# LeetCode 平台会提供 ListNode 定义。
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None


class Solution:
    def getIntersectionNode(
        self,
        headA: Optional[ListNode],
        headB: Optional[ListNode]
    ) -> Optional[ListNode]:
        # 如果任意一个链表为空，就不可能相交。
        if not headA or not headB:
            return None

        # 两个指针分别从两条链表出发。
        pA, pB = headA, headB

        # 当两个指针不相等时，继续向前走。
        # 如果相交，它们会在相交点相遇；
        # 如果不相交，它们会同时变成 None。
        while pA != pB:
            # 走完 A 就去走 B。
            pA = pA.next if pA else headB

            # 走完 B 就去走 A。
            pB = pB.next if pB else headA

        # 此时 pA == pB。
        # 可能是相交节点，也可能是 None。
        return pA
```

## 这段代码最值得记住的地方

你在自己手写的时候，重点记住下面这条主线：

```python
pA, pB = headA, headB

while pA != pB:
    pA = pA.next if pA else headB
    pB = pB.next if pB else headA

return pA
```

本质上就是一句话：

**让两个指针分别走完 `A + B` 和 `B + A`，用总路程相等来抵消长度差。**

## 常见错误

### 1. 比较节点值，而不是比较节点本身

错误理解：

- 只要 `val` 一样就算相交

正确理解：

- 必须是同一个节点对象

### 2. 写成“一个走完就结束”

如果某个指针到尾部就直接结束，
就失去了“补长度差”的作用。

关键就在于：

- 走完一条链表后，要切到另一条链表继续走

### 3. 误以为会死循环

不会。

因为：

- 相交时会在交点相遇
- 不相交时会在 `None` 相遇

所以循环一定会结束。

### 4. 忘记处理空链表

如果 `headA` 或 `headB` 本身就是空，
可以直接返回 `None`。

### 5. 误以为返回的是节点值

题目要求返回的是：

- 相交的起始节点

不是单纯返回它的值。

如果你准备在自己的 `.ipy` 文件里默写，建议先记住下面这个精简版本：

```python
from typing import Optional


class Solution:
    def getIntersectionNode(
        self,
        headA: Optional[ListNode],
        headB: Optional[ListNode]
    ) -> Optional[ListNode]:
        if not headA or not headB:
            return None

        pA, pB = headA, headB
        while pA != pB:
            pA = pA.next if pA else headB
            pB = pB.next if pB else headA

        return pA
```

## 一句话总结

这道题的关键不是额外记节点，而是：

**让两个指针分别走完两条链表，利用“总路程相同”自动对齐长度差，从而在相交点相遇。**
